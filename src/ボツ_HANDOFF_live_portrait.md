# LIVE PORTRAIT — 実装引き継ぎドキュメント

Webカメラ連動のリアルタイム・パーティクル表現「LIVE PORTRAIT」の引き継ぎ資料。

- **対象ファイル**: `sss_art_live_portrait.html`（単体HTML・依存ライブラリはCDN1本のみ）
- **ステータス**: 動作するプロトタイプ v0.1。実カメラでの見え方の追い込みは未実施
- **このドキュメントの位置づけ**: チャット側で作ったプロトタイプを Claude Code へ引き継ぐためのもの。コードを全部読まなくても文脈と判断理由が掴めることを目的とする

---

## 1. 何を作るものか（30秒で）

カメラに映った人物のシルエットを、ブラウザ内のオンデバイス機械学習でリアルタイムに切り抜き、
その内側を約3万個の発光パーティクルに変換する。粒子は映像の実際の色をまとう。
人がフレームから外れると粒子は散って漂い、再び映ると姿に集まり直す。

ビジュアルは暗背景＋加算合成の発光トーン。インタラクティブな体験コンテンツ
（フォトブース、サイネージ、Web上の体験など）を想定。

## 2. 確定仕様（依頼者が選択済み。独断で変えない）

以下は依頼者の明示的な選択。Claude Code 側の判断で勝手に覆さないこと。
変更提案は可だが、必ず確認を取る。

| 論点 | 確定した選択 |
|---|---|
| 認識する範囲 | **人物全体（シルエット）**。顔のみではない |
| 粒子の色 | **映像の実際の色を使う**（特定パレットへの割当ではない） |
| 人がいない時 | **粒子が散って漂う**（特定の形に整列して待機、ではない） |

> 補足：色については「特定の配色に寄せる版」も将来欲しくなる可能性がチャット中に示唆された。
> 現時点の確定は「実色」。両対応にするなら CONFIG フラグで切替できる設計が望ましい（後述）。

## 3. 技術スタックと全体パイプライン

- **WebGL2**（粒子描画）＋ **MediaPipe Tasks Vision**（人物セグメンテーション）
- フレームワーク不使用。素のJS（ES Modules）
- 外部依存は CDN から1本：`@mediapipe/tasks-vision@0.10.14`
  - WASM とモデルファイルも CDN（`cdn.jsdelivr.net` と `storage.googleapis.com`）から取得
- モデル：`selfie_segmenter`（float16）。人物 confidence mask を出力

### 毎フレームの処理フロー

1. `segmentForVideo()` で人物マスク（確信度 0..1 の Float32 配列）を取得（最大30fpsに制限）
2. 映像をグリッド解像度（既定 220×140）に2Dキャンバスでダウンサンプルし、実色を取得
3. 各格子点について、対応するマスク値を参照 → 人物内なら映像上の位置、外なら漂い先をターゲットに
4. 全粒子をターゲットへスプリング＋減衰で追従（CPU計算）
5. 位置・色バッファをGPUへ転送し、加算合成のポイントスプライトで一括描画

### 座標・ミラーの扱い（重要・バグの温床）

- 表示は自撮りミラー（左右反転）。ダウンサンプル時に `ctx.scale(-1,1)` で反転して描画
- マスク参照 `maskAt(u,v)` は、ミラー済みグリッドに合わせてマスク側も `(1-u)` で反転参照している
- アスペクト比は cover 方式。`fitScaleX/Y` で clip 空間に補正
- **この3点（描画ミラー・マスク反転・アスペクト補正）が噛み合っていないと「粒子が人と逆に動く／ずれる」**。
  実機調整で最初に確認すべき箇所

## 4. 設定パラメータ（`CONFIG`）

ファイル冒頭の `CONFIG` オブジェクトに全調整値を集約済み。主要なもの：

- `grid.cols / rows` … サンプリング格子＝粒子数（220×140 ≒ 30,800）。上げると密だが重い
- `particle.sizePx / alpha` … 粒のサイズと不透明度（加算合成なので低めが基本）
- `particle.spring / damping` … ターゲット追従の硬さと減衰。硬いほどキレが出るが散開の余韻が減る
- `particle.scatterJitter` … 不在時の漂いの強さ
- `mask.threshold / feather` … 人物マスクのしきい値とそのやわらかさ。**シルエット輪郭の出方を決める最重要値**
- `display.exposure / saturation / brightness` … 発光トーンと色補正
- `segFps` … セグメンテーション更新の上限（描画は常時、セグメントは間引き可）
- `dprCap` … devicePixelRatio 上限（負荷対策）

## 5. 既知の制約・注意点

### 5-1. 動作要件
- **HTTPS または localhost が必須**（ブラウザの getUserMedia 制約）。
  `file://` 直開きではカメラ拒否されうる。ローカル確認は `python3 -m http.server` 等で localhost 経由を推奨
- 初回はモデル（数MB）のDLに数秒。オフライン不可（現状CDN前提）
- WebGL2 非対応環境では起動せず、静止SVGのフォールバックを表示

### 5-2. 未検証事項（Claude Code 側で最初にやること）
- **実際の人物での見え方は未確認**。チャット側の検証環境にカメラがなく、
  起動ゲート表示・WebGL初期化・モデル読込・描画ループ進入までしか確認できていない
- セグメンテーション精度、輪郭の安定性、複数人が映った時の挙動は実機で要確認
- パフォーマンス（特に grid を上げた時、モバイル実機）の実測が必要

### 5-3. 設計上の割り切り
- 粒子の物理計算は **CPU**（30,800点を毎フレームJSループ）。
  現状は実用範囲だが、粒子数を大幅に増やすなら GPGPU（transform feedback）へ移行が必要
- ダウンサンプルに2Dキャンバスの `getImageData` を使用（毎フレームのCPU↔GPU往復あり）。
  ボトルネックになるようなら WebGL 内でのサンプリングに置換を検討
- マスク解像度はモデル出力依存（selfie_segmenter は256前後）。細かいエッジは出ない

## 6. 次にやるべきこと（推奨タスク、優先度順）

### P0：実機での基本動作確認と座標調整
- localhost で実カメラを通し、ミラー・マスク反転・アスペクト補正の整合を確認
- `mask.threshold / feather` を実映像で追い込み、シルエット輪郭を自然に

### P1：依頼者が試した上で出るであろう調整
- 粒度（grid）の最適点を探る ＝ 「もっと細かく」要望への備え
- 散り方の演出強化（散開時の初速・方向に物語性を持たせる等）
- **色モードの切替フラグ追加**：実色 ⇄ 指定パレット（位置割当）。
  「特定の配色版も欲しくなるかも」という発言への布石。CONFIG で持つのが綺麗

### P2：本番投入に向けた堅牢化
- オフライン対応（モデル・WASMの自前ホスティング、CDN障害時の挙動）
- 複数人・誰もいない・逆光など実環境エッジケースの確認
- 低スペック端末向けの自動品質調整（grid/dpr/segFps の動的制御）
- 展示用途なら：自動アイドルデモ、操作説明UI、フルスクリーン制御、再接続処理

### P3：表現の発展（任意）
- 粒子の GPGPU 化（数十万粒子規模へ）
- 顔ランドマーク（Face Landmarker）併用で、顔の特徴点だけ密度を上げる等
- 導入アニメ（粒子が一旦集合してから人物へ流れる等）の追加

## 7. 引き継ぎ時の留意（Claude Code への申し送り）

- まず `localhost` 経由で開いて実カメラ動作を体感してから着手すること。コードだけ読んでも質感は掴めない
- セクション2の「確定仕様」は依頼者の選択。変更は提案ベースで、独断で変えない
- パラメータ調整は CONFIG で完結する設計。シェーダや構造に手を入れる前に CONFIG で追い込めないか試す
- 粒子描画ロジック（加算合成・きらめき・スプリング追従）は、静止画像を粒子化した先行プロトタイプ
  `sss_art_living_mark.html` がほぼ同型。色やトーンの基準として参照可能
