# LIVE PORTRAIT IN FLUX — 仕様書 / 引き継ぎドキュメント

Webカメラ映像から人物だけをリアルタイムに認識し、ドット絵風の四角い粒子で再構成する WebGL2 作品。静止画版「PORTRAIT IN FLUX（ボクセル）」のリアルタイム派生。

- 成果物: 単一HTML `live_portrait_in_flux.html`（外部依存は MediaPipe CDN のみ）
- 動作要件: WebGL2 + `EXT_color_buffer_float`、`getUserMedia`、**HTTPS もしくは localhost**（カメラとCDN ESModule のため `file://` は不可）
- 検証状況: ヘッドレス環境のためカメラ・MediaPipe をモックに差し替え、合成人物でシミュレーション/描画ロジックを確認済み。**実機のカメラ＋本物のセグメンテーションでの最終確認は未実施**。

---

## 1. コンセプトと確定仕様

| 項目             | 決定                                     | 備考                                                       |
| ---------------- | ---------------------------------------- | ---------------------------------------------------------- |
| 人物以外の描画   | しない                                   | 背景セルの粒子は表示の濃さ `life→0` で消灯                 |
| 動いたときの挙動 | **その場に静かに追従（こぼれ落ちナシ）** | 旧仕様の「重力で落下＝こぼれ落ち」は**廃止**。うるさいため |
| 奥行き           | 薄レリーフ（c案）                        | マスク強度を Z に薄く乗せ、透視投影                        |
| 色               | 映像から拾った色                         | ドット絵デフォルメのため量子化（後述）                     |
| ルック           | ドット絵風デフォルメ                     | 粗い格子＋色の量子化＋四角い粒子                           |
| 補助操作         | マウスで軽く押せる                       | 散らさない程度                                             |

> 注意: HUDコピーや過去のやり取りに「spill / こぼれる / 落下」表現が残っていたら、それは**旧仕様の名残**。現行は「その場で静かに追従」が正。

## 2. パイプライン（毎フレーム）

```
Webカメラ(video)
  └─ MediaPipe ImageSegmenter (selfie_segmenter, VIDEO mode)
        └─ confidenceMask（人物確率）
  └─ video を GRID 解像度に縮小して色取得（鏡像反転）
        └─ 色を量子化＋彩度ブースト（ドット絵化）
  └─ personTex (RGBA, GRID_W×GRID_H): RGB=量子化色 / A=平滑化マスク
        ↓
GPU GPGPU（粒子シミュレーション, MRT ping-pong）
  ・各粒子は固定の home セルを持つ
  ・home セルのマスクを参照し life を 1（人物）/0（背景）へ補間
  ・pos は home(薄レリーフZ) へバネ吸着
        ↓
描画（四角い点, 透視投影, アルファ = m × life）
```

ポイント: 静止画版は「ドット絵から居場所をサンプリング」していたが、本作は逆で**居場所＝固定格子。色と存在(life)が毎フレーム差し替わる**。

## 3. 主要パラメータ（コード上部・冒頭付近）

| 定数             | 現値                | 意味 / 調整指針                                                                                             |
| ---------------- | ------------------- | ----------------------------------------------------------------------------------------------------------- |
| `TEX`            | 256                 | 粒子テクスチャ辺長。粒子数 = TEX² = 65,536。性能↔密度                                                       |
| `GRID_W`         | 96                  | ドット格子の横セル数（縦は映像比から自動）。**小さいほどドット絵感が強い**。120でやや細かい、80でかなり粗い |
| `BG`             | #0C0D10             | 背景色                                                                                                      |
| 色量子化 `Q`     | 42                  | `updatePerson` 内。大きいほどカクッと少色。デフォルメ強度の主ツマミ                                         |
| 彩度 `SAT`       | 1.25                | 同上。色面をはっきりさせる                                                                                  |
| マスク平滑化係数 | 0.35                | `maskSmooth += (mv - maskSmooth)*0.35`。小さいほど輪郭が安定（残像増）、大きいほど追従速い（チラつき増）    |
| マスクしきい値   | 0.45                | これ未満は背景扱い                                                                                          |
| life 補間        | `pow(0.72, uStep)`  | 点灯/消灯のなめらかさ。小さくすると素早く切替                                                               |
| バネ強度         | `(target-pos)*24.0` | 吸着の硬さ                                                                                                  |
| 速度減衰         | `pow(0.74, uStep)`  | 動きの粘り                                                                                                  |
| 速度上限         | `0.05 * uStep`      | これを上げると機敏                                                                                          |
| `HALFY`          | 0.9                 | world 半高さ。表示スケール基準                                                                              |
| `FOCAL`          | 3.0                 | 透視の強さ。小さいほど奥行き誇張                                                                            |

## 4. 技術メモ（WebGL2）

- **GPGPU は MRT ping-pong**。状態を2テクスチャに分割:
  - `state`: `xyz=pos, w=mode`（mode は現状未使用。将来の状態拡張用に温存）
  - `vel`: `xyz=vel, w=life`（life=表示の濃さ 0..1）
  - `home`: `xy=セルのworld座標, z=seed`（不変・読み取り専用）
- シミュレーションは全画面三角形 + フラグメントシェーダで、`gl.drawBuffers([COLOR_ATTACHMENT0, COLOR_ATTACHMENT1])` に pos/vel を同時出力。
- 描画は `gl_VertexID` から状態テクスチャを `texelFetch`、`gl.POINTS` で四角い点（`gl_PointCoord` を矩形マスク）。
- **残像は使わない**（旧版のfadeパスは撤去）。毎フレーム `clear` してから点描画。これが「こぼれ落ちナシ」のクリーンな見た目の要。
- 点サイズはworld→pxへ透視込みで換算: `cellW * pxPerWorld * s * fit`。

### ハマりどころ（実際に踏んだ）

- **fadeパス（残像）と低アルファ点は両立しない**。半透明の背景塗りが薄い点を即上書きして「何も映らない」状態になる。残像が欲しい場合は点のアルファを上げるか、加算合成にする。今回は残像不要なので clear に統一。
- シェーダ内のJS埋め込み（`${HALFX}`等）は `.replace` の対象文字列が一致しないとサイレントに失敗する。**置換後に `includes("${")` で残留チェック**するのが安全。
- ping-pong のスワップは pos/vel **両方**必要。

## 5. プライバシー

- 映像は**端末内処理のみ**でどこにも送信しない。起動パネルに明記済み。
- MediaPipe の wasm/モデルは CDN から取得（`cdn.jsdelivr.net`, `storage.googleapis.com`）。オフライン要件があるならローカルホストへ。

## 6. 既知の課題 / TODO（ClaudeCode 向け）

1. **実機未検証**: 本物のカメラ＋MediaPipe での結像・遅延・マスク品質を要確認。特に髪・眼鏡の縁のマスク精度。
2. **モバイル**: `delegate:"GPU"` が効かない端末向けに `"CPU"` フォールバックと粒子数の自動減（TEX=192等）を検討。
3. **顔/体の細分化**: 現在は人物一括マスク。`PoseLandmarker` を足せば「手だけ」「顔だけ」の領域別演出が可能（例: 手を振った領域だけ強く反応）。
4. **インタラクション拡張**: 「カメラに近づくと密度↑」「動きの速い領域だけ一時的にほどける」など、体の動きを入力にする方向。オプティカルフローやマスク差分で実装可。
5. **奥行きの本格化**: 現状はマスク強度による擬似Z。`DepthEstimation` 系を足せば本物の凹凸。負荷とのトレードオフ。
6. **テスト経路の常設**: `?mock=1` で合成人物に切り替わるフラグを正式実装すると、CI やカメラ無し環境で回帰確認しやすい（今回は手動でモック注入した）。
