# 依頼: WebGL2 リアルタイム映像作品「切り紙の世界」の新規制作

## 1. 作りたいもの

カメラに映った世界全体(人も物も背景も)が、多層ペーパーカットになる。画面全体を
輝度の分位点で切り分けた4〜8枚のフラットな紙レイヤーが奥から手前へ積み重なり、
各層は大きく滑らかなハサミ曲線の輪郭と、切り口の厚み(細いハイライト)・下層への
柔らかい落ち影を持つ。レイヤードペーパーアートの風景箱(シャドーボックス)のように、
映る世界すべてが同じ紙のセットから切り出される。

公開作 `fable5_kirie-portrait.html` の発展形である: あちらは MediaPipe で人物を
部位ごとに切り分けて台紙に貼ったが、**本作は検知を一切使わず**、フレーム全体を
輝度レイヤーで切る。『台紙に貼った人物』ではなく『画面の縁まで紙が満ちた風景箱』。

- ファイル名: `fable5_kirie-sekai.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)

この様式の本質は「**紙の積層(切り口の厚みと落ち影を持つフラットな面の重なり)**」で
ある。これを後処理(ぼかし・色調整・単純なポスタライズ)で近似してはならない
(制作規約 失敗モード#1)。

## 3. 入力映像から生き残らせる信号

- 生き残る: シーンの大きな明暗構造(輝度の帯)→紙レイヤーの切り分け線 / 人物・物の輪郭
  (平滑化したハサミ曲線として)と顔の判読性 / 動き(境界が遅れなく追従、静止時は完全静止) /
  シーンの大まかな色調(パレット選択に僅かに反映)
- 様式側で置き換わる: 実写の質感・連続階調→フラットな紙面 / 実際の色→紙セットへの
  oklab スナップ / 光学的な奥行き→層の重なりと落ち影 / 細部→最小紙片サイズ以上の形のみ
- 被写体(特に人物)が判読できることは受入基準である。

## 4. 技術方針(この指定に従うこと)

実装原理は次の技法語彙で固定する: kuwahara / quantile / hysteresis / ema / sdf /
oklab / cell-hash / ping-pong / edge darkening / fbm

**前身 `fable5_kirie-portrait.html` を実装前に読み、紙積層エンジン(P3 kuwahara→
量子化場、P5 stats→CPU quantile、compFS の切り口/落ち影機構)の実装をそのまま
出発点として再利用してよい**(同一リポジトリの自作品)。MediaPipe・部位クラス・
台紙・髪の LIC/etf・人物シルエットの機構は**すべて捨てる**。

パス構成の出発点(変更する場合は Phase 2 で却下理由と共に提案):

```
入力: カメラ映像 or 合成シーン(?fakesource=1。GLSL で動く人物+室内/風景を合成)
[P0 scene ] cover-fit + mirror                              sceneT  RGBA8 長辺≤1024
[P1 struct] kuwahara(sceneT)→平滑輝度 → 時間 ema           structA/B RGBA8(≤768) ping-pong
[P2 stats ] 輝度ヒストグラム縮約                             statsT RGBA8 128×128
            → CPU readback ~200ms 毎 → 加重ヒストグラム → quantile →
            hysteresis+ema → uniform 配列(しきい値)
[P3 comp  ] 量子化(4〜8層)+境界の擬似 sdf 帯で切り口ハイライト+単一光源方向の
            落ち影+oklab 紙パレットスナップ+fbm 紙グレイン → canvas(DPR≤2)
```

- 外部依存: **なし**(MediaPipe 等の ML 不使用。カメラのみ)。`?fakesource=1` は
  GLSL 合成シーン(**動く人物+背景。動く要素必須** — S3 の --motion 検査対象)。
- uDebug モード割当: 0=最終 / 1=平滑輝度(量子化場) / 2=量子化レベルのみ(切り口・影なし) /
  3=境界帯の可視化(sdf 帯・影方向) / 4=標本(紙トーン階段見本+切り口/落ち影の段階見本)
- レイヤー数・しきい値は全画面共通の quantile(前身のような部位別クラスはない)。
  ただし不変量6(顔の判読性)のため、暗部保護の下限と局所細分の機構を入れること。
- 「明るい層が手前」か「暗い層が手前」かはプリセットで切り替え(§6)。

## 7. 制約条件(dsflon/webgl2 リポジトリ規約 — 受入基準を兼ねる)

### 成果物の形
- 単一の自己完結 HTML。外部ライブラリ・ビルド工程・外部アセット禁止
  (例外: ML モデルのみ CDN 可。本作の許可: **なし**)。
- WebGL2 / GLSL ES 3.00。WebGL1 フォールバック不要。
- ファイル冒頭に HTML コメントで: 作品概要 / 実行方法 / 様式解析の要約 /
  パイプライン図 / 全スライダーの説明 を書くこと。
- README.md の作品リストに GitHub Pages の URL を追記すること(S5 でオーケストレータが行う)。

### カメラ
- getUserMedia は facingMode 指定(user/environment)。モバイルでは切替ボタンを表示。
- <video> は playsinline muted autoplay。ミラーはシェーダの UV 反転で行う。
- 非セキュアコンテキスト / 権限拒否 / カメラ無し の3経路それぞれに、
  専用メッセージと再試行ボタンを持つオーバーレイを表示すること。
- カメラとキャンバスのアスペクト比差は cover-fit(切り取り)で吸収すること。

### UI(既存作品の panel 構造を踏襲)
- 実装前に `fable5_papercraft-cam.html` を読み、カメラ取得・UIパネル・エラー表示・
  PNG保存の規約を踏襲すること(**参考にするのは規約定型のみ。作品表現は参考にしない**。
  作品表現の出発点は `fable5_kirie-portrait.html` の紙エンジン)。
- 全パラメタは単一の state オブジェクトに集約し、スライダー定義は
  [key, ラベル, ヒント, min, max, step] の配列から生成すること。
- DEFAULTS と「RESET LOOK」。「HIDE UI」「SAVE PNG」(preserveDrawingBuffer: true)。
- prefers-reduced-motion 時はアニメーション停止トグルを初期 ON。

### 検証フック(機械検証が依存する。必須)
- window.__artReady: 最初の本描画フレーム完了時に true を立てること。
- ?freeze=1: 時間駆動アニメーションを停止し決定的な静止フレームを出すこと
  (合成シーンも静止)。
- ?prewarm=<秒>: 初回描画の前に、指定秒ぶんのシミュレーションを固定 dt で
  決定的に早送りしてから開始すること(freeze の preroll と同じ機構を非 freeze にも
  公開する。検証環境はソフトウェアレンダリングで実時間 warm が数分かかるため、
  「しきい値が収束した状態」のスクショをこのフックで数秒で撮る)。
- ?fakesource=1: カメラ/権限を一切使わず、GLSL 合成シーン(動く人物+背景)で
  全パイプラインを駆動できること。
- ?fakescale=: 人物マスク駆動ではないため**該当なし**(実装不要)。

### 品質基準
- 静止したカメラの前で画面がチラつかないこと(乱数シードはセル座標由来)。
- デスクトップ 60fps / モバイル 30fps 以上(DPR 上限 2、重いバッファは解像度上限)。
- リサイズ・カメラ切替・タブ復帰で壊れないこと。

## 8. 技術注意リスト(遵守すること)

1. GLSL ES 3.0 の予約語を変数名に使わない: coherent, sample, filter, precise,
   restrict, readonly, writeonly, subroutine, input, output, common, partition, active
2. 同一テクスチャを read しながら write しない。feedback/拡散/EMA は必ず ping-pong。
3. float テクスチャは EXT_color_buffer_float を確認し、未対応時の代替を用意
   (RGBA8 のみで成立する構成を推奨)。
4. MRT のブレンドは全アタッチメント共通。クリアは clearBufferfv を毎アタッチメント。
5. 方向場は二重角 (cos2θ, sin2θ)。角度の直接 lerp をしない。
6. normalize(ゼロベクトル) は NaN。pow(x,y) は x<0 で未定義。
7. ループは const int MAX + break。
8. 頂点シェーダのテクスチャ参照は textureLod。
9. 乱数は pcg系 hash12。シードに時間を混ぜない。
10. UNPACK_FLIP_Y_WEBGL は DOM ソースのみ。TypedArray アップロードはシェーダ側で向きを合わせる。
11. gl_PointSize は使わない。canvas は preserveDrawingBuffer: true。
12. UV・位置計算は highp。
13. ブラーは縦横分離。readPixels は stats の低頻度(~200ms毎)のみ(毎フレーム禁止)。
14. 前身 kirie-portrait からの流用時、部位クラス(髪/顔/体/服)前提の分岐・uniform を
    残さないこと(死んだコードの持ち込み禁止)。
15. 量子化しきい値の hysteresis(不感帯)を必ず入れる(しきい値付近の画素が
    フレームごとに層を行き来する沸き立ちの防止 — 不変量5)。
16. プリセットの「明=手前/暗=手前」の反転は、落ち影のオフセット方向・切り口の
    付く側も一貫して反転すること(不変量3の光源一貫性)。

## 9. 検証環境

- フェイクカメラ+スクリーンショットは `loop/runner/`(testscene.mjs / verify_runtime.mjs)
  を使う。ローカルサーバは python3 -m http.server 8888。
- スクリーンショットは (a) 最終合成 — `?fakesource=1&prewarm=12`(実時間 warm 禁止)
  (b) uDebug の主要モード (c) ?fakesource=1 の標本 の3枚以上。
  pageerror が出ていないことを毎回確認する。
- 時間軸の不変量(#5)があるため `--motion` が必ず通ること(合成シーンの動く要素で担保)。
- 蓄積系ではない(ema はあるが絵は育たない)ため --longrun は必須でないが、
  ema の長時間ドリフトがないことを prewarm 3/8/15 の比較で確認すること。
- **実機乖離の予防**(`loop/CRAFT.md` §C を実装前に読むこと):
  外部検知なしのため fakeseg は「該当なし」と報告してよい。モバイル性能レシピ
  (CRAFT §C3 のうち DPR 上限・バッファ解像度上限)は踏襲すること。
- 検証できない項目(実機カメラ・実機GPU 依存)は「未検証」と明記し、
  確認すべき点を列挙すること。
