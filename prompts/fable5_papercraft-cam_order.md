# 依頼: WebGL2 リアルタイム映像作品「ペーパークラフト・ジオラマカメラ」の新規制作

## 1. 作りたいもの

Webカメラの映像を、リアルタイムに **多層ペーパーカット(切り絵)のジオラマ** として描画する作品。

単眼深度推定モデルで映像の奥行きを推定し、空間を **4〜6枚の「紙のレイヤー」に離散化**する。
各レイヤーは「ハサミで滑らかに切り抜いた色紙」として様式化され、レイヤー間には紙の厚みを
感じさせる柔らかいドロップシャドウが落ち、ポインタ/デバイスの傾きに応じた微小なパララックスで
立体的な紙のジオラマとして知覚される。

- ファイル名: `fable5_papercraft-cam.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)
- タイトル表記: `FABLE5 · Papercraft Cam — WebGL2 depth-layered paper diorama`

このゴールの本質は「**写真が紙に置き換わっている**」ことである。
ポスタライズした写真、等高線の乗った写真、輪郭線フィルタをかけた写真になってはならない
(AI_DIRECTION_GUIDE 失敗モード#1「一次特徴の後処理近似」。本作で最も警戒すべき失敗)。

## 2. 様式の参照 — 視覚的不変量表(**ゲート1通過済み**)

参考画像2枚の言語化:

- **参考1「緑のジオラマ」**: 深いティール〜緑の限定パレット。手前のレイヤーほど暗く濃く、
  奥のレイヤーほど明るく淡いミスト状のティール(空気遠近をパレットで表現)。各レイヤーは
  完全にフラットな紙で、輪郭は細部を省いた滑らかな有機曲線。最前面のレイヤーが画面の縁を
  額縁(アーチ)状に囲み、奥へ向かってトンネル状の奥行きが生じる。レイヤーの縁には柔らかい
  ドロップシャドウが落ち、紙の厚みと浮遊感がある。コーラル・ピンク・黄の差し色は
  少数の要素(鳥・花・キノコ)だけに使われる。
- **参考2「白いエコポスター」**: 白い紙の破れ目の奥に、緑の森と白いビル群が覗く構図。
  ほぼ白+緑2〜3段+濃緑背景の単色系。同じくレイヤーごとのドロップシャドウが厚みを作る。

この様式を成立させている不変量は下表のとおり。**Phase 1 ではこの表を独自の再解析で
置き換えないこと。** 復唱と、実装上の懸念点・質問の列挙のみ行う(§5 Phase 1)。

| # | 視覚的不変量(実装可能な構造の言葉で) | 担当軸 | 実装原理の指定 | 外した場合の影響 |
|---|---|---|---|---|
| 1 | **空間が4〜6枚の平面レイヤーに完全に離散化されている。** 中間深度は存在せず、全ての要素がいずれか1枚の紙に属する | 場/知覚 | 単眼深度推定 → 分位点(quantile)しきい値で量子化 → ヒステリシスで安定化 | ただの写真。作品が成立しない |
| 2 | **輪郭が「ハサミで切った紙」である。** 滑らかで丸く、ピクセルレベルの細部が省かれ、しきい値近傍に1〜3pxの明るい「切り口」ハイライトが走る | マーク | マスクの分離ガウスぼかし → smoothstep 再閾値化(形態学的平滑化)。ぼかし値を擬似SDFとして境界帯を切り口として着色 | ギザギザの「写真の切り抜きコラージュ」になる |
| 3 | **レイヤー内部はフラットな紙の色。** 写真の色ではなく、深度ゾーン別の限定パレットに写像される。奥ほど明るく淡く、手前ほど濃い。彩度の高い被写体だけが差し色にスナップする | 色 | anisotropic Kuwahara で平坦化 → 深度ゾーン別スプリットトーン+灰色度重み。高彩度画素は最近傍の差し色へスナップ | ポスタライズ写真。紙に見えない |
| 4 | **レイヤー間の柔らかいドロップシャドウが「紙の厚みと浮き」を作る。** 影は黒ではなく、落ちる先のレイヤー色を暗く濁した色。下方向+視差方向へ僅かにオフセット | 物質 | 平滑化済みマスクの分離ブラー → オフセット → 奥のレイヤーに乗算合成 | のっぺりした平面ポスタライズ。立体感が消える |
| 5 | **微小パララックス。** ポインタ/デバイスの傾きで各レイヤーが深度に応じた別速度で動き、ジオラマとして知覚される | 時間/知覚 | レイヤーごとに別Zに置いたクワッドを遠近カメラで合成。カメラを±数%オフセット | 静止画では成立しても「立体の紙」と知覚されない |
| 6 | **紙の物質感。** 微細な繊維グレインと、レイヤーごとの僅かな色ムラ | 物質 | cell-hash ノイズの静的グレイン(シードはセル座標+レイヤーindexのみ。時間禁止) | プラスチック的なフラットシェーディングに見える |

優先度(外すとその様式に見えなくなる順): **1 > 2 > 4 > 3 > 5 > 6**

最重要の 1・2 は、ぼかし・ポスタライズ・輪郭線フィルタ等の後処理で近似せず、
「深度量子化 → マスク形態学的平滑化 → SDF境界帯」という**描画アーキテクチャのレベルで**
実装すること。

## 3. 入力映像から生き残らせる信号

- **生き残る**: 形態(シルエット)、奥行きの順序、大まかな明暗、被写体の動き
- **様式側で置き換わる**: 色(パレットへ写像)、テクスチャ(紙の質感へ)、細部(切り絵の単純化された輪郭へ)
- 顔は「シルエット+レイヤー」で表現される。写実的な顔の描写は不要だが、
  カメラの前の人物が人物として判読できること(受入基準)。
- カメラの前で手を前後に動かすと、手がレイヤーからレイヤーへ「渡って」移動すること。
  これが本作のインタラクションの核であり、受入試験の項目である。

## 4. 技術方針(以下の指定に従うこと)

### 4.1 深度推定

- `@huggingface/transformers`(transformers.js v3系)を CDN から ESM import し、
  `pipeline('depth-estimation', 'onnx-community/depth-anything-v2-small')` を使う。
  これは制約条件ブロックの「MLモデルのみCDN可」例外に該当する唯一の外部依存である。
- 実行デバイスは `webgpu` を第一候補とし、初期化失敗時は `wasm` へ自動フォールバックする。
  dtype は webgpu: `fp16`、wasm: `q8`。使用中のバックエンドと推論Hzを readout に表示する。
- 推論はレンダリングループから**完全に分離した非同期ループ**で回す(latest-wins:
  前の推論が完了してから最新フレームを1枚だけ送る。キューを溜めない。rAFコールバック内で
  await しない)。描画は深度の更新頻度と無関係に 60fps を維持する。
- 推論への入力は **cover-fit で切り抜いた後の映像**を縮小したもの(長辺 350px 程度から調整)。
  切り抜き前のフル映像を推論してはならない(深度と色のUVがずれる)。
  ミラー(フロントカメラ時)はシェーダ側で色と深度に**同一のUV反転**を適用する。
- **深度の正規化**: フレーム単位の min/max 正規化はレイヤーのパカつきを起こす。
  min/max を EMA(時定数1〜2秒)で追従させる temporal normalization を使うこと。
- 深度テクスチャは GPU 側で ping-pong の EMA(αはスライダー)により時間平滑化する。

### 4.2 レイヤー分割

- レイヤー数 N はスライダー(3〜8、初期値 5)。
- しきい値は固定等分ではなく、**深度ヒストグラムの分位点(quantile / equal-area)**から
  求める(推論結果はCPU側にあるので、アップロード前にCPUでヒストグラムを取ればよい。
  GPUからの readPixels を毎フレーム行わないこと)。しきい値自体も EMA で平滑化する。
- レイヤー割り当てには**ヒステリシス**を入れる(しきい値±εの帯では前フレームの
  割り当てを維持)。静止シーンでレイヤー境界がパカパカしないことが品質基準。

### 4.3 紙の様式化(レイヤーごと)

- **マスク平滑化**: レイヤーマスクを分離ガウスぼかし→ smoothstep 再閾値化して
  「切り口の丸み」を作る。半径は `cutSmooth` スライダー。
- **切り口**: 再閾値化前のぼかし値を擬似SDFとみなし、しきい値近傍の帯(1〜3px)を
  「切り口ハイライト」(その紙色を明るくした、ほぼ白の色)として描く。
- **色**: 下地は anisotropic Kuwahara(半解像度)で平坦化した映像色。これを
  深度ゾーン別スプリットトーン+灰色度重みでパレットへ写像する。奥のレイヤーほど
  明るく淡いミスト色、手前ほど濃い(空気遠近)。彩度の高い被写体はパレットの差し色に
  スナップさせる(参考1の「緑の世界に少数のコーラル」を再現する仕組み)。
  `paletteMix` スライダーで写真色↔紙色を連続的に行き来できること。
- **影**: レイヤー k の平滑化済みマスクを分離ブラー→下方向+視差方向へオフセットし、
  レイヤー k+1 以遠へ乗算合成。影色は黒ではなく、落ちる先のパレット色を暗く濁した色。
  強度・オフセット・ぼけは `thickness` スライダーに連動。
- **パララックス**: 各レイヤーを別Zのクワッドとして遠近カメラで合成。ポインタ
  (デスクトップ)/ deviceorientation(モバイル)でカメラを±数%オフセットする。
  視差でレイヤー間の隙間が露呈しないよう、各レイヤーのテクスチャは
  **マスクを数px 膨張(dilate)した範囲まで**塗っておくこと。
- **紙の質感**: cell-hash 由来の静的な繊維グレイン+レイヤーごとの僅かな色ムラ。
  シードはセル座標とレイヤーindexのみから導出し、時間・フレーム番号を混ぜない。

### 4.4 デバッグ表示(必須)

`uDebug` uniform で次の中間出力を単独表示できること(UIの DEBUG セレクタから切替):

```
0=最終合成  1=生深度  2=平滑化深度  3=量子化レイヤー(レイヤーごとに色分け)
4=マスク+切り口  5=影バッファ  6=Kuwahara下地
```

### 4.5 合成深度スイッチ(必須)

URLパラメータ `?fakedepth=1` で、推論の代わりに**合成深度**(斜めランプ+球+矩形の
組み合わせ。§10 の断面標本と同一のもの)を深度源にできること。
オフライン検証・標本表示・デバッグの3用途で共用する。

- **Phase 2: 設計** — 次を提出する:
  1. 候補アーキテクチャ 2〜3案の比較(様式再現度/性能/実装リスクのトレードオフ表、

  2. パス構成図: カメラ入力から画面出力までの全パスについて、入出力テクスチャ・

  3. フィルレート概算(レイヤー数×パス数×画素数)と、モバイルで成立する根拠。
  4. リスク: 最も失敗しそうな箇所と代替案(例: wasm 経路の推論が遅すぎる場合)。
- **Phase 3: 実装** — 添付の制約条件ブロックと技術注意リストに従う。順序:

  2. 次に**標本**を実装・提示し、承認を得る(§10。`?fakedepth=1` を流用してよい):
     - **断面標本**: 合成深度を入力に、レイヤー分割・切り口・影が1枚で見えるデバッグ画
     - **色見本**: 深度ゾーンのグラデーション帯 × 2プリセットのパレット写像帯
  3. 承認後、本パイプラインのパスを1本ずつ追加する。**承認済み標本のパラメタを

  4. 1000行を超えるファイルは論理単位で分割して書き込むこと(一度に全文を出力しない)。
- **Phase 4: 検証** — §9 の検証手順でスクリーンショットを取得し、§11 の自己批評

(一括実行条項 — 発注者が明示した場合のみ有効: Phase 1〜4 を1ターンで通貫してよい。

## 6. UI 仕様

### 6.1 スライダー(「写真らしさ ↔ 様式の強さ」の軸で命名)

全パラメタは単一の state オブジェクトに集約し、`[key, ラベル, ヒント, min, max, step]`
の配列から生成すること(参照実装の規約)。

| key | ラベル | 範囲(初期値) | 作用 |
|---|---|---|---|
| layerCount | LAYERS | 3〜8 (5) | 紙のレイヤー枚数 |
| depthRange | DEPTH SPREAD | 0〜1 (0.6) | 分位点しきい値の広がり(手前偏重↔全域均等) |
| depthSmooth | DEPTH CALM | 0〜1 (0.65) | 深度EMAの強さ(層の落ち着き↔追従の速さ) |
| cutSmooth | CUT ROUNDNESS | 0〜1 (0.5) | 切り口の丸み(マスクぼかし半径) |
| edgeLight | CUT HIGHLIGHT | 0〜1 (0.55) | 切り口ハイライトの明るさ・太さ |
| flatten | PAPER FLATTEN | 0〜1 (0.7) | Kuwahara平坦化の強度(写真↔紙) |
| paletteMix | PALETTE | 0〜1 (0.75) | 映像色↔プリセットパレットの写像率 |
| thickness | PAPER LIFT | 0〜1 (0.6) | 影のオフセット・ぼけ・濃さ(紙の浮き) |
| parallax | PARALLAX | 0〜1 (0.5) | 視差カメラの振れ幅 |
| grain | PAPER GRAIN | 0〜1 (0.4) | 繊維グレインの強さ |

### 6.2 パレットプリセット(色見本で承認を得ること)

プリセットは「深度ゾーン基調色(奥→手前)+差し色+切り口色+影色」のセットとして定義する。
以下の2つを実装する。追加プリセットは実装せず提案に留めること(スコープ膨張の禁止)。

- **Deep Forest**(参考画像1・初期プリセット)
  - ゾーン基調色(奥→手前): `#a8ded2 → #5db3a0 → #2e7f6e → #175a4f → #0e3b38 → #082624`
  - 差し色: coral `#f08a4b` / pink `#ec5f8a` / yellow `#f2b134` / leaf `#9dc45f`
  - 切り口: `#f4efe2` 系(紙色を明るく) / 影: `#05201f` 方向へ乗算
  - 背景(最奥の紙): `#0b2b30`
- **Eco White**(参考画像2)
  - ゾーン基調色(奥→手前): `#10301a → #1f4d26 → #3e7d3f → #6fae5c → #dfe3e0 → #f5f4ee`
  - 差し色: なし(単色系。高彩度スナップは緑階調へ吸収)
  - 切り口: `#ffffff` / 影: `#59695c` 方向へ乗算

※レイヤー数が6未満/超のときはゾーン基調色を補間して割り当てる。

### 6.3 readout・ボタン

- readout: FPS / 描画解像度 / 深度バックエンド(webgpu|wasm) / 深度推論Hz / レイヤー数
- ボタン: SAVE PNG / RESET LOOK / HIDE UI / DEBUG セレクタ / (モバイル)FRONT⇄REAR CAM
- prefers-reduced-motion 時: パララックスの自動微揺動を停止するトグルを初期ONにする。

## 7. ローディングUX(本作固有・必須)

深度モデル(数十MB)の初回ダウンロードが走るため、次の段階的な立ち上がりを実装すること:

1. 起動 → カメラ許可 → **即座に「下地モード」で表示開始**
   (Kuwahara平坦化+グレイン+単一パレットの1層のみ。深度なしでも既に紙っぽい画)。
2. パネルまたは画面隅に `FOLDING PAPER … n%` の進捗表示
   (transformers.js の progress_callback を使う)。
3. 最初の深度が届いたら、1〜2秒かけてレイヤーがふわっと立ち上がる遷移
   (深度の寄与を 0→1 にイージング)。
4. モデル取得失敗(オフライン等)は専用のエラーオーバーレイ+RETRYボタン。
   下地モードのまま使い続ける選択肢も残す(`CONTINUE FLAT` ボタン)。

## 8. 制約条件(dsflon/webgl2 リポジトリ規約 — 受入基準を兼ねる)

### 成果物の形
- 単一の自己完結 HTML。外部ライブラリ・ビルド工程・外部アセット禁止
  (**本作の例外: `@huggingface/transformers` の CDN import と、それが取得する
  `onnx-community/depth-anything-v2-small` のモデル重みのみ可**)。
- WebGL2 / GLSL ES 3.00。WebGL1 フォールバック不要。
- ファイル冒頭に HTML コメントで: 作品概要 / 実行方法 / 様式解析の要約(§2の不変量) /
  パイプライン図 / 全スライダーの説明 を書くこと。
- README.md の作品リストに GitHub Pages の URL を追記すること。

### カメラ
- getUserMedia は facingMode 指定(user/environment)。モバイルでは切替ボタンを表示。
- `<video>` は playsinline muted autoplay。ミラーはシェーダの UV 反転で行い、
  フロントカメラ時のみ ON をデフォルトとする(色と深度に同一の反転を適用)。
- 非セキュアコンテキスト / 権限拒否 / カメラ無し の3経路それぞれに、
  専用メッセージと再試行ボタンを持つオーバーレイを表示すること。
- カメラとキャンバスのアスペクト比差は cover-fit(切り取り)で吸収すること。

### UI(既存作品の panel 構造を踏襲)
- 実装前に `fable5_van-gogh.html` を読み、カメラ取得・UIパネル・エラー表示・
  PNG保存の**規約を踏襲**すること。
- 全パラメタは単一の state オブジェクトに集約し、スライダー定義は
  `[key, ラベル, ヒント, min, max, step]` の配列から生成すること。
- DEFAULTS オブジェクトと「RESET LOOK」ボタン。プリセットは §6.2 の命名。
- 「HIDE UI」トグル(モバイルでは下部シート化)、「SAVE PNG」
  (preserveDrawingBuffer: true で実装)、§6.3 の readout。
- prefers-reduced-motion 時はアニメーション停止トグルを初期 ON。

### 品質基準
- 静止したカメラの前で画面がチラつかないこと(グレインのシードはセル座標由来、
  レイヤー割り当てはヒステリシスで安定)。
- デスクトップ 60fps / モバイル 30fps 以上(DPR 上限 2、重いバッファは解像度上限)。
  深度推論の目標: webgpu で 8Hz 以上、wasm では 1Hz 程度でも EMA 補間で体験が成立すること。
- リサイズ・カメラ切替・タブ復帰で壊れないこと(タブ非表示中は推論ループを停止し、
  visibilitychange で再開)。

## 13. 技術注意リスト(遵守すること)

```text
## WebGL2 / GLSL 技術注意

1. GLSL ES 3.0 の予約語を変数名に使わない: coherent, sample, filter, precise,
   restrict, readonly, writeonly, subroutine, input, output, common, partition, active
2. 同一テクスチャを read しながら write しない。feedback/拡散/EMA は必ず ping-pong。
3. float テクスチャへ描画する場合は EXT_color_buffer_float の取得を確認し、
   未対応時のフォールバック(RGBA8 固定小数パック)か明示エラーを用意する。
4. MRT のブレンドは全アタッチメント共通。クリアは clearBufferfv をアタッチメント毎に。
5. 方向場をテクスチャに格納するときは二重角 (cos2θ, sin2θ)。角度の直接 lerp をしない。
6. normalize(ゼロベクトル) は NaN。微小値を足してから正規化する。
   pow(x, y) は x<0 で未定義。
7. ループは const int MAX で回し uniform 上限は break で制御(ドライバ互換)。
   レイヤー数のループ(最大8)もこの方式で。
8. 頂点シェーダでのテクスチャ参照は textureLod で LOD を明示(ミップ付きの場合)。
9. 乱数は fract(sin(dot(...))) 系を避け、pcg系 hash12 を使う。
   グレイン・色ムラのシードに時間を混ぜない。
10. UNPACK_FLIP_Y_WEBGL は DOM ソースのアップロードにのみ効く。設定は1回。
11. gl_PointSize は使用時必ず書く。canvas は preserveDrawingBuffer: true(PNG保存)。
12. mediump は実機で fp16。UV・位置計算は highp を明示。
13. ブラーは縦横分離。generateMipmap は必要な1枚だけ。readPixels を毎フレーム呼ばない。

## 本作固有(深度推定まわり)

14. 推論を rAF コールバック内で await しない。非同期ループで latest-wins。
    推論中に届いたフレームは捨てる(キューを溜めない)。
15. 深度は cover-fit 切り抜き後の映像に対して推論し、色と同一のUV系に載せる。
    モデルの前処理(リサイズ/パディング)で縦横比が変わる場合は出力を切り抜いて戻す。
16. 深度ヒストグラム・分位点の計算は推論結果のCPU側データで行う
    (GPUからの readPixels を毎フレーム行わない、と両立させる)。
17. deviceorientation は iOS で requestPermission が必要。ボタンで要求し、
    非対応/拒否時はポインタ追従または低周波の自動微揺動へフォールバック。
18. タブ非表示(visibilitychange)で推論ループを停止し、復帰で再開する。
19. transformers.js の初期化・モデルDL失敗は catch して専用オーバーレイへ。
    進捗は progress_callback で取得し UI に表示する。
```
