# 依頼: WebGL2 リアルタイム映像作品「声」の新規制作

## 1. 作りたいもの

森山直太朗「声」(映画『半落ち』主題歌)のための映像。マイクとカメラ。

**あなたに向けて歌うと、声は雨になって降る。ただし声は空中では見えない。あなたの肩に
触れた瞬間だけ、見える。** カメラに映る人は真綿(まわた)でできていて、届いた声を吸って
黒く重くなる。そして——**大声では届かない。** 声を張ると雨は霧になって身体をすり抜けて
流れていく。静かに、長く、穏やかな声だけが雨になり、肩に着く。

- ファイル名: `opus5_koe.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)

この様式の本質は「**声は、触れたところにしか存在しない**」である。声の可視化を波形・
スペクトル・音量メータのような*読み取り表示*で近似してはならない。それは声の記述であって
声ではない(制作規約 失敗モード#1)。

### 歌詞から取り出した構造

| 歌詞 | 構造 |
|---|---|
| この声が いつの日か あなたに見える日まで | **声を見えるものにする**ことが作品の主命題。ただし空中では不可視で、身体に触れた瞬間だけ可視 |
| ああ愛とは 何も語らず 静かに そっと肩にかかる雨 | 声は雨。着くのは**上を向いた面**(肩・頭頂)から。腕の下側は濡れない。そして「語らず静かに」を**鑑賞者への条件**として実装する — 声を張ると届かない |
| あなたが今日もどこかで 真綿のように生きて居るということ | 人物の**素材**が真綿。数千本の細く短い繊維、マットで白く空気を含む。写真的な切り抜きの逆であり、水の反射の逆でもある |
| 今 私の胸のうちに息衝くのは 確かな誇り | 濡れは乾ききらない。届いたものは残る(下限が 0 ではない)。有界 |
| あの夏の日 風に吹かれ 雲に焦がれ | 風。乾いた繊維は風に梳かれ、雨は斜めに降る。**無音のときの絵を成立させる**担当 |
| あなたが眠る場所へ帰ろう / 夜が明けてしまう前に | 夜であること(暗い実写の地)だけを受け取る。夜明けの周期は**実装しない**(2026-07-28 ユーザー判断。系を増やしすぎないため) |
| 光の庭で 永遠に唄うよ | 植物を育てない(それは `opus5_hana.html` の領分)。「光の庭」は歌う場そのもの=夜の画面として受け取る |

### 近接作品との差別化(このリポジトリは「マイク→人物の周りに何か」が混んでいる)

| 既存作 | 何が違うか |
|---|---|
| `fable5_water-cam` 水のひと | あれは**人物が水になる**(銀の屈折と鏡面)。本作の人物は真綿=**マット・繊維・吸水**で、光らせない。濡れは反射ではなく**暗く重くなる**ことで表す |
| `fable5_kotonoha-shigure` 言の葉時雨 | あれは声が**言葉(活字)**になる。本作の声は言葉にならず、触れた場所にしか現れない |
| `opus5_hana` 花 | あれは声で**植物が育つ**。本作は育てない |
| `opus5_ikitsugi` 息継ぎ | あれは声で**筆が走る**(線)。本作は線を引かない |
| 上記すべて | **音量が大きいほど報われる**設計。本作はそれを反転させる。この反転はリポジトリ内で未踏であり、「声」以外の曲では正当化できない |

## 2. 様式の参照 — 視覚的不変量表

| # | 視覚的不変量(実装可能な構造の言葉で) | 担当軸 | 実装原理の指定 | 外した場合の影響 |
|---|---|---|---|---|
| 1 | 声は触れたところだけで見える: 落下中の雨は完全に不可視。人物のシルエットに達した瞬間だけ着弾が光り、すぐ消える。空中に雨の線・粒・軌跡を一切描かない | 場 | 粒はプール制の GPGPU 粒子。マスクに入った瞬間に短い閃光クワッドを出して死ぬ。飛行中は描画しない | 空中に雨を描いた瞬間、ただの雨エフェクトになり「声が見える」が消える |
| 2 | あなたは真綿でできている: 人物は数千本の細い繊維の集合。マット・白・空気を含む。輪郭は線ではなく毛羽で、繊維は輪郭の外へはみ出す | 質感 | シルエットを埋めるインスタンス繊維クワッド。輪郭付近で密度と長さを上げ、マスクの外へ伸ばす(CRAFT §A2 シール輪郭の対策)。内部を平坦な白で塗らない(§A1 平坦高原の対策) | 人物が「白い切り抜き」になり、真綿という歌詞の中心像が失われる |
| 3 | 濡れは上を向いた面から: 肩と頭頂が先に濡れ、腕の下側は乾いたまま。上に身体がある場所(庇の下)は濡れない | 場 | マスク勾配から法線を作り (normal·up) で重み付け。加えて**上方への短いマーチ**でマスクの遮蔽を見て、庇の下を除外する | どこもかしこも一様に濡れ、「肩にかかる雨」が幾何として存在しない |
| 4 | 濡れた真綿は重くなる: 吸った繊維は暗く、束になり、半透明になって垂れる。水滴の反射で光らせない | 質感 | 濡れ場で繊維の色(白→暗い灰)・向き(風→重力)・束化(近傍でまとまる)・不透明度を変える | 濡れが「明るいハイライト」になると water-cam と同じ絵になり、吸水という素材の本質が消える |
| 5 | 静けさが条件: 雨量は音量ではなく**声の安定度**で決まる。閾値を超える音量では雨が霧に変わり、身体をすり抜けて届かない | 時間 | 安定度 = 短窓 RMS 分散とスペクトル流束の逆数。雨量 ∝ 安定度 × (適度な音量)、音量が閾値超で mist 比率が上がる。mist 粒はマスクを無視して通過し、堆積しない | 「何も語らず静かに」が絵に出ず、声を張るほど派手になる既存作と同じ設計になる |
| 6 | 確かな誇り: 濡れは乾ききらない。下限が 0 ではなく、届いたものは残る。ただし上限があり発散しない | 時間 | 濡れ場の減衰に床(floor)を設ける。床自体もゆっくり上がるが上限で飽和 | 歌い終えると全部乾いて、何も届かなかったことになる |

優先度(外すとその様式に見えなくなる順): 1 > 2 > 5 > 3 > 4 > 6

## 3. 入力映像から生き残らせる信号

- 生き残る: **人物のシルエットと動き**、そして**背景の実写**(暗い夜の部屋として)。
  声の安定度・音量・声色。
- 様式側で置き換わる: 人物の**素材**(実写 → 真綿の繊維)。
- 背景の実写はそのまま投影する(`opus5_kiin-seido` での是正: 背景を動く仮想背景に
  置き換えない)。真綿になるのは**人物だけ** — 「真綿のように生きて居る」のは あなた で
  あって部屋ではない。
- 被写体が人間の姿として判読できることは受入基準である。

## 4. 技術方針

派生元エンジン: `opus5_hana.html`(MediaPipe ImageSegmenter のモバイル手順・マイク解析・
合成の歌・カメラと UI と検証フック)。

実装原理は次の技法語彙で固定する: **ping-pong**(濡れ場と雨粒プールの状態)、
**EMA**(マスク・運動場・音の各メーター・安定度)、
**stroke splatting**(真綿の繊維と着弾の閃光のインスタンス描画)、
**hysteresis**(アタック検出)、**SDF**(fakesource の合成人型)。
新規要素として**マスク勾配 → 法線 + 上方マーチによる遮蔽判定**を導入する
(`loop/TECHNIQUES.md` に既存項目なし。シルエットには奥行きが無いので、
「上を向いた面」は輪郭の勾配としてしか定義できない。ゆえに濡れの発生源は
輪郭の細い帯であり、身体を覆うのは重力で流れ落ちる分である)。

- MediaPipe は **ImageSegmenter のみ**。推論は 288px 縮小コピー、33〜250ms の適応
  カデンス、GPU→CPU デリゲートのフォールバック。マスクが取れなくても(拒否・失敗)
  絵が成立すること。
- uDebug の割り当て: 0=最終 / 1=マスクと法線 / 2=濡れ場 / 3=音の特徴量(**安定度を
  含む**) / 4=雨と繊維 / 5=配色標本。
- モバイル: 繊維本数と粒子プールを落とす。ソフトウェアレンダラはさらに小さく。

## 6. 制約条件(リポジトリ規約)

- **単一の自己完結** HTML(WebGL2 / GLSL ES 3.00)。外部依存は MediaPipe tasks-vision と
  そのモデルのみ(許可リスト内)。
- **カメラ**: `getUserMedia({ facingMode })`、`<video playsinline muted autoplay>`、
  モバイルで前面/背面の切替。エラー3経路(SECURE CONTEXT / PERMISSION DENIED /
  NO CAMERA)に専用オーバーレイと再試行。マイクは拒否されても自走すること。
- **品質基準**: 60fps 目標。DPR は 2 で上限。`preserveDrawingBuffer: true`。
  規約ID を踏襲。`prefers-reduced-motion` 対応。
- **検証フック**: `window.__artReady`、`?freeze=1`、`?prewarm=<秒>`、`?fakesource=1`、
  `?fakeseg=1`、`?fakescale=<f>`。

## 7. 技術注意リスト(既知の地雷)

1. GLSL の**予約語**を変数名にしない(`sample` `filter` `input` `output` `patch` ほか)。
2. 場と状態は必ず **ping-pong**。
3. GLSL のテンプレートリテラル内に**バッククォートを書かない**(コメントでも JS の
   文字列が閉じて構文エラーになる)。
4. マーク配置・繊維のシードに `uTime` を混ぜない(freeze でチラつく)。
5. 蓄積する場(濡れ)は減衰と注入のバランスを `--longrun` で測る。**床を持つ場は
   特に**、上限で飽和することを数値で確認する。
6. 「上を向いた面」の判定はマスクをぼかしてから勾配を取る。生マスクの勾配は
   ブロックノイズになる。
7. `?fakesource=1` の合成の歌は**音量が大きい構成**である。安定度メーターが駆動される
   静かな持続パッセージが無いと、不変量5が検証されないまま通ってしまう
   (`opus5_samoarinan` で「指標が実は雨のざわつきを測っていた」ことに後で気づいた前例)。
   合成の歌に静かな区間を必ず設け、デバッグ表示3で安定度を目視すること。

## 8. 進め方(フェーズ制・厳守)

- Phase 1: 不変量表の復唱+実装上の懸念点の列挙(コードを書かない)
- Phase 2: 設計 — パス構成図(入出力・解像度・フォーマット・更新頻度)、
  メモリとフィルレート概算、リスク
- Phase 3: 実装 — 骨格(カメラ→cover-fit→素通し→UI→エラー経路)→ 標本(濡れ場と
  法線のデバッグ表示、繊維と着弾の標本)→ パス追加
- Phase 4: 検証 — 検証手順+自己批評ルーブリック。未検証のまま完成と報告しない

## 9. 検証環境と手順

- ローカル: `python3 -m http.server 8899` → `http://localhost:8899/opus5_koe.html`
- **フェイクカメラ** + `?fakesource=1` で全パイプラインをオフライン駆動。
  **スクリーンショット**を1変更ごとに撮って自分の目で見る(CRAFT §D1)。
- 決定的検証: `node loop/runner/verify_static.mjs` と
  `node loop/runner/verify_runtime.mjs <url>?fakesource=1&freeze=1 --motion --longrun`
- 実機スケール: `?fakescale=0.5` と `?fakescale=1.9` の両端。

## 10. 自己批評ルーブリック

各不変量を 1〜5 で自己採点し、4 未満なら原因(構造の欠落か、パラメタか)を書く。加えて:

- **ゲシュタルトテスト**: 先入観なしに「この画像は何に見えるか」。「雨のエフェクト」
  「白い切り抜き」「水の人」に見えたら不成立。
- **静けさテスト**: 静かに歌ったときと張り上げたときで、絵が**逆方向に**動くか。
  どちらでも同じように賑やかになるなら不変量5は未達。
- **肩テスト**: 濡れが肩と頭頂から始まっているか。腕の下側が乾いているか。
- 無音のときの絵が成立しているか(風だけで持つか)。
