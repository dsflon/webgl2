# 依頼: WebGL2 リアルタイム映像作品「Blue Dissolve Cam」の新規制作

## 1. 作りたいもの

Webカメラに映った人物の輪郭が、**青く発光する煙となってほどけていく**リアルタイム作品。
画面は夜のサイバーパンク・スリラーの1カットとしてグレードされ、暗い書き割りの背景に
赤/青の警察灯のボケ光が揺れ、人物のシルエットは左右から赤青のリムライトに縁取られる。
動くほど激しく煙になり、静止すると縁からゆっくり実体が再構成される。

- ファイル名: `fable5_blue-dissolve.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)

この様式の本質は「**溶解境界(実体↔気体の遷移帯)が実在し、煙がそこから実際に放出される**」
ことである。人物の上に煙を半透明合成しただけの画は不合格(制作規約 失敗モード#1)。
写実(photorealistic)の再現は目標ではない — リアルタイムの様式化されたVFXとして成立させる。

## 2. 様式の参照 — 視覚的不変量表(ゲート1通過済み)

参照(brief.references の言語化):
1. 夜の暗い街路に立つ人物。顔と手の輪郭が青く発光する濃い煙へ解けていく。遷移部が最も明るい。
   背景はボケたシルエット群と赤/青の警察灯。
2. ナイトグレード: 暗部は青緑に濁り、黒は落ちきらない。画面外の赤/青光源による対向リムライト。
   フィルムグレインの空気感。
3. 実写VFXの溶解表現: 侵食帯は輪郭の縁から進行し、放出された気体は渦を巻いて上昇し減衰する。

| # | 視覚的不変量(実装可能な構造の言葉で) | 担当軸 | 実装原理の指定 | 外した場合の影響 |
|---|---|---|---|---|
| 1 | 人物シルエットの縁に「溶解帯」が存在し、内側=実体・外側=気体・帯上は混在して最も明るく発光。煙はこの帯から実際に放出される | マーク/場 | 背景の遅い EMA 推定との差分からシルエット場を作り、擬似 SDF の帯から流体の密度場へ毎フレーム注入 | 半透明オーバーレイ合成に見え「解けていく」が消える |
| 2 | 煙は流体として振る舞う(移流で運ばれ、渦を巻いて上昇し、実体側を避ける)。スプライト貼り付けではない | 場/時間 | 半解像度 Stable Fluids(semi-Lagrangian 移流+Jacobi 圧力+vorticity confinement)+curl noise 外乱+弱い浮力 | ゲームのスプライト煙に見える |
| 3 | 煙は自発光する: 芯ほど白青く飽和、縁ほど深青。多段ブルームでにじみ、残光を引く | 色/物質 | 密度→発光ランプ(深青→シアン→白)+分離ブラー多段ブルーム+feedback 減衰残光 | 光らないドライアイスになる |
| 4 | 夜のシネマティックグレード: 暗部=青緑、赤/青の対向リムライト、背景は暗い書き割り+ボケ光帯 | 色/知覚 | 輝度ゾーン別 split toning+シルエット縁の Fresnel 近似リム+背景ボケ光の書き割り | ただのカメラ映像+煙になる |
| 5 | 溶解は動きに反応: 速く動いた部位ほど侵食が深く、静止で縁からゆっくり再構成 | 時間 | フレーム差分の EMA 運動場が注入量と侵食深さを変調(速い=溶ける/遅い=戻る) | 静的エフェクトになり物語性が消える |
| 6 | 静的フィルムグレイン+暗部ノイズフロアの湿った空気感 | 物質 | cell-hash 静的グレイン(時間シード禁止)+暗部限定ディザ | 合成が浮いてデジタル臭くなる |

優先度(外すと様式に見えなくなる順): **1 > 3 > 2 > 4 > 5 > 6**

Phase 1 ではこの表を独自の再解析で置き換えず、復唱と実装上の懸念の列挙のみ行うこと。

## 3. 入力映像から生き残らせる信号

- 生き残る: 人物のシルエット(形態)/ 動きの速さと方向(煙の放出へ)/ 大まかな明暗
- 様式側で置き換わる: 色(夜のスプリットトーン+青発光ガス)/ 背景(暗い書き割り+ボケ光帯)/
  溶解帯より外の肌・服のテクスチャ
- 被写体(人物)がシルエットと残存実体部で判読できることは受入基準である。

## 4. 技術方針(この指定に従うこと)

実装原理は次の技法語彙で固定する: **Stable Fluids / curl noise / feedback / EMA /
split toning / cell-hash / Fresnel / SDF**

- **シルエット推定(ML 不使用・外部依存ゼロ)**: 背景の遅い EMA 推定(人物がいない部分が
  ゆっくり背景に馴染む)との色差分+中央重みの事前分布でシルエット場を作る。
  起動直後は数秒の「背景学習」があってよい(UI に LEARNING BACKGROUND 表示)。
  シルエット場は EMA で時間平滑化し、縁の擬似 SDF(ぼかし値)から溶解帯を導出する。
- **流体**: 半解像度以下(長辺 ≤512)の Stable Fluids。Jacobi 圧力反復 20〜30回。
  vorticity confinement あり。外力 = 運動場(フレーム差分の EMA)+curl noise+浮力。
  密度注入は溶解帯からのみ。実体内部には注入しない。
- **発光と残光**: 密度→カラーランプ(深青 #0a2a66 → シアン #35c8ff → 白 #eaf6ff 目安)。
  ブルームは縦横分離ブラーの2〜3段。feedback バッファ(ping-pong)の減衰で残光。
- **グレード**: split toning(影 #12333a 系 / 中間 #274a6e 系 / ハイライト冷白)。
  リムは左=赤 #ff2f4f / 右=青 #2f6dff(スライダーで入替可でなくてよい)。
  背景書き割りは映像をほぼ落とし、大きなボケ円/光帯(静的+ゆっくり明滅)に置き換える。
- **?fakesource=1(必須)**: カメラの代わりに合成シーン(暗い背景+中央の人物シルエット:
  頭・肩・挙げた両手が判る形。腕がゆっくり動く)を入力にする。オフライン検証・標本用。
- **?freeze=1(必須)**: 時間駆動を全て停止して決定的な静止フレームを出す —
  流体シミュレーション・背景学習(EMA)・書き割りの明滅・fakesource の腕の動き・残光の
  減衰を含む(freeze 中は最後の場をそのまま表示し続ける)。
- **window.__artReady(必須)**: 最初の本描画フレームで true。
- **uDebug**: 0=最終 1=シルエット場 2=流体密度 3=速度場 4=溶解帯(SDF) 5=グレードのみ(煙なし)
  6=背景推定。UI の DEBUG セレクタから切替。

## 8. 技術注意リスト(遵守すること)

1. GLSL ES 3.0 の予約語を変数名に使わない: coherent, sample, filter, precise,
   restrict, readonly, writeonly, subroutine, input, output, common, partition, active
2. 同一テクスチャを read しながら write しない。流体・feedback・EMA は必ず ping-pong。
3. float テクスチャは EXT_color_buffer_float を確認し、未対応時の代替(RGBA8 パック等)を用意。
4. 速度場のクランプと密度の減衰を必ず入れる(発散すると NaN 黒画面)。
   normalize(ゼロベクトル) は NaN。pow(x,y) は x<0 で未定義。
5. Jacobi 反復は const int MAX + break。
6. 乱数は pcg系 hash12。グレインのシードに時間を混ぜない(cell-hash)。
7. UNPACK_FLIP_Y_WEBGL は DOM ソースのみ。
8. gl_PointSize は使用時必ず書く。canvas は preserveDrawingBuffer: true。
9. ブラーは縦横分離。readPixels を毎フレーム呼ばない。
10. freeze=1 は dt=0 と等価にすること(パスをスキップするのではなく時間発展だけ止めると
    実装が単純になる。ready フックは freeze でも立つこと)。
