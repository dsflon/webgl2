# 依頼: WebGL2 リアルタイム作品「打ち水」の新規制作

## 1. 作りたいもの

記録的酷暑への「対処」を体験にする。陽炎の立つ乾いた灼熱の路面を、指(タップ/
ドラッグ)でなぞると**水を撒ける**。撒いた水は流体場として路面に広がり、地熱で
湯気を上げながら蒸発し、濡れの帯が『涼』として通り抜ける。触らない待機時間は
路面がじりじりと乾き、陽炎の屈折ゆらぎが戻る — この**乾き↔打ち水のループそのもの**が
主役である。カメラもマイクも使わず、路面・水・陽炎はすべてジェネラティブに合成する。

- ファイル名: `fable5_uchimizu.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)
- **入力: ポインタ/タッチのみ**。カメラ・マイクは使わない。
  `<meta name="art-input" content="none">` を宣言する(カメラ規約の免除プロファイル。
  検証器対応済み)。

この様式の本質は「**触れて涼を作る介入 — 撒いた水が流体場として広がり、蒸発して
必ず乾きへ戻る**」である。これを後処理(ぼかし・色調整・オーバーレイ)で近似しては
ならない(制作規約 失敗モード#1)。水の広がりと蒸発は Stable Fluids の場で駆動すること。

## 2. 様式の参照 — 視覚的不変量表(ゲート1通過済み)

参照:
- **夏の路面への打ち水**(photo): 乾いたアスファルトに水を撒くと、周囲より濃く暗い
  『濡れの縁』ができて広がり、強い日差しの下でじきに蒸発して薄れる。晴天の白い照り返しの
  中で濡れた帯だけが涼しく沈む。
- **陽炎・逃げ水**(image): 灼けた路面直上の空気が密度ムラで光を屈折させ、遠景が波打つ。
  揺らぎは細かく、上へ立ちのぼるほど強い。
- **温度の色対比**(style): 乾いた高温路面は白茶〜赤みの暖色の照り、濡れた面は暗く
  彩度が落ちて青みに沈む。乾湿=暑涼が色温度対比として読める。

## 3. 入力から生き残らせる信号

- 生き残る: **ポインタ/タッチの位置**→水の注入位置 / **移動速度**→速度場への外力と
  撒かれる水量 / **時間**→乾き・蒸発・湯気上昇・陽炎位相の内部時計。
- 様式側で置き換わる: カメラ映像→使用しない(乾いた灼熱路面と陽炎を完全合成) /
  実写の水→ Stable Fluids の密度場が作る水膜と移流・拡散・蒸発 / 実写の湯気→
  濡れ密度から立ちのぼる浮力ある上昇密度(curl noise で揺らす)。
- 「触らない待機状態が陽炎として美しく成立すること」は受入基準である。

## 4. 技術方針(この指定に従うこと)

実装原理は次の技法語彙で固定する: **Stable Fluids / curl noise / domain warp / fbm /
sdf / oklab / edge darkening / ema / ping-pong**。

- **流体場(Stable Fluids)**: 半解像度の速度場・濡れ密度場・湯気密度場を float テクスチャ
  ping-pong で持つ。advect→(濡れは蒸発減衰・湯気は浮力)→注入→clamp の順。EXT_color_buffer_float
  未対応時は RGBA8 でスケールを持たせた代替にフォールバック。速度平滑に ema。
- **背景路面(陽炎)**: フルスクリーン合成パスで、乾いた路面テクスチャ(fbm のマイクロ凹凸)を
  domain warp で歪めて陽炎を出す。歪み量 = 乾き度 × 時間発展 fbm(下→上で増加)。
- **合成**: 濡れ密度 → oklab で温度色を補間、濡れの縁を edge darkening、水面ハイライトを
  擬似法線で乗せ、湯気を加算合成。周縁ビネット。乱数は pcg 系 hash12(時間を混ぜない)。
- **外部依存なし**(ML モデル不使用)。
- **?fakesource=1(合成入力)**: 実ポインタを使わず、**決定的スクリプトで撒く動作
  (画面中央を横切るドラッグ列)を一定周期で発行**して水注入→拡散→蒸発→乾きの全経路を
  駆動する。時間軸検証(--motion)の前提として、fakesource では常に水膜と湯気が動くこと。
  中央列は放置検証時に陽炎へ戻る様子も含む。
- **uDebug モード割り当て**: 0=最終合成 / 1=濡れ密度場 / 2=速度場(可視化) /
  3=湯気密度 / 4=標本(乾湿の温度色見本+陽炎ゆらぎのテストパッチ)。

## 7. 制約条件(dsflon/webgl2 リポジトリ規約 — 受入基準を兼ねる)

### 成果物の形
- 単一の自己完結 HTML。外部ライブラリ・ビルド工程・外部アセット禁止(本作の許可: なし)。
- WebGL2 / GLSL ES 3.00。WebGL1 フォールバック不要。
- ファイル冒頭に HTML コメントで: 作品概要 / 実行方法 / 様式解析の要約 /
  パイプライン図 / 全スライダーの説明 を書くこと。
- README.md の作品リストに GitHub Pages の URL を追記すること。

### カメラ・入力(本作固有)
- **本作はカメラ不使用**。`<meta name="art-input" content="none">` を宣言する。カメラ用 UI
  (#video / #retryCamera / facingMode)とカメラエラー文字列は実装不要。
- 入力はポインタ/タッチのみ。`pointerdown/move/up` と touch を扱い、ドラッグで連続的に
  水を撒く。座標はキャンバス解像度・DPR に正しく変換すること。
- 入力が全く無くても作品は成立する(乾いた路面＋陽炎)。初回訪問者向けに、数秒操作が
  無ければ「タップ/ドラッグで打ち水」の淡いヒントを出し、触れたら消す。

### UI(既存作品の panel 構造を踏襲)
- 実装前に `fable5_papercraft-cam.html`(または kotonoha-shigure)を読み、UI パネル
  (折りたたみ)・PNG 保存・オーバーレイ・readout の規約を読んで踏襲すること(カメラ部分は不要)。
- 全パラメタは単一の state オブジェクトに集約し、スライダー定義は
  [key, ラベル, ヒント, min, max, step] の配列から生成すること。
- DEFAULTS と「RESET LOOK」。「HIDE UI」「SAVE PNG」(preserveDrawingBuffer: true)。
- prefers-reduced-motion 時はアニメーション停止トグルを初期 ON(陽炎・湯気の揺れを止める)。

### 検証フック(機械検証が依存する。必須)
- window.__artReady: 最初の本描画フレーム完了時に true を立てること。
- ?freeze=1: 時間駆動(陽炎・湯気・蒸発の進行)を停止し決定的な静止フレームを出すこと。
- ?fakesource=1: 実ポインタなしで、決定的な散水ストローク列で全パイプライン
  (注入→拡散→蒸発→湯気→乾き)を駆動できること。

### 品質基準
- 入力の無い静止状態(乾いた路面)で画面がチラつかないこと(乱数シードは座標由来)。
- デスクトップ 60fps / モバイル 30fps 以上(DPR 上限 2、流体場は半解像度で解像度上限)。
- リサイズ・タブ復帰で壊れないこと(流体テクスチャの再確保を正しく行う)。

## 8. 技術注意リスト(遵守すること)

1. GLSL ES 3.0 の予約語を変数名に使わない: coherent, sample, filter, precise,
   restrict, readonly, writeonly, subroutine, input, output, common, partition, active
2. 同一テクスチャを read しながら write しない。feedback/拡散/EMA は必ず ping-pong。
3. float テクスチャは EXT_color_buffer_float を確認し、未対応時の代替を用意。
4. MRT のブレンドは全アタッチメント共通。クリアは clearBufferfv を毎アタッチメント。
5. 方向場は二重角 (cos2θ, sin2θ)。角度の直接 lerp をしない。
6. normalize(ゼロベクトル) は NaN。pow(x,y) は x<0 で未定義。
7. ループは const int MAX + break。
8. 頂点シェーダのテクスチャ参照は textureLod。
9. 乱数は pcg系 hash12。シードに時間を混ぜない。
10. UNPACK_FLIP_Y_WEBGL は DOM ソースのみ。TypedArray アップロードはシェーダ側で向きを合わせる。
11. gl_PointSize は使用時必ず書く。canvas は preserveDrawingBuffer: true。
12. UV・位置計算は highp。
13. ブラーは縦横分離。readPixels を毎フレーム呼ばない。
14. ポインタ座標は canvas 論理サイズ→流体場 UV へ DPR 込みで正確に変換。移流の
    CFL 安定のため速度に上限クランプ。蒸発率は dt スケールし、フレームレート非依存に。

## 9. 検証環境

- フェイク入力+スクリーンショットは `loop/runner/`(verify_runtime.mjs)を使う。
  ローカルサーバは python3 -m http.server 8888。カメラは使わないためフェイクカメラ機構は
  発火しないが、URL 形式は共通: `?fakesource=1&freeze=1`。
- スクリーンショットは (a) 最終合成(非 freeze で 8〜15 秒 warm、散水→蒸発が進んだ絵)
  (b) uDebug の主要モード(濡れ密度・湯気・速度場) (c) ?fakesource=1 の標本 の3枚以上。
  pageerror が出ていないことを毎回確認する。
- **蓄積系(密度・feedback で絵が育つ)につき `verify_runtime --longrun` で長時間安定
  (whiteout/発散なし)を確認すること**。時間軸の不変量(id 2/3/6)があるため `--motion` も必須。
- 本作は外部検知を使わないため実機乖離(CRAFT §C)は**該当なし**。ポインタ作品として
  完全オフライン検証可(V-A)。実ポインタ・実機タッチの操作感のみ目視の領分として明記する。
- 検証できない項目は「未検証」と明記し、確認すべき点を列挙すること。
