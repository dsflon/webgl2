# 依頼: WebGL2 リアルタイム作品「走馬灯」の新規制作

## 1. 作りたいもの

盆提灯の走馬灯(回り灯籠)。二重構造の灯籠で、内側の絵筒に貼られた切り絵が灯の
上昇気流でゆっくり回り、外側の和紙に**逆光のシルエット**が映って紙面を巡っていく。
行列は片端から現れ、反対の端へ去り、周期をおいてまた現れる。灯は炎なので明るさも
回転もわずかに揺らぎ、影は呼吸する。夜闇に灯籠だけが琥珀色に浮かぶ。**無操作で
延々と巡り続ける情景そのものが主役**である。

- ファイル名: `opus5_soumatou.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)
- **入力: 無入力(時間のみ)が主。ポインタは副入力(なくても完全に成立)**。カメラ・
  マイクは使わない。`<meta name="art-input" content="none">` を宣言する
  (カメラ規約の免除プロファイル。検証器対応済み)。

この様式の本質は「**影絵が巡る — 過ぎ去る時間**」である。これを後処理(ぼかし・
セピア調・オーバーレイ)で近似してはならない(制作規約 失敗モード#1)。影は
**光源・切り絵・投影面の距離関係から計算した半影つきの投影**として実装すること。

## 2. 様式の参照 — 視覚的不変量表(ゲート1通過済み)

参照:
- **走馬灯(回り灯籠)の実物**(photo): 内側の絵筒が灯の上昇気流で回り、外側の和紙に
  切り絵の影が逆光のシルエットとして映って横へ流れる。紙は灯の色に温かく透け、影は暗く沈む。
- **点光源による影の半影(penumbra)**(image): 有限サイズの光源が作る影は、遮蔽物が投影面に
  近いほど鋭く、離れるほどぼけて大きい。影の内部は一様に暗く階調を持たない純粋なシルエット。
- **和紙の透過光と枠の骨**(style): 内側から照らされた和紙は中央ほど明るい琥珀色で周縁に落ちる。
  繊維のむらが透過光に細かい濃淡を作り、枠の縦桟が暗い直線として紙面を区切る。
- **炎のゆらぎと回転**(style): 光量が絶えず微かに揺れ、上昇気流に依存する回転も一定でない。
  影は呼吸するように濃さと位置を揺らす。

## 3. 入力から生き残らせる信号

- 生き残る: **時間**(唯一の外部信号。絵筒の回転位相・炎のゆらぎ・影の巡りを駆動) /
  **ポインタ**(副入力・なくても成立。触れている間だけ回転を速める/緩める、灯を強める)。
- 様式側で置き換わる: カメラ映像→使用しない(夜闇の灯籠を完全合成) / 実写の切り絵→
  sdf で彫ったシルエット群 / 実写の影→光源・切り絵・紙の距離関係から計算する半影つき投影。
- **無操作の巡りが主役級に美しいこと**は受入基準である(ポインタは味付けに留める)。

## 4. 技術方針(この指定に従うこと)

実装原理は次の技法語彙で固定する: **sdf / oklab / edge darkening / fbm / ema /
ping-pong / cell-hash / curl noise**。

- **影絵の形(sdf)**: 馬・草・鳥・雲など単純な図形を sdf で彫り、筒の周方向に複数配置する
  (行列を成す)。図形の種類・間隔は cell-hash で決定的に散らす(時間シードを混ぜない)。
- **回転と投影**: 円筒の回転位相 θ(t) を進め、紙面の横座標を筒の周座標へ写像して sdf を
  サンプルする。切り絵→紙の距離は θ 依存(手前/奥)で変わり、その距離で**半影のボケ半径**
  (smoothstep 幅)と影の濃さを変える。円筒の湾曲による横方向の伸縮も反映する。
- **紙の透過光**: 中心から距離減衰＋ fbm の繊維むら＋等間隔の縦桟の暗帯。周縁は edge darkening。
- **炎**: fbm/curl noise で光量と角速度を低振幅変調し、ema で平滑。状態は ping-pong で保持。
- **色**: oklab で琥珀→暗褐色。影は純黒にしない。背景は暗い夜色。
- **外部依存なし**(ML モデル不使用)。
- **?fakesource=1(合成入力)**: 実ポインタを使わず、**決定的スクリプトで回転と炎のゆらぎを
  進める**(通常の無入力挙動と同じで可)。時間軸検証(--motion)の前提として、fakesource では
  常に影が巡って画面が変化すること。
- **uDebug モード割り当て**: 0=最終合成 / 1=影のマスクのみ(半影の効きを確認) /
  2=紙の透過光のみ(繊維・桟・減衰) / 3=切り絵 sdf の配置(筒の展開図) / 4=標本(琥珀→暗褐色の
  色見本＋半影のボケ量の段階見本)。

## 7. 制約条件(dsflon/webgl2 リポジトリ規約 — 受入基準を兼ねる)

### 成果物の形
- 単一の自己完結 HTML。外部ライブラリ・ビルド工程・外部アセット禁止(本作の許可: なし)。
- WebGL2 / GLSL ES 3.00。WebGL1 フォールバック不要。
- ファイル冒頭に HTML コメントで: 作品概要 / 実行方法 / 様式解析の要約 /
  パイプライン図 / 全スライダーの説明 を書くこと。
- README.md の作品リストに GitHub Pages の URL を追記すること。

### カメラ・入力(本作固有)
- **本作はカメラ不使用**。`<meta name="art-input" content="none">` を宣言。カメラ用 UI
  (#video / #retryCamera / facingMode)とカメラエラー文字列は実装不要。
- 主入力は時間(無入力)。**入力が全く無くても完全に成立する**こと。
- ポインタは副入力: 触れている間だけ回転を速める/緩める・灯を強める程度に留める
  (作品の主役は無操作の巡り)。数秒無操作なら「触れると灯がゆらぐ」の淡いヒントを出し、
  触れたら消す。

### UI(既存作品の panel 構造を踏襲)
- 実装前に `fable5_senkohanabi.html`(または papercraft-cam)を読み、UI パネル(折りたたみ)・
  PNG 保存・オーバーレイ・readout の規約を踏襲すること(カメラ部分は不要)。
- 全パラメタは単一の state オブジェクトに集約し、スライダー定義は
  [key, ラベル, ヒント, min, max, step] の配列から生成すること。
- DEFAULTS と「RESET LOOK」。「HIDE UI」「SAVE PNG」(preserveDrawingBuffer: true)。
- prefers-reduced-motion 時はアニメーション停止トグルを初期 ON(回転と炎の揺れを止める)。

### 検証フック(機械検証が依存する。必須)
- window.__artReady: 最初の本描画フレーム完了時に true を立てること。
- ?freeze=1: 時間駆動(回転・炎のゆらぎ)を停止し決定的な静止フレームを出すこと。
- ?prewarm=<秒>: 初回描画の前に、指定秒ぶんのシミュレーションを固定 dt で決定的に
  早送りしてから開始すること(freeze の preroll と同じ機構を非 freeze にも公開する。
  検証環境はソフトウェアレンダリングで実時間 warm が数分かかるため、「絵が育った状態」の
  スクショをこのフックで数秒で撮る)。本作は蓄積系ではないが、回転位相を進めた状態を
  決定的に得るために実装すること。
- ?fakesource=1: 実ポインタなしで決定的に回転・炎のゆらぎを駆動できること。

### 品質基準
- 入力の無い状態で画面がチラつかないこと(乱数シードは座標/セル由来、時間を混ぜない)。
- デスクトップ 60fps / モバイル 30fps 以上(DPR 上限 2)。
- リサイズ・タブ復帰で壊れないこと。

## 8. 技術注意リスト(遵守すること)

1. GLSL ES 3.0 の予約語を変数名に使わない: coherent, sample, filter, precise,
   restrict, readonly, writeonly, subroutine, input, output, common, partition, active
2. 同一テクスチャを read しながら write しない。feedback/EMA は必ず ping-pong。
3. float テクスチャは EXT_color_buffer_float を確認し、未対応時の代替を用意。
4. MRT のブレンドは全アタッチメント共通。クリアは clearBufferfv を毎アタッチメント。
5. 方向場は二重角 (cos2θ, sin2θ)。角度の直接 lerp をしない。
6. normalize(ゼロベクトル) は NaN。pow(x,y) は x<0 で未定義。
7. ループは const int MAX + break(切り絵の走査も上限つき)。
8. 頂点シェーダのテクスチャ参照は textureLod。
9. 乱数は pcg系 hash12 / cell-hash。シードに時間を混ぜない。
10. UNPACK_FLIP_Y_WEBGL は DOM ソースのみ。TypedArray アップロードはシェーダ側で向きを合わせる。
11. gl_PointSize は使用時必ず書く。canvas は preserveDrawingBuffer: true。
12. UV・位置計算は highp。
13. ブラーは縦横分離。readPixels を毎フレーム呼ばない。
14. 回転位相・炎のゆらぎは dt スケールでフレームレート非依存に。位相は周期で折り返し、
    long-run で数値が発散しないこと(fract や mod で丸める)。

## 9. 検証環境

- フェイク入力+スクリーンショットは `loop/runner/`(verify_runtime.mjs)を使う。
  ローカルサーバは python3 -m http.server 8888。カメラ不使用ゆえフェイクカメラ機構は
  発火しないが、URL 形式は共通: `?fakesource=1&freeze=1`。
- スクリーンショットは (a) 最終合成(`?prewarm=12` で回転が進んだ状態) (b) uDebug の主要
  モード(影マスク・紙の透過光) (c) 標本 の3枚以上。pageerror が出ていないことを毎回確認する。
- **時間軸の不変量(id 2/5)があるため `--motion` は必須**。蓄積系ではないため `--longrun` は
  任意だが、位相の数値発散がないことは確認すること。
- 本作は外部検知を使わないため実機乖離(CRAFT §C)は**該当なし**。無入力作品として
  完全オフライン検証可(V-A)。実機での回転の滑らかさのみ目視の領分として明記する。
- **反復中のスクショは小画面(480×300 程度)で撮る**(swiftshader はフィルレート律速)。
  報告用の一式のみフルサイズで撮り直す。
- 検証できない項目は「未検証」と明記し、確認すべき点を列挙すること。
