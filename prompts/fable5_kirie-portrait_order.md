# 依頼: WebGL2 リアルタイム映像作品「切り紙の積層ポートレート」の新規制作

## 1. 作りたいもの

Webカメラに映る人物を、**多層ペーパーカット(レイヤード・ペーパーコラージュ)の
ポートレート**としてリアルタイムに再構成する。肌は陰影で切り分けたフラットな紙の
積層(各層に切り口の厚みと落ち影)、**髪はカールした紙リボン(クイリング)の集合**、
服は重なる紙の帯。人物は無地の台紙に貼られた切り紙として、台紙に一つの柔らかい
影を落とす。参照画像3枚(refs/)のトーンと物質感に忠実に。

- ファイル名: `fable5_kirie-portrait.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)
- 入力: **Webカメラ(必須)+ MediaPipe ImageSegmenter 多クラス**(髪/顔肌/体肌/服/背景)。
  マイク・ポインタは使わない(ポインタはプリセット切替等のUI操作のみ)。

この様式の本質は「**人物を紙の層に再構成する**」である。これを後処理(ポスタライズ
フィルタ・輪郭線オーバーレイ)で近似してはならない(制作規約 失敗モード#1)。層は
量子化された面として明示的に持ち、切り口・落ち影は層構造から導出すること。

## 2. 様式の参照 — 視覚的不変量表(ゲート1通過済み)

参照(実物画像 — `loop/state/kirie-portrait/refs/` を必ず View してから実装):
- `ref_1_hijab.jpg`: ティール台紙にピンクのヒジャブの女性(横顔)。肌4〜6段の暖色トーン積層、
  ヒジャブは幅広の紙帯の波状の重なり(帯ごとに明度1段差・縁に切り口と落ち影)。
- `ref_2_curls_man.jpg`: 濃紺の紙テープを丸めたカール髪(クイリング)。個々のリボンに
  円筒の明暗・縁の照り・下への落ち影。顔は大きな面の積層、目・眉・唇だけ精密。
- `ref_3_curls_woman.jpg`: 茶〜紺のカール+柄の紙帯のスカーフ。頬に円形の紙が1枚。
  服は紺の細い紙襞が放射状。イヤリングは紙の輪。彩度統一・影は柔らかく短い。

## 3. 入力映像から生き残らせる信号

- 生き残る: **陰影の大きな構造**(頬・鼻筋・顎・額の明暗→切り分け線) / **部位クラス**
  (髪・顔肌・体肌・服→紙の扱いの違い) / **輪郭**(単純化した切り紙曲線として) /
  **目・眉・唇の判読性** / **身体の動き**(層とリボンが追従)。
- 様式側で置き換わる: 実写の質感→フラットな紙面+繊維グレイン / 実背景→無地の台紙色+
  人物の落ち影 / 実際の髪→紙リボンのカール / 服の皺・柄→紙の帯と落ち影。
- **被写体(人物)が判読できることは受入基準である。**

## 4. 技術方針(この指定に従うこと)

実装原理は次の技法語彙で固定する: **kuwahara / quantile / hysteresis / ema / etf /
stroke splatting / sdf / oklab / cell-hash / ping-pong / edge darkening**。

- **検知**: MediaPipe ImageSegmenter(tasks-vision)の**多クラスセルフィーセグメンテーション**
  (selfie_multiclass 系: 背景/髪/体肌/顔肌/服)。モデルURLは許可リスト
  (cdn.jsdelivr.net/npm/@mediapipe/tasks-vision / storage.googleapis.com/mediapipe-models/)
  内から、**実在するファイル名を必ず確認して**使う(打ち間違い404=検知全滅、CRAFT §C2)。
  クラスマスクは ema で平滑(≈11/s 目安、CRAFT §B3)。
- **トーン積層(肌・服)**: kuwahara(または双方向平滑)→輝度の quantile 量子化(クラス別の
  段数)→境界の擬似 sdf 帯で切り口+落ち影。しきい値は ema+hysteresis。
- **髪リボン**: 髪クラス領域で etf(構造テンソル/Sobel から)を計算し、リボン(曲率つき帯)を
  stroke splatting でインスタンス描画。円筒シェーディング+縁の照り+リボンごとの落ち影。
  シードは cell-hash の安定空間、更新はゆっくり(マスクノイズで震えない)。
- **台紙**: 背景クラスをフラット色に置換、人物マスクの平滑輪郭で切り、ぼかし+オフセットの
  落ち影。紙グレインは cell-hash 由来(時間を混ぜない)。
- **色**: oklab でクラス別パレットへスナップ。プリセットで台紙色とパレットの組を切替。
- **?fakesource=1(合成入力)**: カメラ・MediaPipe を使わず、**合成人物(頭部+髪領域+肩+服の
  動くフィギュア)とその合成クラスマスク**で全パイプラインを駆動。--motion の前提として
  フィギュアが動き続けること。**?fakescale=<f>**(CRAFT §C2): 合成フィギュアを係数 f で
  拡縮(既定1.0)。**?fakeseg=1**(CRAFT §C1): 既知向きの合成マスクを実カメラ経路に流す
  診断スイッチ。
- **uDebug**: 0=最終合成 / 1=クラスマスク(色分け) / 2=量子化トーン面(切り口・影なし) /
  3=リボンのみ(髪) / 4=標本(パレット見本+切り口/落ち影の段階見本+リボン単体見本)。

## 5. 進め方(フェーズ制・厳守)

- Phase 1: 不変量表の復唱+実装上の懸念点の列挙(コードを書かない)
- Phase 2: 設計 — 候補アーキテクチャ2〜3案の比較(却下理由付き)、パス構成図
  (入出力・解像度・フォーマット・更新頻度)、フィルレート/リボン数概算、リスク(コードを書かない)
- Phase 3: 実装 — 骨格(カメラ→cover-fit→素通し→UI→エラー経路)→ 標本(パレット見本・

  承認済み標本のパラメタを無断変更しない。1000行超は論理単位で分割書き込み。

## 7. 制約条件(dsflon/webgl2 リポジトリ規約 — 受入基準を兼ねる)

### 成果物の形
- 単一の自己完結 HTML。外部ライブラリ・ビルド工程・外部アセット禁止
  (例外: 本作の許可 = **MediaPipe tasks-vision と多クラスセルフィーセグメンテーション
  モデルのみ CDN 可**)。
- WebGL2 / GLSL ES 3.00。WebGL1 フォールバック不要。
- ファイル冒頭に HTML コメントで: 作品概要 / 実行方法 / 様式解析の要約 /
  パイプライン図 / 全スライダーの説明 を書くこと。
- README.md の作品リストに GitHub Pages の URL を追記すること。

### カメラ
- getUserMedia は facingMode 指定(user/environment)。モバイルでは切替ボタンを表示。
- <video> は playsinline muted autoplay。ミラーはシェーダの UV 反転で行う。
- 非セキュアコンテキスト / 権限拒否 / カメラ無し の3経路それぞれに、
  専用メッセージと再試行ボタンを持つオーバーレイを表示すること。
- カメラとキャンバスのアスペクト比差は cover-fit(切り取り)で吸収すること。

### UI(既存作品の panel 構造を踏襲)
- 実装前に **`fable5_mosaic.html` と `fable5_gas-head.html`** を読み、カメラ取得・UIパネル・
  エラー表示・PNG保存・モバイル性能レシピの規約を踏襲すること
  (**fable5_papercraft-cam.html は読まない** — 美的品質不十分の未公開作)。
- 全パラメタは単一の state オブジェクトに集約し、スライダー定義は
  [key, ラベル, ヒント, min, max, step] の配列から生成すること。
- DEFAULTS と「RESET LOOK」。「HIDE UI」「SAVE PNG」(preserveDrawingBuffer: true)。
- prefers-reduced-motion 時はアニメーション停止トグルを初期 ON。

### 検証フック(機械検証が依存する。必須)
- window.__artReady: 最初の本描画フレーム完了時に true を立てること。
- ?freeze=1: 時間駆動を停止し決定的な静止フレームを出すこと(fakesource の合成フィギュアも静止)。
- ?prewarm=<秒>: 初回描画前に指定秒ぶんを固定 dt で決定的に早送りして開始すること
  (ema 類の収束済み状態を数秒で得る。検証環境は実時間 warm が数分かかる)。
- ?fakesource=1: カメラ・MediaPipe なしで合成フィギュア+合成クラスマスクが全経路を駆動。
- ?fakescale=<f>: 合成フィギュアの拡縮(既定1.0)。?fakeseg=1: 実カメラ経路への合成マスク注入。

### 品質基準
- 静止したカメラの前で画面がチラつかないこと(乱数シードはセル座標由来)。
- デスクトップ 60fps / モバイル 30fps 以上(DPR 上限 2、重いバッファは解像度上限。
  CRAFT §C3: 縮小推論・負荷適応間引き・デリゲート破綻検出・診断チップ)。
- リサイズ・カメラ切替・タブ復帰で壊れないこと。

## 8. 技術注意リスト(遵守すること)

1. GLSL ES 3.0 の予約語を変数名に使わない: coherent, sample, filter, precise,
   restrict, readonly, writeonly, subroutine, input, output, common, partition, active
2. 同一テクスチャを read しながら write しない。feedback/EMA は必ず ping-pong。
3. float テクスチャは EXT_color_buffer_float を確認し、未対応時の代替を用意。
4. MRT のブレンドは全アタッチメント共通。クリアは clearBufferfv を毎アタッチメント。
5. 方向場(etf)は二重角 (cos2θ, sin2θ)。角度の直接 lerp をしない。
6. normalize(ゼロベクトル) は NaN。pow(x,y) は x<0 で未定義。
7. ループは const int MAX + break。
8. 頂点シェーダのテクスチャ参照は textureLod。
9. 乱数は pcg系 hash12 / cell-hash。シードに時間を混ぜない。
10. UNPACK_FLIP_Y_WEBGL は DOM ソースのみ。TypedArray アップロードはシェーダ側で向きを合わせる。
11. gl_PointSize は使わない(リボンはインスタンスクアッド)。canvas は preserveDrawingBuffer: true。
12. UV・位置計算は highp。
13. ブラーは縦横分離。readPixels を毎フレーム呼ばない。
14. **座標規約(CRAFT §C1)**: マスクのサンプルは Y 反転・cover-fit・mirror を背景と完全同一の
    変換で。動作実績のある公開作(fable5_mosaic / fable5_gas-head / overflowing_aura_v2)と
    厳密突合すること。
15. ema・しきい値は dt スケールでフレームレート非依存に。

## 9. 検証環境

- フェイクカメラ+スクリーンショットは `loop/runner/`(verify_runtime.mjs)を使う。
  ローカルサーバは python3 -m http.server 8888。URL 形式: `?fakesource=1&freeze=1`。
- スクリーンショットは (a) 最終合成(`?prewarm=12`) (b) uDebug 主要モード(クラスマスク・
  トーン面・リボン) (c) 標本 の3枚以上。pageerror が出ていないことを毎回確認する。
- **時間軸の不変量(id 5)があるため `--motion` は必須**。ema 蓄積があるため `--longrun` も回す。
- **検知もの(CRAFT §C)**: `?fakescale=2` と `?fakescale=0.5` の両端でも final+`--longrun` を
  回すこと(実機バグはスケール依存)。`?fakeseg=1` 診断スイッチを実装・動作確認すること。
  モバイル性能レシピ(§C3)を踏襲すること。
- **反復中のスクショは小画面(480×300 程度)**。報告用の一式のみフルサイズ。
- 検証できない項目(実カメラの見え・実機推論速度・実機スケール)は「未検証」と明記し、
  確認すべき点を列挙すること。
