# 依頼: WebGL2 リアルタイム映像作品「うねり」の新規制作

## 1. 作りたいもの

依頼者が10代の頃に繰り返し見た悪夢の再現。カメラのみ(マイク不使用 — 夢の中では
**声も出せない**ので、意図的に音声を取らない)。

**大きく複雑なうねりの中に身が置かれ、視界はそのうねりのみ。** 強い重力のような拘束が
あり身動きは取れない。痛みはないが、身体はよじれ、引き裂かれてうねりに呑まれていく。
**意識だけがはっきりしている** — 画面の中で、顔のまわりの小さな一角だけが現在のまま
明瞭に残り続ける。強い目眩に近い感覚と浮遊感。もがくほど、うねりは締まる。
暗い空間。うねりの色成分は赤なのか茶色なのか。あれがうねりだったのかも、定かではない。

- ファイル名: `opus5_uneri.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)

この様式の本質は「**意識だけが明瞭なまま、身体がうねりに呑まれる**」である。
ホラー演出(出血・驚かせ・グロテスク)で近似してはならない — この悪夢に痛みは無く、
恐怖の種類は「抜け出したいのに抜け出せない」倦怠と不快である(制作規約 失敗モード#1)。

### 体験の記述から取り出した構造(依頼者の言語化 2026-08-01)

| 記述 | 構造 |
|---|---|
| 視界はそのうねりのみ | **実写の部屋は画面に残らない**。カメラ映像は「うねりに呑まれる素材」としてのみ生き残る。※これは「実世界を投影する」という既往の是正(kiin-seido)からの意図的な離反である — この夢に世界は無い |
| 意識ははっきりしている | 顔のまわりの小さな窓だけが、現在のカメラ映像のまま明瞭に残る。うねりはそこだけ奪えない |
| 身体はよじれ引き裂かれる(痛みはない) | 窓の外の身体はうねりの流れに常時注入され、引き伸ばされ、千切れてリボン状に流されていく。ゆっくり、なめらかに、出血や飛散なしに |
| 強い重力・身動きが取れない・もがいても抜け出せない | **もがくと締まる**。動き(運動場)が大きいほど引きが強まり、意識の窓が狭まる。静止しても緩むだけで、決して解放されない |
| 強い目眩と浮遊感 | 画面全体がごくゆっくり回転・呼吸し(ベクション)、意識の窓は逆位相で漂う |
| 暗い空間、色は赤か茶 | 深い闇の中の酸化した赤茶(オックスブラッド〜錆〜黄土)。彩度は低く、血の赤にしない |
| あれはうねりだったかも定かではない | 質感を特定しない。液体とも布とも岩とも読めない、多スケールの不定形 |

### 報告されている現象との対応(2026-08-01 に調査済み)

熱夢(Schredl: 空間の歪み・巨大な不定形・否定的感情価)、睡眠麻痺の圧迫型+前庭運動型
幻覚(Cheyne: 意識明瞭・不動・無声・浮遊・回転・身体のねじれ)、Isakower 現象
(影のような不定形の塊が迫り膨れ上がる・思春期・発熱時)。個人の悪夢でありながら
広く共有された型であり、「見た人の悪夢」になり得る。

### 近接作品との差別化

| 既存作 | 何が違うか |
|---|---|
| `fable5_gas-head` / `blue-dissolve` | あれは人物が**気体になって上昇**する(解放の方向)。本作は**呑まれて引き込まれる**(拘束の方向)。上昇なし |
| `suibokuga_sakana` | あれは Stable Fluids を**ポインタで操作**する。本作の流れは操作できない — 操作できないことが主題 |
| `opus5_kiin-seido` | あれは実世界を投影し人物の周囲だけ抽象。本作は世界ごと呑む(意図的な離反、上記) |
| リポジトリ全作品 | **動くほど報われない**どころか、動くほど悪化する。「もがくと締まる」の反転はリポジトリ未踏 |

## 2. 様式の参照 — 視覚的不変量表

| # | 視覚的不変量(実装可能な構造の言葉で) | 担当軸 | 実装原理の指定 | 外した場合の影響 |
|---|---|---|---|---|
| 1 | 視界はうねりのみ: 画面の全域が、画面より遥かに大きい多スケールの回転流で満ちる。部屋も地平も無い。うねりは自己完結して動き続ける(無人でも成立) | 場 | フィードバック移流(semi-Lagrangian の逆追跡)。流れは巨大渦(中心は画面外を彷徨う)+中間コイル+微細剪断の3スケール合成、微細側は curl noise | 部屋が見えた瞬間「部屋にエフェクトが掛かった映像」になり、夢の中に居ない |
| 2 | 意識の窓: 顔のまわりの小さな一角だけ、現在のカメラ映像が明瞭に残る。窓は漂う(浮遊感)が消えない | 図地 | 頭部推定(セグメンタのマスクの上端質量の重心。JS のアップロードループで行毎和から算出、cover-fit と鏡像を逆変換)を中心に、柔らかい縁の窓で現在フレームを合成 | 全部呑まれると意識まで失われ、「意識だけ明瞭」という体験の核が消える |
| 3 | 身体は呑まれる: マスク内の実写が毎フレームうねりの場へ注入され、移流で引き伸ばされ、千切れる。痛みの記号(血・飛散・轟音)は使わない | 質感 | 注入 = マスク×現在フレーム(悪夢の配色へグレード)×dt。千切れ = 微細剪断の強度+移流の複数タップにノイズ偏差 | 注入が無いと自分が呑まれず、ただの抽象背景になる |
| 4 | もがくと締まる: 運動量(重心速度の EMA +運動場)が大きいほど、引きが強まり意識の窓が狭まる。静止で緩む。ゼロにはならない | 時間 | struggle メーター(JS: 重心速度の EMA)→ uPull と窓半径に接続。運動場(マスク BA)は局所の乱流を上げる | 「抜け出したいのに抜け出せない」が絵に出ず、動きが報われる通常作品になる |
| 5 | 目眩と浮遊: 画面全体がごくゆっくり回転・呼吸する。窓は逆位相で漂う。reduced-motion では停止 | 時間 | 合成パスでうねりのサンプリング座標を微回転+微拡縮(art clock 由来、freeze で停止) | 目眩が無いと「観察している」絵になり、「中に居る」体験にならない |
| 6 | 酸化した赤茶の闇: 地は近黒、うねりに宿る色はオックスブラッド〜錆〜黄土のみ。血の赤(純赤・高彩度)を出さない。周縁は深く沈む | 色 | 注入時に実写をトーンマップ(輝度保持+錆側へ)。スライダーで赤↔茶。強いビネット | 高彩度の赤はゴアに、明るい画面は悪夢でなくスクリーンセーバーになる |

優先度(外すとその様式に見えなくなる順): 1 > 2 > 3 > 4 > 6 > 5

## 3. 入力映像から生き残らせる信号

- 生き残る: **人物の像**(ただし注入素材として。窓の中だけ現在のまま)、
  人物のシルエットと運動量。
- 消えるもの: **背景の実写**(部屋は一切残らない — §2-1 の意図的な離反)。
- 音声: 使わない。マイク許可も要求しない(声も出せない夢のため)。
- 受入基準: 意識の窓の中で人物の顔が判読できること。窓の外でも、呑まれていく像が
  「自分だったもの」と分かる程度の連続性があること。

## 4. 技術方針

派生元エンジン: `opus5_koe.html`(ImageSegmenter のモバイル手順・カメラと UI と
検証フック・fakesource の合成人型・マスクの重心計算)。音声系は全て除去する。

実装原理は次の技法語彙で固定する: **ping-pong**(うねりのフィードバック移流と
マスク場)、**EMA**(マスク・運動場・struggle メーター)、**curl noise**(微細剪断と
乱流)、**SDF**(fakesource の合成人型)。移流は semi-Lagrangian の逆追跡
(`suibokuga_sakana` の Stable Fluids と同族だが、圧力解法は使わない — 非圧縮性は
この夢に不要で、発散が「呑み込み」を作る)。

- MediaPipe は **ImageSegmenter のみ**。推論は 288px 縮小コピー、33〜250ms の適応
  カデンス、GPU→CPU デリゲートのフォールバック。マスクが取れなくても(拒否・失敗)
  うねりだけで絵が成立すること。
- 頭部推定: セグマスクのアップロードループで行毎の質量和と x 重み和を蓄積し、
  マスク上端から質量の 18% までの行の重心を頭部とする。cover-fit と鏡像の逆変換は
  `opus5_koe.html` の重心変換(2026-07-29)を踏襲。
- uDebug の割り当て: 0=最終 / 1=マスクと運動 / 2=流れの向き(色相=方位) /
  3=うねりの生画 / 4=注入と窓 / 5=配色標本。
- モバイル: うねりの解像度を落とす(長辺 ≤896)。ソフトウェアレンダラはさらに小さく。

## 6. 制約条件(リポジトリ規約)

- **単一の自己完結** HTML(WebGL2 / GLSL ES 3.00)。外部依存は MediaPipe tasks-vision と
  そのモデルのみ(許可リスト内)。
- **カメラ**: `getUserMedia({ facingMode })`、`<video playsinline muted autoplay>`、
  モバイルで前面/背面の切替。エラー3経路(SECURE CONTEXT / PERMISSION DENIED /
  NO CAMERA)に専用オーバーレイと再試行。
- **品質基準**: 60fps 目標。DPR は 2 で上限。`preserveDrawingBuffer: true`。
  規約ID を踏襲。`prefers-reduced-motion` 対応(ゆらぎ停止が初期 ON)。
- **検証フック**: `window.__artReady`、`?freeze=1`、`?prewarm=<秒>`、`?fakesource=1`、
  `?fakeseg=1`、`?fakescale=<f>`。

## 7. 技術注意リスト(既知の地雷)

1. GLSL の**予約語**を変数名にしない(`sample` `filter` `input` `output` `patch` ほか)。
2. 場と状態は必ず **ping-pong**(フィードバック移流は特に)。
3. GLSL のテンプレートリテラル内に**バッククォートを書かない**。
4. グレイン・ノイズのシードに `uTime` を混ぜない(freeze でチラつく)。
5. フィードバック移流は**必ず減衰の床と注入の上限**を持たせ、`--longrun` で
   平均輝度の発散/暗転を数値で確認する。dt=0 のとき逆追跡が恒等(back=uv)に
   なることも確認(freeze の決定性)。
6. 移流のフィードバックはリニアサンプリングで**にじんで灰色に平均化**していく。
   注入と、彩度の床(うねり自身の色)で対抗する。
7. `curl noise は正規化してスケールを制御する`(kiin-seido で未正規化 curlN が
   200px の変位を生んだ前例)。
8. 頭部推定は fakesource でも駆動できるように、合成人型の頭位置を det に出すこと。
   実カメラ経路の cover-fit/鏡像の逆変換を忘れると窓が顔から外れる(koe の後光の前例)。

## 8. 進め方(フェーズ制・厳守)

- Phase 1: 不変量表の復唱+実装上の懸念点の列挙(コードを書かない)
- Phase 2: 設計 — パス構成図(入出力・解像度・フォーマット・更新頻度)、
  メモリとフィルレート概算、リスク
- Phase 3: 実装 — 骨格(カメラ→cover-fit→素通し→UI→エラー経路)→ 標本(流れの
  デバッグ表示と注入・窓の標本)→ パス追加
- Phase 4: 検証 — 検証手順+自己批評ルーブリック。未検証のまま完成と報告しない

## 9. 検証環境と手順

- ローカル: `python3 -m http.server 8899` → `http://localhost:8899/opus5_uneri.html`
- **フェイクカメラ** + `?fakesource=1` で全パイプラインをオフライン駆動。
  **スクリーンショット**を1変更ごとに撮って自分の目で見る(CRAFT §D1)。
- 決定的検証: `node loop/runner/verify_static.mjs` と
  `node loop/runner/verify_runtime.mjs <url>?fakesource=1&freeze=1 --motion --longrun`
- 実機スケール: `?fakescale=0.5` と `?fakescale=1.9` の両端。

## 10. 自己批評ルーブリック

各不変量を 1〜5 で自己採点し、4 未満なら原因(構造の欠落か、パラメタか)を書く。加えて:

- **ゲシュタルトテスト**: 先入観なしに「この画像は何に見えるか」。「部屋にエフェクト」
  「スクリーンセーバー」「溶岩/血しぶき」に見えたら不成立。
- **拘束テスト**: 合成人型が動く区間と静止する区間で、引きと窓が**逆方向に**
  動くか(動くと締まり、静止で緩む)。
- **意識テスト**: どの瞬間のスクリーンショットでも、窓の中の顔が判読できるか。
- **巨大テスト**: 最大渦が画面より大きく感じるか(渦の中心が画面内に見えたら小さい)。
- 無人のときの絵が成立しているか(うねりだけで持つか)。
