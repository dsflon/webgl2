# 依頼: WebGL2 リアルタイム作品「線香花火」の新規制作

## 1. 作りたいもの

一本の線香花火。先端に橙〜黄白の火球(牡丹)がぶら下がり、そこから無数の火花が
四方へ放射し、飛翔の途中で分岐して松葉になる。牡丹→松葉→柳/散り菊→散り の
4位相を時間でたどり、最後に火球がポトリと落ちて消え、間をおいてまた点火する。
夜闇に火花だけが白熱し、動いた光は短い残光の尾を引く。指(ポインタ/ドラッグ)で
火球を「持つ位置」を操り、**静かに持つほど松葉が長持ち、素早く動かす/振ると
火球が乱れて早く散る**。無操作でも一本が自然に燃え尽き、また点火するループが主役。

- ファイル名: `fable5_senkohanabi.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)
- **入力: ポインタ/タッチ主 + 端末傾き(副・なくても成立)**。カメラ・マイクは使わない。
  `<meta name="art-input" content="none">` を宣言する(カメラ規約の免除プロファイル。
  検証器対応済み)。

この様式の本質は「**火花の分岐と一瞬の儚さ**」である。これを後処理(ぼかし・
グロー・オーバーレイ)で近似してはならない(制作規約 失敗モード#1)。火花は
GPUパーティクルの分岐する軌跡として、残光はフィードバック蓄積として実装すること。

  寿命とともに橙・赤へ冷える。火球の芯が最輝。

## 3. 入力から生き残らせる信号

- 生き残る: **ポインタ位置**→火球の持ち位置/火花原点 / **ポインタ移動速度**→静けさ=松葉長持ち・
  乱暴=早く散る / **時間**→4位相と無操作時の点火ループ / **端末傾き**(副・なくても成立)→火球の
  垂れと火花の流れ(ポインタへフォールバック)。
- 様式側で置き換わる: カメラ映像→使用しない(夜闇と火花を完全合成) / 実写の火花→GPUパーティクルの
  分岐軌跡(ストリーク) / 実写の残光→フィードバック蓄積の光の尾。
- 「触らない待機状態が、自然に燃える一本の線香花火として美しく成立すること」は受入基準である。

## 4. 技術方針(この指定に従うこと)

実装原理は次の技法語彙で固定する: **ping-pong / ema / oklab / sdf / hysteresis /
cell-hash / curl noise / edge darkening**。

- **パーティクル(GPU)**: 位置・速度・寿命・世代を float テクスチャに詰め、更新パスで
  ping-pong。EXT_color_buffer_float 未対応時は RGBA8 代替(スケール保持)。発生(spawn)と
  分岐(子の世代+1)を管理し、有界な最大粒数に収める。描画は速度方向に伸ばしたストリーク
  (インスタンス/クアッド)で加算合成。gl_PointSize は使わない。
- **残光**: フィードバック蓄積レイヤ(前フレームを ema 減衰保持=ping-pong)に加算し暗く沈める。
  必ず散逸>加算・上限 clamp(§A5)。
- **色**: 寿命→oklab で黄白→橙→赤、火球芯は sdf、周縁 edge darkening。乱数は hash12/cell-hash
  (時間を混ぜない)。curl noise で火花の蛇行。
- **外部依存なし**(ML モデル不使用)。
- **?fakesource=1(合成入力)**: 実ポインタ/傾きを使わず、**決定的スクリプトで火球を
  ゆっくり動かしつつ4位相を一定周期で回す**(発生→分岐→散り→再点火)。時間軸検証(--motion)の
  前提として、fakesource では常に火花が動くこと。
- **傾き(DeviceOrientation)**: 副入力。iOS は要許可(タップで `requestPermission`)。センサ無し/
  未許可/PC ではポインタのみで完全に成立させる。傾きの有無で作品が死なないこと。
- **uDebug モード割り当て**: 0=最終合成 / 1=パーティクル生(残光なし・素の火花) /
  2=残光蓄積レイヤ / 3=速度/寿命の可視化 / 4=標本(火の色温度グラデーション見本)。

- 全パラメタは単一の state オブジェクトに集約し、スライダー定義は
  [key, ラベル, ヒント, min, max, step] の配列から生成すること。

- window.__artReady: 最初の本描画フレーム完了時に true を立てること。

- ?fakesource=1: 実ポインタ/傾きなしで、決定的スクリプトで火球移動+4位相を回し全パイプライン
  (発生→分岐→残光→散り→再点火)を駆動できること。

### 品質基準
- 入力の無い静止状態でも自然に燃え、チラつかないこと(乱数シードは粒/セル座標由来)。
- デスクトップ 60fps / モバイル 30fps 以上(DPR 上限 2、粒数と残光解像度に上限)。
- リサイズ・タブ復帰で壊れないこと(FBO の再確保を正しく行う)。

## 8. 技術注意リスト(遵守すること)

1. GLSL ES 3.0 の予約語を変数名に使わない: coherent, sample, filter, precise,
   restrict, readonly, writeonly, subroutine, input, output, common, partition, active
2. 同一テクスチャを read しながら write しない。feedback/粒状態/EMA は必ず ping-pong。
3. float テクスチャは EXT_color_buffer_float を確認し、未対応時の代替を用意。
4. MRT のブレンドは全アタッチメント共通。クリアは clearBufferfv を毎アタッチメント。
5. 方向場は二重角 (cos2θ, sin2θ)。角度の直接 lerp をしない。
6. normalize(ゼロベクトル) は NaN。pow(x,y) は x<0 で未定義。
7. ループは const int MAX + break。
8. 頂点シェーダのテクスチャ参照は textureLod。
9. 乱数は pcg系 hash12 / cell-hash。シードに時間を混ぜない。
10. UNPACK_FLIP_Y_WEBGL は DOM ソースのみ。TypedArray アップロードはシェーダ側で向きを合わせる。
11. gl_PointSize は使わない(火花はストリーク)。canvas は preserveDrawingBuffer: true。
12. UV・位置計算は highp。粒の位置・速度も highp。
13. ブラー/加算は縦横分離 or 直接加算。readPixels を毎フレーム呼ばない。
14. パーティクル spawn/分岐はフレームレート非依存(dt スケール)。速度に上限、寿命は dt で減算。
    残光の減衰も dt スケールし、フレームレートで尾の長さが変わらないように。

## 9. 検証環境

- フェイク入力+スクリーンショットは `loop/runner/`(verify_runtime.mjs)を使う。
  ローカルサーバは python3 -m http.server 8888。カメラ不使用ゆえフェイクカメラ機構は
  発火しないが、URL 形式は共通: `?fakesource=1&freeze=1`。
- スクリーンショットは (a) 最終合成(非 freeze で 8〜15 秒 warm、松葉が育った瞬間)
  (b) uDebug の主要モード(粒生・残光蓄積) (c) ?fakesource=1 の標本 の3枚以上。
  pageerror が出ていないことを毎回確認する。
- **蓄積系(残光 feedback で絵が育つ)につき `verify_runtime --longrun` で長時間安定
  (whiteout/発散なし)を確認すること**。時間軸の不変量(id 2/3/5)があるため `--motion` も必須。
- 本作は外部検知を使わないため実機乖離(CRAFT §C)は**該当なし**。ポインタ作品として
  完全オフライン検証可(V-A)。**傾き(DeviceOrientation)は実機依存で headless 検証不可**=
  「傾き対応は実機目視の領分」を未検証事項として明記すること。実ポインタ/タッチの操作感も同様。
- 検証できない項目は「未検証」と明記し、確認すべき点を列挙すること。
