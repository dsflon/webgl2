# 依頼: WebGL2 リアルタイム映像作品「黄金地モザイク」の新規制作

## 1. 作りたいもの

Web カメラに映る人物が、ビザンチンの黄金地モザイクになる。人物は不揃いの色ガラス片
(テッセラ)のタイル画に変換され、背景は一面の黄金地(金のテッセラ)。タイル間には暗い
目地(グラウト)が走り、金のタイルは身体の動きに応じて反射がきらめく。重厚で神話的な、
教会モザイクのような佇まい。

- ファイル名: `fable5_mosaic.html`
- リポジトリ: `dsflon/webgl2`(単一HTML作品集。GitHub Pages で配信)

この様式の本質は「連続画像ではなく、暗い目地で区切られた離散したテッセラの集合」である。
これを後処理(ぼかし・色調整・グリッド線オーバーレイ)で近似してはならない
(制作規約 失敗モード#1)。タイルは実体として分割され、各片が代表色・面角・ベベルを持つこと。

## 2. 様式の参照 — 視覚的不変量表(ゲート1通過済み)

参照: ビザンチン黄金モザイク(ラヴェンナ/ハギア・ソフィア — 黒目地で区切られた不揃いの
ガラス・石片で像を作り、背景は一面の金箔テッセラ) / 金地(各片が微妙に異なる明度・色温度・
傾きを持ち光を反射) / テッセラの物質感(暗い目地とタイルのベベル状の立体感)。

## 3. 入力映像から生き残らせる信号

- 生き残る: 人物の位置・シルエット(セグメンテーションマスク) / 人物内の明暗・色
  (各タイルの代表色の元) / 身体の動き(金の反射の揺らめきを駆動)
- 様式側で置き換わる: 連続した写真ピクセル → 離散した不揃いのタイル / 背景 → 一面の黄金地 /
  肌・服の連続階調 → 限られた色数の面(テッセラ色)
- 被写体(特に人物)が判読できることは受入基準である。

## 4. 技術方針(この指定に従うこと)

実装原理は次の技法語彙で固定する: voronoi / oklab / 分位点(quantile) / cell-hash /
sdf / edge darkening / ema / ping-pong。

- **タイル分割**: 画面を voronoi セルに分割する。セル中心は cell-hash による不規則配置
  (ジッタ付き格子で可)。各画素は最近セル中心に属し、セル距離場(最近と次近セル中心の距離差)で
  目地とベベルを作る。**セル配置のシードに時間を混ぜない**(静止時チラつき禁止)。
- **人物のタイル色**: 人物マスク内は、各セルの代表色(セル中心付近のカメラ色)を oklab へ変換し、
  明度・色相を分位点/段階量子化して色数を絞る。セル内は単色で塗る。
- **黄金地**: 人物マスク外は金のパレットで塗る。各タイルの金は cell-hash で明度・色温度・
  面角をばらす。
- **反射のきらめき(時間)**: タイルごとの擬似面法線を cell-hash で与え、固定ライトへの
  スペキュラを出す。運動場(直前フレームとの輝度差、ema 平滑化)でハイライト方向/強度を
  揺らす。人物の金縁・装飾も同様に反射。
- **人物検知**: MediaPipe ImageSegmenter で人物マスクを取得(実装は overflowing_aura_4taigyo_v2 /
  fable5_gas-head と同じ座標規約 — Y反転・cover-fit・mirror)。**モバイル対応レシピ**
  (Pose 不使用・288px 縮小推論・負荷適応間引き・GPU破綻時CPU自動切替・presence=カバレッジ・
  診断チップ)を踏襲すること。マスクは EMA 平滑化し ping-pong FBO で運動場も保持。
- **?fakesource=1**: MediaPipe 不使用で、合成の動く人物マスク+シーンを生成し全パイプラインを
  駆動する。合成人物は緩やかに動く(反射の揺らめきの検証に必要)。
- **?fakescale=<f>**: fakesource の合成人物を係数 f で拡大縮小できること(実機スケール乖離の
  検査用。既定 1.0)。
- **uDebug**: 0=最終 / 1=人物マスク / 2=voronoi セル(目地) / 3=運動場 / 4=金/色パレット標本。

## 5. 進め方(フェーズ制・厳守)

## 6. UI 仕様

### スライダー(「写真らしさ ↔ 様式の強さ」の軸で 6〜10 本)

| key | ラベル | 範囲(初期値) | 作用 |
|---|---|---|---|
| tileScale | タイルの大きさ | 0–1 (0.5) | voronoi セルの密度(小さいほど細かいテッセラ) |
| grout | 目地の太さ | 0–1 (0.45) | タイル間の暗い隙間の幅と暗さ(edge darkening) |
| bevel | 立体感 | 0–1 (0.5) | タイルのベベル陰影の強さ(sdf セル距離場) |
| colors | 色数 | 0–1 (0.4) | 人物タイルの oklab 分位点量子化の段階数(小さいほど色が少ない) |
| gold | 金の強さ | 0–1 (0.6) | 黄金地の彩度・明度・金らしさ |
| shimmer | きらめき | 0–1 (0.55) | 動きに対する金の反射(スペキュラ)の揺らめき量 |
| figure | 人物の分離 | 0–1 (0.5) | 人物と金地の明度コントラスト・輪郭目地の強調(図地判読) |

  (標本=金パレット見本で承認を得ること)

## 7. 制約条件(dsflon/webgl2 リポジトリ規約 — 受入基準を兼ねる)

### 成果物の形
- 単一の自己完結 HTML。外部ライブラリ・ビルド工程・外部アセット禁止
  (例外: ML モデルのみ CDN 可。本作の許可: MediaPipe tasks-vision(ImageSegmenter))。
- WebGL2 / GLSL ES 3.00。WebGL1 フォールバック不要。
- ファイル冒頭に HTML コメントで: 作品概要 / 実行方法 / 様式解析の要約 /
  パイプライン図 / 全スライダーの説明 を書くこと。
- README.md の作品リストに GitHub Pages の URL を追記すること。

### カメラ
- getUserMedia は facingMode 指定(user/environment)。モバイルでは切替ボタンを表示。
- <video> は playsinline muted autoplay。ミラーはシェーダの UV 反転で行う。
- 非セキュアコンテキスト / 権限拒否 / カメラ無し の3経路それぞれに、
  専用メッセージと再試行ボタンを持つオーバーレイを表示すること。
- カメラとキャンバスのアスペクト比差は cover-fit(切り取り)で吸収すること。

### UI(既存作品の panel 構造を踏襲)
- 実装前に `fable5_gas-head.html` を読み、カメラ取得・UIパネル(固定✕)・エラー表示・
  検知系(モバイル対応)・PNG保存の規約を踏襲すること。
- 全パラメタは単一の state オブジェクトに集約し、スライダー定義は
  [key, ラベル, ヒント, min, max, step] の配列から生成すること。
- DEFAULTS と「RESET LOOK」。「HIDE UI」「SAVE PNG」(preserveDrawingBuffer: true)。
- prefers-reduced-motion 時はアニメーション停止トグルを初期 ON。

### 検証フック(機械検証が依存する。必須)
- window.__artReady: 最初の本描画フレーム完了時に true を立てること。
- ?freeze=1: 時間駆動アニメーション(反射の揺らめき等)を停止し決定的な静止フレームを出すこと。
- ?fakesource=1: 合成入力で様式パイプラインを駆動できること。
- ?fakescale=<f>: fakesource の合成人物を係数 f で拡大縮小できること(実機スケール乖離の検査用。既定 1.0)。

### 品質基準
- 静止したカメラの前で画面がチラつかないこと(乱数シード=セル座標由来。時間を混ぜない)。
- デスクトップ 60fps / モバイル 30fps 以上(DPR 上限 2、重いバッファは解像度上限)。
- リサイズ・カメラ切替・タブ復帰で壊れないこと。
- 大きく/小さく写った人物でも破綻しないこと(?fakescale 両端で確認)。

## 8. 技術注意リスト(遵守すること)

1. GLSL ES 3.0 の予約語を変数名に使わない: coherent, sample, filter, precise,
   restrict, readonly, writeonly, subroutine, input, output, common, partition, active
2. 同一テクスチャを read しながら write しない。feedback/拡散/EMA は必ず ping-pong。
3. float テクスチャは EXT_color_buffer_float を確認し、未対応時の代替を用意。
4. MRT のブレンドは全アタッチメント共通。クリアは clearBufferfv を毎アタッチメント。
5. 方向場は二重角 (cos2θ, sin2θ)。角度の直接 lerp をしない。
6. normalize(ゼロベクトル) は NaN。pow(x,y) は x<0 で未定義。
7. ループは const int MAX + break(voronoi の近傍探索も固定回数で)。
8. 頂点シェーダのテクスチャ参照は textureLod。
9. 乱数は pcg系 hash12。シードに時間を混ぜない(セル配置・面角・グレインすべて)。
10. UNPACK_FLIP_Y_WEBGL は DOM ソースのみ。TypedArray アップロード(seg マスク)はシェーダ側で向きを合わせる(Y反転)。
11. gl_PointSize は使用時必ず書く。canvas は preserveDrawingBuffer: true。
12. UV・位置計算は highp。
13. ブラーは縦横分離。readPixels を毎フレーム呼ばない。
14. oklab 変換は正しい行列で(sRGB→linear→LMS→oklab)。量子化は oklab の L/色相で行い sRGB へ戻す。

## 9. 検証環境

- フェイクカメラ+スクリーンショットは `loop/runner/`(testscene.mjs / verify_runtime.mjs)
  を使う。ローカルサーバは python3 -m http.server 8888。
- スクリーンショットは (a) 最終合成 (b) uDebug の主要モード(セル/マスク) (c) ?fakesource=1 の標本
  の3枚以上。pageerror が出ていないことを毎回確認する。
- 実機乖離の予防(`loop/CRAFT.md` §C を実装前に読むこと): 座標規約(Y反転・cover-fit・mirror)は
  動作実績のある実装(overflowing_aura_4taigyo_v2 / fable5_gas-head)と厳密突合し、
  `?fakescale=<f>` の診断スイッチを実装すること。モバイル性能レシピ(CRAFT §C3)を踏襲すること。
- 検証できない項目(実機カメラ・実機GPU 依存)は「未検証」と明記し、確認すべき点を列挙すること。

## 10. 自己批評ルーブリック(スクリーンショット取得後、報告の前に実行)

1. §2 の不変量表の各行を画像と照合し 5 段階で自己採点(存在しなければ1点+理由)。
2. **第一印象**(brief を伏せて「この画像は何に見えるか」)を言語化し、テーマ(黄金モザイク)と
   一致するか確認する。星雲/ステンドグラス/ただの色ブロック等に見えるなら様式不成立。
3. 「縮小して見た印象」(様式の成立)と「等倍で見た印象」(タイル・目地・ベベルの正しさ・
   誤魔化しの有無)を分ける。
4. 最低点の2項目に、制作規約 §10 翻訳表の語彙で修正案(数値の増減方向まで)を出す。
5. 全項目4点以上まで最大3周まで自走してよい。採点は甘くしない。

## 11. 報告様式
