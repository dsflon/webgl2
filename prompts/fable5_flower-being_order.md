# 発注書 — fable5_flower-being.html（チームラボ風・花に溶ける人／動きに反応）

## ゴール（ユーザー確定要件）
Web カメラの人物が、**極彩色の発光する花びらに溶けて**いき、黒の空間に舞う無数の花の中へ還る。**人物の動きが風**になり、花びらが舞い上がり渦巻く。チームラボ「Flowers Bloom」系の没入空間の質感を、単一ファイル WebGL2 で。人物が生映像の切り抜きに見えず、シーン（花・光・闇）に自然に溶け込むこと。

## 土台（重要）: fable5_gas-head.html を複製して改造する
`fable5_gas-head.html` は**モバイル対応・検証済み**のエンジン。これを土台にし、「灰色の煙表現」を「花・花びら表現」に差し替える。**必ず流用するもの（作り直さない）**:
- 検知: ImageSegmenter のみ（Pose なし）、288px 縮小入力、負荷適応間引き(33〜250ms)、GPU 破綻時 CPU 自動切替、presence をマスクのカバレッジで判定、ステータスチップに推論ms・デリゲート表示。**そのまま流用**。
- 実カメラ座標一致: seg マスクの Y 反転（`1.0 - suv.y`）、cover-fit(uSegScale)、mirror。**そのまま流用**。
- 半解像度 Stable Fluids（移流+Jacobi 圧力+vorticity+curl noise）、ping-pong FBO、RGBA16F＋RGBA8 フォールバック。
- 検証フック: `?fakesource=1`（合成の動く人物＋シーンで全駆動）、`?freeze=1`（dt=0 決定的）、`window.__artReady`、FAKE でも startCamera()、カメラ3エラー経路（英語文言そのまま: SECURE CONTEXT REQUIRED / PERMISSION DENIED[retry] / NO CAMERA FOUND）、`<video playsinline muted autoplay>`、canvas id="gl"、preserveDrawingBuffer:true、固定✕UI(.panel/.panel-body/#closePanel/#togglePanel、モバイル既定折りたたみ)、日本語スライダー、#debugView、#readout、`?fakeseg=1` 診断。
- verify_static / verify_runtime を通す構造。

## 花・花びら表現への差し替え（ここが新規）
1. **背景 = 黒**（チームラボ）。生カメラ背景は使わない。黒地に、うっすら点在する環境花（全画面に低密度で咲く花）＋人物由来の濃い花。床/空間の奥行きは彩度と明度で。
2. **密度場を「花」として描く**（灰色の煙をやめる）:
   - 密度→**極彩色パレット**でマッピング。単色でなく、位置ノイズで**複数の花色が混ざる**（マゼンタ/薔薇/紫/シアン/黄金/白）。彩度高め・発光（加算/スクリーン）＋ブルームで、参照のように光る花に。
   - **花びらの粒状化**: 煙の fbm ムラではなく、**花・花びららしい離散的な塊**にする。voronoi/セル状ノイズや「花スタンプ」（丸い花弁クラスタ、中心が明るい）で密度を花の集合に見せる。舞い散る個々の花びらも表現（点在する小さな明るい弁）。のっぺりフォグにしない。
   - 咲く→漂う→散る のライフ感（時間とともに開花し、流れて薄れる）。
3. **人物が花びらに溶ける**:
   - 人物マスク領域を濃い開花の源にし、buoyancy＋風で花びらが体から**流れ出して周囲の花畑へ**。体はうっすら人型に花が密集して見える（灰色ガスではなく極彩色の花の塊）。
   - 人物の生映像は出さない。マスク下は暗く（チームラボの人＝暗いシルエット）。溶けた花びらが体の内外を跨いで流れ、切り抜き縁を消す。前作の「無彩化の縁」相当で色付き縁を防ぐ。
4. **動きに反応（風）**: フレーム差分/マスク運動場（gas-head の mask BA チャンネルに既にある flow）を**強めの外力**として速度場へ。人が動くと花びらが舞い上がり渦巻く。動きが大きいほど風強く。静止時は穏やかに漂う。
5. **配色・仕上げ**: 黒背景に発光する極彩色。強すぎる白飛びは避けつつ（花芯だけ明るく）、全体は彩度で魅せる。フィルムグレイン控えめ。ブルームは花の発光感の要なので効かせる（ただしモバイル負荷に注意）。
6. **debug**: 0=最終 / 1=マスク / 2=密度(花密度) / 3=速度場(風) / 4=パレット標本 等。

## モバイル性能（必須）
- gas-head のモバイル最適化検知をそのまま維持。加えて描画負荷を gas-head と同等以内に抑える（フィールド≤512、ブルームは2段まで、パーティクルを別途大量に足すなら点スプライトで数を端末適応。まずはフルード密度＋花シェーダで軽く実現し、重ければ数を絞る）。
- 過度に重くしない。参照の"没入感"は色・発光・流れで出す。
