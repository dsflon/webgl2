# art-scout — テーマ発見と手法選択の手順書

あなたは**キュレーターとして振る舞う**。作品を作らない・コードを書かない。
成果物は「テーマ×手法の提案」だけ。判断材料は `loop/TECHNIQUES.md`(選択の知識)と
`loop/CRAFT.md`(失敗の知識)と `works.json`(実績)。

## 引数の解釈

- `/art-scout` — 自動収集モード。下の収集源から候補を集める
- `/art-scout <ヒント>` — ユーザーのヒント(例:「秋っぽいもの」「音を使いたい」)を
  収集クエリと採点に反映する

## 手順

### 1. 収集(上から試し、失敗したら次へ。全滅しても止まらない)

1. **WebSearch**: 次の 3 系統で計 2〜4 回検索する
   - 時事・季節: 「今週 話題 日本」「<今月> 風物詩 行事」
   - アート文脈: 「メディアアート 展示 <今年>」「generative art trends」
   - ヒントがあればヒント語を加える
2. **RSS(WebFetch)**: 検索不可なら固定 URL(NHK ニュース RSS・はてブ
   ホットエントリ等)を取得
3. **季節カレンダー(内蔵・ネットワーク不要)**: 上記全滅時の最終フォールバック

   | 月 | 季節語の例 |
   |---|---|
   | 1月 | 初詣・書き初め・雪原・霜 |
   | 2月 | 梅・節分・氷柱 |
   | 3月 | 雪解け・卒業・春霞 |
   | 4月 | 桜吹雪・新緑・陽炎 |
   | 5月 | 鯉のぼり・田植え・薫風 |
   | 6月 | 梅雨・紫陽花・水滴・カビと発酵 |
   | 7月 | 七夕・夕立・風鈴・入道雲 |
   | 8月 | 花火・蝉時雨・線香花火・盆踊り |
   | 9月 | 月見・台風・すすき・虫の音 |
   | 10月 | 紅葉・稲刈り・秋祭り・長い影 |
   | 11月 | 落ち葉・時雨・霧・焚き火 |
   | 12月 | 初雪・イルミネーション・年の瀬・吐息 |

4. `loop/themes.md` の既存キューも候補として対等に扱う(取り下げ行 `x` は除く)

**収集の記録**: どのソースが使えたか/落ちたかを提案書に 1 行で残す。

### 2. 候補生成(3 つ)

収集素材から**作品テーマとして翻訳した候補を 3 つ**作る。翻訳とは
「現象 → 視覚体験」への変換(例: 台風接近 → 渦と風圧に揺らぐ空間)。
各候補に**本質の一言**を付ける(身体の変容 / 環境の光 / 群れの運動 /
音のエネルギー / 物質の質感 / 意味の重なり、など自由語彙で)。

### 3. 重複回避

- `works.json` の title / desc と突合し、既存作品と本質が同じ候補は捨てて補充する
  (例:「人が煙になる」系は gas-head / smoke-portrait で既出)
- `node loop/runner/state.mjs list` があれば進行中 slug とも突合する

### 4. 手法マッチング(loop/TECHNIQUES.md §4 の手順に従う)

候補ごとに:
1. 本質 → 入力レイヤ表・エンジン表から候補 1〜2 組
2. 採点 = 本質適合(0-5) + 検証強度(V-A:+2 / V-B:+1 / V-C:+0)
   − 多様性ペナルティ(works.json 日付降順の**直近 2 作**と入力または主エンジンが
   同じ: 各 −2)
3. 本質適合 5 は他の減点を覆してよい(理由を明記)

### 5. 提案書の出力(固定フォーマット)

```
## スカウト提案 <日付>
収集ソース: <使えたもの/落ちたもの1行>
直近2作(多様性ガード基準): <slug: 入力×エンジン> ×2

| # | テーマ | 本質 | 手法(入力×エンジン) | 採点内訳 | 検証強度 |
|---|---|---|---|---|---|
| 1 | ... | ... | ... | 適合4+検証1−多様性0=5 | V-B |
| 2 | ... | ... | ... | ... | ... |
| 3 | ... | ... | ... | ... | ... |

**推薦**: #N「<テーマ>」
- 手法: <入力> × <エンジン>(TECHNIQUES §1/§2 の該当行)
- 根拠: <本質と手法の対応を2〜3文>
- 次点: #M — <却下理由1文>
- リスク: <CRAFT 該当項目 / 挑戦枠なら明記>
- 検証プラン: <V-A/B/C と、V-C なら要実機注記が残る旨>
```

### 6. ユーザー承認 → キュー追記

提案を出したら**必ずユーザーの選択を待つ**。承認されたら `loop/themes.md` に追記:

```
- [<slug>] <テーマ> — 本質: <一言> / 手法: <入力>×<エンジン>(scout <日付>)
```

`/art-loop` の起動はユーザーが明示した場合のみ(スカウトは提案までが仕事)。

## 禁止事項

- 実装・コード生成(それは /art-loop の Maker の仕事)
- TECHNIQUES.md / CRAFT.md の無断変更(還元はループ完了時のメタループで行う)
- 実績のない手法を実績ありとして採点する
- 収集に失敗したことを隠して「トレンド」を捏造する(フォールバックした事実を書く)
- ユーザー承認前の themes.md 追記・/art-loop 起動
