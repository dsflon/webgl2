## A. 体積・場もの(煙・霧・ガス・液体)

### A1. 石膏の塊(飽和場は照明が死ぬ)
- **症状**: 煙/霧が「石膏・粘土・ソフトクリームの塊」に見える。内部が無地で縁だけベベル。
- **根本原因**: 密度場が対象の内部で 1.0 に飽和 → **平坦な場は勾配がゼロ** →
  勾配由来の法線・自己遮蔽・ディテールが全て消える。
- **処方**: 注入をテーパして密度を 0.6〜0.85 帯に**構造を残したまま**保つ
  (mottle をゲインの主成分にする)。ライティングは飽和していない場に対してのみ機能する。
- 出典: gas-head 疑似ボリューム化ラウンド。

### A2. ステッカー輪郭(セグメンテーション輪郭をそのまま使わない)
- **症状**: エフェクトの輪郭が検知マスクの輪郭そのもので、切り抜きシールを貼った見た目。
- **根本原因**: マスクを可視形状として直接使用(alpha フロア等)。
- **処方**: マスクは**発生源/隠蔽にのみ**使い、可視の輪郭は (a) シミュレーションが作る
  (移流・侵食)、(b) 乱流ワープ越しにマスクをサンプル、(c) 縁の帯はノイズゲートで
  ちぎる。隠蔽用マスク(非ワープ)と形状用マスク(ワープ)を分離し、侵食が生映像を
  露出させないこと。
- 出典: gas-head(ワープ侵食+covHide 分離)。

### A3. 照明が微細ディテールを見ないと粘土になる
- **症状**: 内部に模様はあるのに立体感がなく、なめらかな成形物に見える。
- **根本原因**: 法線を低解像度のなめらかな場からだけ計算している。
- **処方**: 法線=「場のなめらかな勾配 + ディテールノイズの有限差分勾配」の合成。
  自己遮蔽は光方向に場を 2 タップ+ノイズを 1 タップ行進。塊の谷間にクレバス AO。
  薄い受光縁にシルバーライニング(控えめに)。
- 出典: gas-head(billow ノイズ込みのライティング)。

### A4. 水面 vs 風(モーションの言語)
- **症状**: 空中の粒子/花びら/煙のはずが「水面のうねり」に見える。
- **根本原因**: 流体場でスクリーン空間の密度を移流させると、うねる膜のモーションになる。
- **処方**: 「空気中を舞う」表現は**各粒が独自の加速度を積分するパーティクル**にする
  (curl ノイズのドリフト+突風+浮遊+抵抗+回転 tumble)。運動場(フレーム差分)は
  移流ではなく**粒への外力**として効かせる。
- 出典: flower-being(流体場→パーティクル転換)。

### A5. 蓄積 whiteout(有界な定常状態にする)
- **症状**: 起動後しばらくして画面全体が白/明灰色に飽和する。実機で顕在化しやすい
  (検知マスクが検証用より大きい)。
- **根本原因**: 注入と散逸が不均衡で密度が際限なく蓄積。露出・加算グローが増幅。
- **処方**: (1) 密度は clamp、注入は既高密度でテーパ。(2) 散逸は「発生源からの
  距離依存」にして源から離れたら速やかに消す(封じ込め)。(3) 濃色の上限を純白の
  手前に(例 0.9)、露出/加算グローは控えめ。(4) **時系列輝度で検証**:
  非 freeze で 3/8/15 秒の全画面・背景域・対象域の平均輝度を測り、背景が時間不変で
  あること(verify_runtime `--longrun` で機械化済み)。
- **限界(重要)**: 既定の合成スケールで安定していても安心しない。過去の whiteout は
  すべて**実機の被写体スケール**(大きく写る・よく動く)で発症し、既定スケールの
  longrun は素通しだった(後検証で実証)。→ C2 の `?fakescale=` を実装し、
  **スケール増し(1.8〜2.2)でも longrun を回す**こと。
- 出典: gas-head 実機 whiteout 修正。

## B. パーティクル・スプライトもの

### B1. 星に見える(丸いボケ玉は光の粒)
- **症状**: 花びら/雪片/葉のつもりが「星・銀河・宇宙」に見える。
- **根本原因**: スプライトが放射状グラデーションの丸い点(+加算グロー)。黒地では
  それは「光」のゲシュタルトになる。
- **処方**: **モチーフの形をスプライトに彫る**(花=深い花弁スキャロップ 0.6〜0.8+
  花弁間の暗いスリット+彩度のある花芯、花びら=先の尖った涙型+葉脈)。回転(tumble)を
  付ける。丸い点の敷き詰めを排除し、大小の判別できる個体+舞い散り種の混成にする。
- 出典: flower-being「星→花」ラウンド。

### B2. 人型の判読性ツールキット(検知もの共通)
被写体が判読できることは受入基準(発注書 §3)。効いた順に:
1. **色相分離**: 被写体=暖色系、環境=寒色系(またはその逆)。同輝度でも図地分離する。
2. **黒い緩衝帯(moat)**: 検知中は被写体の周囲に環境要素を発生させない+重なったら
   減光。輪郭が常に地の色で縁取られる。presence でゲート(無人時は全面に環境)。
3. **輪郭トレース**: 発生の一部をマスクのソフトエッジ帯に割り当て、輪郭線をなぞる。
4. **連続下地**: 離散要素の隙間でシルエットが途切れるなら、マスク形の淡いオーラ+
   エッジの発光コンターを合成で下敷きに(強すぎると切り抜きに見える。オーラに留める)。
- 出典: flower-being 人型判読性ラウンド×2。

### B3. 発生失敗のフォールバックが図を消す
- **症状**: 小さい/動く被写体で、被写体の花(粒)が全画面に散って図が消える。
  マスクと表現が「反転」したように見える。
- **根本原因**: マスクの棄却サンプリングがミスした際に**画面全体へ明るくばら撒く**
  フォールバック。動く被写体は EMA マスクが薄まりミス率が跳ね上がる。
- **処方**: ミス時は環境側の配置規則に退避(被写体から離れたクラスタ)。受理しきい値は
  EMA の薄まりに寛容に(試行 16 回・内部 >0.35 等)。マスク外に居る被写体粒は減光。
  マスク EMA は速すぎず遅すぎず(≈11/s。遅いと動く人物がスミア)。
- 出典: flower-being 図地反転バグ。

## C. 実機乖離(オフライン検証と実カメラの差)

fakesource 合格 = 完成ではない。**以下は fakesource では原理的に検出できない**:

### C1. 座標規約(Y反転・cover-fit・mirror)
- MediaPipe のマスク/ランドマークは画像空間(左上原点)。video テクスチャは
  UNPACK_FLIP_Y=true が通例 → **マスクのサンプルは `1.0 - y` の反転が必要**
  (overflowing_aura の `vec2(camUV.x, 1.0 - camUV.y)` が実証済みの規約)。
- cover-fit(uSegScale)と mirror は**背景とマスクで完全に同一**の変換を適用する。
- **診断スイッチを実装せよ**: `?fakeseg=1` 型 — 既知向きの合成マスクを実カメラ経路
  (uSource==1 側)に流し、headless で向きを検証可能にする。
- 出典: gas-head「顔だけガス化」(Y反転欠落)。

### C2. 実機スケールの想定違い
- 検証用合成マスクと実機の被写体はサイズ・動き方が別物。ランドマーク由来の寸法は
  **保守的に上限クランプ**(gas-head: 頭部半径 0.4→0.19 で whiteout 解消)。
- **`?fakescale=<f>` フックを実装せよ**(検知もの標準): fakesource の合成フィギュア/
  マスクを係数 f で拡大縮小する URL パラメタ。実機の「大写し」(f≈1.8〜2.2)と
  「小さく写る/引き」(f≈0.5)の両端で final スクショと `--longrun` を回す。
  過去の実機バグ(whiteout・図地反転)は**すべてスケール依存**で、既定スケールの
  検証は素通しだった。
- モデルのファイル名・URL は動作実績のある実物と突合(pose_landmarker_lite.task を
  pose_landmarker.task と書いて 404 → 全検知死亡、の実例あり)。

### C3. モバイル性能レシピ(検知もの標準)
- 使わないモデルをロードしない(Pose が表示に無関係なのに全コストの半分だった実例)。
- **推論入力は縮小コピー**(長辺 ~288px)。マスクは粗い解像度で消費されるので画質影響なし。
- **負荷適応の間引き**: 推論時間を実測し検知間隔を伸縮(33〜250ms)。EMA が間を補間。
- GPU デリゲートの**出力破綻**(全0/全1マスク)を検出して CPU に自動再生成。
- presence はマスクの実カバレッジから(無人でラッチしない)。
- ステータスチップに**推論 ms・デリゲート**を表示(実機診断はこの数字で会話する)。
- 出典: gas-head モバイル対応(flower-being が無改変流用)。

### C4. 検証環境の GPU キュー滞留(swiftshader)と偽の ready
- **症状**: (a) `__artReady` は立つのにスクショが 30 秒超タイムアウト。(b) クラスは
  付くのに CSS トランジションが視覚的に発火しない(computed style が開始値のまま)。
  (c) `verify_runtime` の uiToggle は pass する(クラス状態しか見ないため)。
- **根本原因**: 重い GL 作業(長い事前ロール等)は「投入」と「実行」が分離しており、
  swiftshader では実行が数十秒遅れてキューに滞留する。その間コンポジタはフレームを
  提示できず、rAF・CSS トランジションが完全停止する。`gl.finish()` はこの環境で
  実質ノンブロッキングであり同期に使えない。
- **処方**: (1) 真の同期は **1×1 `readPixels`**(glSync ヘルパー)で取る。
  (2) 事前ロールはチャンク分割し各チャンク後に glSync(ハードウェア GPU では無コスト)。
  (3) `__artReady` は glSync 後に立てる(「最初の本描画フレーム完了」の意味を守る)。
  (4) freeze/pause 中に描画入力が不変ならフレームをスキップ
  (preserveDrawingBuffer 前提。rAF を UI に返す)。
- 出典: taifu-no-me(無入力・240 ステップ事前ロール)のパネル閉鎖バグ診断。

## D. 進め方の規律(介入で実証された手順)

### D1. 毎変更スクショ目視(最重要)
1 つ直すたびに **スクショを撮って自分の目で見る**。verify が通っても見た目は判定できない。
「変更 → 検証 → スクショ → 目視 → 診断 → 次の変更」を1単位とする。まとめて直さない
(どの変更が効いたか分からなくなり、逆行に気づけない)。

### D2. 診断は証拠から(推測で直さない)
不具合報告(実機で顔だけ/白飛び/人型が見えない)を受けたら、**まずオフラインで再現する**
(縮小フィギュア・fakeseg・時系列輝度・debug ビュー)。再現スクショ/数値を得てから直す。
再現できない場合のみ、実績コードとの厳密突合で論理的に絞り込む。

### D3. ゲシュタルトテスト(第一印象)
仕上げ確認では、ルーブリックの前に**「この画像は何に見えるか」を先入観なしに言語化**する。
「花のつもりが星」「風のつもりが水面」は不変量照合では漏れる。第一印象がテーマと
一致しないなら、どれだけ検証が通っていても様式不成立。

### D4. 修正ラウンドは文脈を保持した同一 Maker で
初回実装は隔離された Maker(バイアス遮断)。ただし**美的修正ラウンドは同一 Maker を
resume** する方が実証的に優る(シェーダアーキテクチャの理解を保持し、的確な最小変更が
できる)。隔離を保つのは Checker 側で足りる。
