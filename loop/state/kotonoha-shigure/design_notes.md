## Phase 1 — 不変量表の復唱(発注書 §2 を独自再解析せず復唱)+実装上の懸念

優先度順(2 → 4 → 1 → 3 → 5 → 6):

- **#2 剛体堆積(場/時間)**: 文字は矩形剛体として落下・衝突・回転し、床と堆積の上に
  載って安定した山を作る。貫通・永久振動なし、積もったら静止。
  実装原理: CPU 剛体物理(衝突応答+スリープ)、描画は WebGL2 インスタンス描画+
  グリフアトラス。ボディ数有界(≤200、静定したら蓄積レイヤへ転写して除去)。
- **#4 音駆動の発生(時間/知覚)**: 音量→サイズ、onset→発生タイミング、プロソディ
  (重心・ノイズ性)→書体と朱。無音時は新規発生が止まり塵だけが漂う。
  実装原理: AnalyserNode → RMS/スペクトル重心/ゼロ交差率を毎フレーム ema 平滑、
  onset はヒステリシス+リフラクトリ。音声認識は上乗せ層。
- **#1 和紙と墨と朱(色/物質)**: 地=生成り和紙(fbm 繊維+漉きムラ)、図=墨の
  無彩階調(oklab 無彩軸で紙色→淡墨→濃墨)、彩色は朱ただ一色。純白飛び・純黒つぶれなし。
- **#3 にじみ→定着→風化(物質/時間)**: 着地の瞬間に縁がふくらんで染み込む。
  実装原理: 着地イベントで蓄積レイヤ(ping-pong)へ転写、繊維方向の異方性拡散を
  若い墨ほど強く。埋没深さでコントラスト低下+濃度沈降。
- **#5 風のひと払い(時間/場)**: 高さ場の閾値到達で横風インパルス→掃き出し、
  蓄積レイヤはスミア+フェードで白紙化。輝度・物量は常に有界(CRAFT §A5)。
- **#6 オノマトペの運動翻訳(マーク/時間)**: ザー=細く軽く速い斜め、ゴロゴロ=太く
  重く転がる、ポツ=小さく単発。種別ごとに初速・角速度・質量・摩擦・字重プリセット。

### 実装上の懸念(Phase 1 の列挙)

1. **longrun の white 側閾値と和紙の明度が近い**: 検証器は late mean ≤ 200/255 を要求。
   生成り紙をナイーブに明るく(≈0.86 sRGB)すると紙だけで ≈219 になり失格する。
   → 紙のベースを sRGB ≈0.80 前後+周縁の焼け/ビネットで全画面 mean ≈180 台に設計。
   これは不変量 #1「純白にしない」とも整合する。
2. **黒側の発散**(発注書 §9): 墨は暗い方向に蓄積するので、風化の「濃度沈降」を
   無際限にすると紙が消える。→ 沈降は den→0.85 への漸近(clamp)のみ、払いで全リセット。
   3/8/15 秒の輝度を自分で計測して報告する。
3. **--motion の中心 96px サンプル**: fakesource のイベント列が中心を外れると、
   2 秒窓の 2 サンプル両方で中心に文字が居ない確率が残る。→ fakesource は各イベントで
   中心帯(fx 0.40〜0.60)に小さな雨文字を 2 連(0.27s 差)で必ず併発させ、
   中心透過が途切れないイベント列にする(発注書 §9 の指定)。
4. **swiftshader の GPU キュー滞留(CRAFT §C4)**: freeze の事前ロール(≈780 ステップ、
   各ステップ全画面のにじみパス)は投入だけ先行して ready が嘘になる。
   → チャンク分割+各チャンク後 1×1 readPixels(glSync)、__artReady は glSync 後。
   静止時は drawSig でフレームスキップ(taifu-no-me 踏襲)。
5. **検証環境のフォントは Unifont 1 種**(確認済: unifont_jp のみ)。書体クラス差は
   合成差(太字ストローク合成/斜体スキュー/サイズ比)で出す。実機フォント族での
   見えは未検証と報告する。
6. **グリフ拡大 2 倍制限**: アトラスはグリフ ≈92px(128px セル)。DPR2 の高解像度で
   最大サイズ文字が 2 倍を超えないよう、発生サイズをピクセル換算で clamp する。
7. **アトラス LRU の失効**: アクティブボディが参照中のスロットを evict すると字が
   化ける。→ evict 候補からアクティブ参照中スロットを除外(上限 256、実使用は数十)。
8. **蓄積レイヤの read&write**: にじみは必ず ping-pong。着地スタンプは「update で
   書いた側」へブレンド描画(fixed-function blend は read-modify-write として合法)。
9. **マイク 3 重フォールバック**: 非セキュア/拒否/不在の各経路で専用メッセージ+
   「マイクなしで眺める」+再試行。裏でデモ時雨が常に走る。Web Speech は
   feature-detect+沈黙フォールバック(エラーを一切出さない)。
10. **石膏化ならぬ「黒山化」(CRAFT §A1 の転写)**: 堆積が単一濃度に飽和すると
   「文字の集積」でなく黒い山になる。→ 沈降上限 0.85、風化のコントラスト低下は
   埋没深さ依存の勾配で、表層は常に字形が読める淡→濃の階調を残す。

## Phase 2 — 設計比較

### 候補アーキテクチャ

- **A案(採用): CPU 剛体+カラム高さ場+GPU ping-pong 蓄積レイヤ**
  文字=CPU の回転つき矩形ボディ(≤200)。衝突は 192 カラムの 1D 高さ場(CPU 配列、
  readback なし)に対して行い、空中のボディ同士は円近似の簡易衝突。静定→蓄積レイヤへ
  スタンプ転写→ボディ除去→高さ場更新。にじみ・風化・払いは蓄積レイヤの毎フレーム
  update パスで行う。発注書 §4 の出発点そのもの。
- **B案(却下): GPU 剛体物理(テクスチャにボディ状態、transform feedback)**
  却下理由: ボディ数が ≤200 と小さく GPU 化の利得がない。衝突応答・スリープ判定・
  着地イベント(スタンプのトリガ)・音イベントとの結線は分岐だらけで GPU に不向き。
  決定性(freeze)も CPU 固定 substep の方が単純に保証できる。
- **C案(却下): 着地文字を静的インスタンスとして保持し続ける(蓄積レイヤなし)**
  却下理由: 総物量が非有界(長時間で数千インスタンス)。にじみ・圧密・風化という
  「墨=物質」の時間過程(不変量 #3)がインスタンスの静的描画では表現できず、
  単発ブラー近似は発注書が明示的に禁じる後処理近似になる。
- **D案(却下): 蓄積を CPU canvas2D で合成**
  却下理由: 異方性拡散を毎フレーム全画面 CPU で回すのは DPR2 で非現実的。
  getImageData/putImageData の往復は §8-13(毎フレーム readback 禁止)に反する。

にじみの実装も比較した: 単発ガウスぼかしをスタンプ時に 1 回かける案は「にじみ=状態
遷移(潤→渇)」でなくただのブラー(発注書 §1 の禁止事項)なので却下。採用は
freshness(G ch)を持つ継続拡散 — 若い墨ほど拡散が強く、時間とともに定着する。

### パス構成図

```
[CPU 毎フレーム]
  audio: AnalyserNode(fft2048) → rms/centroid/zcr → ema → onset(ヒステリシス)
         (fakesource: 決定的イベント列 / demo: 手続き時雨 — 同じ spawner API)
  spawner: イベント → 文字ボディ生成(クラス→初速/質量/字重/朱)
  physics: 固定 substep 1/60(≤4/frame)。重力+抵抗+ボディ間円衝突+
           高さ場衝突+スリープ→[stamp イベント]→高さ場更新+なだれ緩和
  hTex 更新: 192×1 R8 texSubImage2D(CPU→GPU 一方向。readPixels なし)

[GPU 毎フレーム]                入力                  出力・形式・解像度
  P1 layerUpdate   layerA(RGBA8 full×DPR≤2), hTex → layerB   にじみ(繊維方向
     毎フレーム     R=墨 G=freshness B=朱                     異方性 4tap)+風化+
                                                             払いスミア/フェード+clamp
  P2 stamp         着地ボディの instanced quad → layerB      加算ブレンド(イベント時のみ)
  P3 composite     layerB, hTex, atlas → canvas(full×DPR≤2) 紙 fbm × oklab 墨ランプ ×
                                                             朱 + 塵 + uDebug 0..4
  P4 bodies        instanced quad(≤200) → canvas            落下中のシャープな活字
                                                             (uDebug1 ではワイヤ枠)
  remap            リサイズ時: 旧 layer → 新 layer へ世界座標リマップ(copy パス)
  atlas            2048² RGBA8。canvas2D 128px セル → texSubImage2D(LRU ≤256)
```

- freeze: fakesource イベント列で 780 ステップ(=13s)を dt=1/60 で事前ロール
  (60 ステップ毎に glSync)→ dt=0。シードは pcg 系 hash(イベント連番・セル座標)のみ。
- リサイズ: **世界座標リマップで状態保持**(高さ場は CPU で線形再標本化)。
  報告事項: 白紙リセットではなくリマップを選択。

### フィルレート概算

full-res(DPR≤2)換算: P1(1.0)+P3(1.0)+P4(ボディ被覆 ≈0.1)+P2(稀) ≈ **2.1 画面/frame**。
taifu-no-me(シミュ 7 パス半解像度+full composite ≈ 1.6 画面 equiv)と同オーダー。
P3 の fbm は紙 5oct+塵で ALU 重めだが分岐なし。モバイル 30fps は DPR cap 2 と
物理の固定 substep(フレーム落ち時も ≤4 substep)で担保。

### リスク(Phase 1 の懸念と対応づけ)

- 輝度側: 紙の設計輝度(懸念 1)・黒側発散(懸念 2)→ 目視+時系列計測で確認。
- 検証側: motion の中心イベント列(懸念 3)・swiftshader 滞留(懸念 4)。
- 見た目側: 黒山化(懸念 10)、朱の花柄化(ルーブリック追加観点 b)→ 朱は
  興奮閾値制+スタンプ時に墨を減らして「朱字」として読ませる。
- 決定性: 物理は JS 倍精度の固定 substep で決定的。時間はシードに混ぜない。

### uDebug 設計(発注書指定の 5 面)

0=最終 / 1=物理(ボディ矩形ワイヤ+高さ場の線+堆積下領域の色) /
2=蓄積レイヤ raw(R=墨 G=年齢 B=朱) / 3=音特徴量メータ(RMS・重心・ZCR・onset
フラッシュ・書体クラス 3 ブロック。fakesource ではスクリプト値。選択中の語は readout に表示) /
4=標本(紙地見本+墨 oklab ランプ+アトラス実グリフのにじみ前/後標本+朱見本)

### スライダー(発注書 §6 の 8 本をそのまま)

amount/size/bleed/weather/paper/ink/aka/sweep — 単一 state、[key,ラベル,ヒント,min,max,step]
配列から生成。プリセット: 写経/時雨(既定)/喧騒。
