## Phase 1 — 不変量表の復唱(発注書 §2 をそのまま復唱。再解析しない)

1. **[知覚/場]** 無傷の表面は生のカメラ映像そのもので、ブロックの継ぎ目・格子・タイル感が
   一切見えない。剥離して初めてグリッドの存在が分かる。
   → 無傷領域は video テクスチャをフルスクリーン直描き。事前タイル分割禁止。剥離状態は
   低解像度の剥離マスク(グリッドセル単位)で管理し、合成時にマスクで生映像/裏世界を切替。
   セル割当は cell-hash の安定空間。外すと「いつも通りが偽りだった」の反転が死に、
   ただのモザイクエフェクトになる。
2. **[物質/時間]** 剥離ブロックは回転を伴う剛体として落下し、床と互いに衝突して画面下に
   自然な山なりに堆積(整列・等間隔・同位相の禁止)。CPU 剛体(衝突応答+スリープ)+
   WebGL2 インスタンス描画。ボディ数はセル総数で有界。着地後スリープ。
3. **[マーク/物質]** 各ブロックは剥離した瞬間の映像を凍結して携える(元位置 UV で切り出した
   過去のフレーム)。破片の中の像は止まり、背後の白黒世界だけが動く。剥離イベント時のみ
   sceneT をスナップショット凍結(GPU 内コピー)、世代共有 2〜3 枚、ブロックは生成時の世代を選ぶ。
4. **[色/知覚]** 露出する裏世界は彩度ゼロの白黒で味気なく、sobel 輪郭線と粗い明暗
   (3〜4 段ポスタライズ)だけ。ライブ映像から検知され続けるので裏世界の被写体は動く。
   表との対比のため暗めに沈める。
5. **[時間]** 崩壊は部分的: クリックは手のひら大の剥離に留まり、支持喪失伝播で周縁セルが
   時間差でパラパラ追い崩れ、距離と時間で減衰して必ず止まる。1 クリックで全面崩壊しない。
   乱数は cell-hash(時間を混ぜない)。
6. **[時間/場]** 表面は緩やかに自己修復(回復は穴の端から埋まる、ema 的長時定数)。堆積した
   破片は寿命で退色して白黒世界に同化し消える。長時間で発散も枯渇もしない
   (ボディ数と堆積高さを有界に保つ)。

優先度: [1, 3, 2, 5, 4, 6]

### 実装上の懸念(列挙のみ)

- **懸念 a(不変量1×6)**: 修復途中のセルをマスク値の中間値で表すと、無傷面の中に
  「うっすら四角い継ぎ目」が見える危険。→ 合成はマスクのバイリニア補間値を smoothstep で
  再鋭化し、面としては常に 生映像 or 裏世界 の二値+狭い縁帯のみにする(中間の
  半透明ブレンド面を作らない)。修復は「境界線が穴の端から内側へ動く」ことで表現する。
- **懸念 b(不変量3)**: スナップショット世代 2〜3 枚の共有は、古い世代の再利用時に
  既存ブロックの画が差し替わるリスク。→ 世代に参照カウントを持ち、未参照世代を優先再利用。
  全世代参照中のみ LRU 上書き(有界な妥協として報告)。
- **懸念 c(不変量2, CRAFT §E2)**: 列ハイトマップ堆積は針山・宙吊りの既知失敗がある。
  → 安息角の緩和(隣接カラム差の毎ステップ平準化)+隆起量は実カバレッジの ~75% に抑制+
  スリープは速度と接地の両方で判定。
- **懸念 d(不変量5)**: 伝播の収束保証。確率だけだと無限連鎖があり得る。→ ストレス場
  (ピール時に近傍へ注入、毎 tick 幾何減衰、世代ごとに注入係数 <1)で数学的に有限化。
- **懸念 e(不変量4×受入基準)**: depth(裏世界の暗さ)最大時に sobel 黒線が沈んで被写体の
  判読性が落ちる。→ トーン床(≥0.05)と線/面のコントラスト比を維持する写像にする。
  標本(uDebug=4)のトーン段見本で確認。
- **懸念 f(--motion, CRAFT §E3)**: 画面中央 96×96 のサンプルで運動を測るため、fakesource の
  合成シーンは中央に動く要素(揺れる人物の頭・胸)を置く。
- **懸念 g(freeze × flicker)**: freeze 時は物理・伝播・修復・シーン時刻を完全停止し、
  マスク/インスタンスバッファも不変にして決定的静止フレームを保証する。
- **懸念 h(実機乖離)**: 実カメラでの「無傷面の継ぎ目不可視」は snapshot/mask の座標規約が
  1px でもズレると破綻する。オフラインでは fakesource 一致で検証できるが、実カメラの
  非整数 cover-fit は実機確認項目として報告する。

## Phase 2 — 設計

### 候補アーキテクチャ比較

**案 A(採用): CPU グリッド+CPU 剛体+GPU 合成(発注書 §4 の出発点どおり)**
- 剥離マスク: CPU TypedArray(≤ 約 64×40=2560 セル)→ 毎フレーム R8 小テクスチャへ一方向
  アップロード。支持喪失伝播・修復・イベントは全部 CPU(決定的、prewarm 容易)。
- 物理: CPU で O(ボディ数)。堆積は列ハイトマップ近似+安息角緩和(kotonoha 簡略方式)。
- 描画: sceneT 直描き+bwT+snapT[3]+instanced quads。RGBA8 のみで成立
  (float バッファ不要 → EXT_color_buffer_float 非対応機でも同一の見た目)。
- 採用理由: セル数・ボディ数が小さく CPU で余裕(下記概算)。決定性(prewarm・freeze・
  スクリプトイベント列)が最も作りやすい。readPixels 不要の一方向転送。

**案 B(却下): GPU ping-pong で剥離マスクと伝播を計算**
- マスク更新をフラグメントシェーダの ping-pong で行う。
- 却下理由: 剥離イベント→ボディ生成(CPU)へ状態を戻すのに毎フレーム readPixels が必要に
  なり技術注意 13 に抵触。1440 セル規模では GPU 化の利得がなく、決定的な prewarm
  (固定 dt 早送り+スクリプトイベント)の実装も複雑化する。発注書も CPU 管理を推奨。

**案 C(却下): Matter.js 型の本格剛体(ブロック同士の完全な衝突応答・回転衝突)**
- kotonoha-shigure は Matter.js を内蔵していたが、本作の許可依存は「なし」であり
  物理エンジンの同梱は行数・複雑性に対して利得が薄い。ブロックは同サイズ正方形で
  山なりの堆積が主目的 → 列ハイトマップ+安息角+着地時の角度保持で十分
  (発注書 §4 も「列ハイトマップ近似でよい」と明記)。空中のブロック同士衝突は省略し、
  落下タイミングと初速・角速度の分散で「同位相禁止」を担保する。

### パス構成図(解像度・フォーマット・更新頻度)

```
入力: video(実カメラ) or fakeScene(GLSL 合成: 揺れる人物+振り子ランプ+流れる雲)
      ?fakesource=1 で GLSL 合成に切替(カメラ API は従来どおり試行し 3 エラー経路を保持)

[P0 scene ]  cover-fit + mirror(or fakeScene)     → sceneT   RGBA8  長辺≤1024   毎フレーム
[P1 bw    ]  sceneT → 輝度 sobel + 無彩 3〜4 段    → bwT      RGBA8  長辺≤512    毎フレーム
             ポスタライズ + depth で沈める
[P2 snap  ]  剥離イベント時のみ copyTexSubImage2D  → snapT[3] RGBA8  sceneT と同寸 イベント時のみ
             (sceneT の FBO から GPU 内コピー。参照カウントで未参照世代を優先再利用)
[CPU mask ]  グリッド(基準 48×30、block スライダで 24〜72 列)Float32Array
             surf(1=無傷,0=穴)+ stress + healDelay。pointer イベント→初期剥離(半径減衰)、
             12Hz tick で支持喪失伝播(ストレス幾何減衰で有限収束)、毎ステップ ema 修復
             (穴の端=無傷隣接数に比例)。毎フレーム R8 gridW×gridH LINEAR へ texSubImage2D
             (readPixels なしの一方向)
[CPU phys ]  剥離セル→ボディ化(pos/vel/angvel/世代/寿命)。固定 dt=1/60 の積分、重力+空気抵抗、
             列ハイトマップ(gridW×2 カラム)との着地判定+安息角緩和+スリープ+寿命消滅
             (風化中はカラム寄与も漸減 → 山が滑らかに沈む)。上限 1600 ボディ
[P3 comp  ]  フルスクリーン 1 パス: bwT を基層に、マスク(バイリニア+ノイズジッタ閾値の
             smoothstep 再鋭化)で無傷領域だけ sceneT を直描き。縁は擬似 sdf 距離帯で
             欠けの厚み(裏側に落ち影、表側に石膏の欠け縁ハイライト)。uDebug 1/2/4 も本パス
[P4 blocks]  instanced quads(≤1600)。snapT[世代] を元位置 UV で参照、面内回転、
             縁の厚み暗帯、風化=無彩化→透明化。uDebug 3 は世代着色
出力は canvas(preserveDrawingBuffer: true)。DPR≤2。
```

### フィルレート/ボディ数概算

- 毎フレームの描画画素: P0 ≤1024×640 + P1 ≤512×320 + P3 canvas(≤2.2MP@DPR2 モバイル、
  デスクトップ ~1.4MP) + P4 ブロック合計(最悪 1600×(20px)² ≈ 0.64MP)。
  合計 ≈ 3〜4MP/フレーム、全パス単純シェーダ(sobel 3×3 が最重)→ モバイル 30fps 余裕。
- CPU: 物理 1600 ボディ×積分+カラム判定 ≈ 数万 op/フレーム。伝播 tick は 12Hz×2560 セル。
  マスクアップロード 2.5KB/フレーム。いずれも無視できる規模。
- メモリ: snapT 3 枚 ≈ 3×1024×640×4 ≈ 7.9MB + sceneT/bwT ≈ 3.3MB。問題なし。

### 検証フックの設計

- `?freeze=1`: dt=0(シーン時刻・物理・伝播・修復すべて停止)。
- `?prewarm=<秒>`: 初回描画前に固定 dt=1/60 で決定的早送り。チャンク分割+1×1 readPixels の
  glSync(CRAFT §C4)。スクリプトイベント列: t=1.0s(左上寄り)/ t=4.2s(右下寄り)/
  t=prewarm−1.2s(中央)の 3 発 → 12 秒 prewarm で「部分修復された穴+堆積+落下中+追い崩れ」が同居。
- `?fakesource=1`: GLSL 合成シーン(中央で揺れる人物=--motion 対応、雲・振り子=周辺の動き)。
- fakescale: 該当なし(発注書 §7 明記)。
- 蓄積系検査: --longrun(放置では剥離しないので自明に安定だが、prewarm 後の堆積・修復も
  clamp と寿命で有界)。--motion(裏世界と無傷面の両方が合成シーンの動きで変化)。

### リスク

1. 実カメラで snapshot と live の 1px ズレ → ブロック縁で背景が二重に見える(実機確認項目)。
2. 世代 3 枚共有の上書き(懸念 b)— 参照カウントで緩和、ゼロにはならない。
3. swiftshader での prewarm 12s = 720 ステップ×全パス → チャンク glSync で数十秒に収まる見込み。
   物理のみのステップは GPU を使わないため、GPU パスは 1/4 に間引いた「代表フレーム」更新でも
   決定性を保てる(snap はイベント時のみなので間引き対象外)→ 実装で採用。
4. 修復の見た目が「ワイプで戻る」と安っぽい → 端から埋まる+閾値ノイズジッタで
   有機的な縁を保つ。目視ラウンドで確認(CRAFT §D1)。
