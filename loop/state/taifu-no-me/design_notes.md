# design_notes — fable5_taifu-no-me「台風の目」(Maker Phase 1–2)

## Phase 1 — 不変量表の復唱と実装上の懸念

発注書 §2 の表を再解析せず復唱する(優先度順 2 > 1 > 3 > 4 > 6 > 5)。

1. **[#2 場/知覚] 目の維持**: 中心に雲のない円形の静穏領域(目)が常に維持され、境界は
   最も濃い雲の壁(アイウォール)。目は雲で埋まらず内側に暗い海面がのぞく。
   実装原理: 中心距離場(sdf)で注入と速度をゲート。目の内側は散逸最強+注入禁止、
   アイウォール半径 R の環に最濃注入。外すと渦巻く煙になり主題が消える。
2. **[#1 場] 大域の回転組織**: 画面はひとつの巨大な渦で、雲帯が対数螺旋状に中心へ
   巻き込む。実装原理: Stable Fluids の速度場に中心まわりの接線外力(スパイラル角つき)を
   常時与える。雲帯の乱れは curl noise を注入の変調に、帯は複数の弧として注入し移流が
   螺旋に引き伸ばす。外すとただの乱流・煙。
3. **[#3 時間] 運動の対比**: 外縁は速く、アイウォール付近で回転最速、目の内側はほぼ静止。
   実装原理: ランキン渦の接線速度プロファイル(r で増→R で最大→内側で急減)を外力に。
   細部維持に vorticity confinement。外すと一様回転になり主題(動と静)が消える。
4. **[#4 物質] 雲の mottle と自己遮蔽**: 雲帯は内部に濃淡の mottle を持ち、光方向の
   自己遮蔽で盛り上がって見える。飽和した白一色(石膏)にしない。
   実装原理: 注入テーパで密度 0.6〜0.85 帯、curl noise 由来の mottle を密度ゲインに、
   密度勾配の擬似法線+光方向2タップ自己遮蔽。外すと CRAFT §A1 の石膏。
5. **[#6 時間/場] 長時間定常**: 雲量・輝度が発散も消失もせず渦は回り続ける。
   実装原理: ping-pong 各ステップで clamp、注入は既高密度でテーパ、散逸は中心距離依存
   (目の内側で最強)、運動場の平滑化に ema。外すと CRAFT §A5 whiteout か雲消失。
6. **[#5 色] 俯瞰の色設計**: 雲は青みがかった白〜灰、切れ間と目の内側は深い海色、
   周縁は減光。実装原理: 密度→oklab で海色→灰→白補間、edge darkening のビネット、
   彩度低く白上限 0.9。外すと衛星写真のゲシュタルトが崩れる(銀河化に注意)。

### 実装上の懸念(CRAFT 該当節を読了: A1 / A4 / A5 / D1、追加で D3・B1)

- **銀河化(CRAFT §B1/D3 の変種)**: 黒地+青白の渦は即座に「渦巻き銀河」に読まれる。
  地は必ず「海」= 深い青(真っ黒にしない。freeze 中心輝度 >8/255 は発注書の受入基準)、
  雲は加算グローではなく遮蔽つきの物質として描く。周縁減光もビネット過剰だと宇宙になる。
- **石膏化(§A1)**: アイウォールは「最も濃い」が要件だが、注入を強くしすぎると環全体が
  1.0 飽和して照明が死ぬ。テーパ上限 0.85 は環にも適用し、mottle をゲインの主成分にする。
- **whiteout / 消失(§A5)**: 注入と散逸の平衡を距離依存で設計し、`--longrun` で機械検証。
  白上限 0.9・露出控えめ。逆に外縁散逸が強すぎると雲帯が届かず「輪だけ」になる。
- **水面化(§A4)**: 本作は「雲の大陸を上から見る」ので流体移流の膜的モーション自体が
  正解側(A4 が禁じるのは空中粒子の表現)。ただし密度をスクリーンノイズで直接揺らすと
  水面のうねりに見えるため、ディテールノイズは流れと共回転する座標系でサンプルする。
- **motion 検査と目の静止の衝突**: verify_runtime の motionResponse は画面中央 96×96 を
  測るが、中央は「静止の目」。発注書 §4 の海面のきらめき(ゆっくり位相、freeze 停止)を
  目の海面に実装して中央にも微小変化を確保する(主題を壊さない振幅で >0.5/255 を満たす)。
- **freeze の決定性**: シードは全て固定値/セル座標。freeze 時は固定 dt=1/60 の事前ロール
  240 ステップ後に dt=0。リサイズで FBO を作り直したら事前ロールを再実行して同じ
  発達状態に戻す(チラつき検査は freeze URL で走る)。
- **fakesource=1 受理**: 無入力なので読み捨てる(エラーにしない)。
- **(R/r)^α の r→0**: pow の基数を max で保護。normalize(grad|ω|) はゼロ割防止。

## Phase 2 — 設計

### 候補アーキテクチャ比較

| 案 | 概要 | 判定 |
|---|---|---|
| A. 純手続き(流体なし) | 極座標の差動回転+domain-warp fbm で螺旋雲をシェーダ1本で描く | **却下**: 発注書 §1「構造は場が作る。テクスチャアニメで描かない」に正面から違反。雲の生成消滅も嘘になる |
| B. フル解像度 Stable Fluids | 速度・密度ともキャンバス解像度 | **却下**: Jacobi 反復×20 をフル解像度で回すのはフィルレート浪費(規約も流体は半解像度以下を要求)。雲の微細質感は密度解像度ではなくレンダ時のディテールノイズで出す方が制御可能 |
| C. 低解像度場+フル解像度レンダ(採用) | 速度場・密度場は長辺 ≤448 の低解像度 ping-pong。外力は「ランキン渦ターゲット場への緩和(ema)」。レンダはフル解像度1パスで、密度勾配法線+共回転ディテールノイズ+oklab | **採用**: 場が構造(螺旋・目・対比)を作り、レンダが物質(mottle・自己遮蔽)を作る分業。安定(緩和外力は速度が有界)でフィルレートも軽い |

外力の方式比較(C 内の設計判断): 単純加算外力は速度が蓄積し発散しやすく、
毎フレームの調律が必要。**ターゲット場への緩和** vel += (v_rankine − vel)·k·dt は
ema そのもので(語彙 ema の主用途)、有界かつ「目の内側 = ターゲット 0 + 強い緩和」で
不変量 3 の静止が構造的に保証される。curl noise/confinement が緩和で消されない程度に
k は帯域で弱める。

### パス構成図(毎フレーム 1 ステップ。★= EXT_color_buffer_float 時 RGBA16F / 無時 RGBA8 オフセット符号化)

```
シミュ格子: キャンバス相似・長辺 ≤448(流体半解像度以下の規約)。単位は「画面高さ=1」の
ワールド系(正方テクセル h = 1/simH)。C=画面中心、R=アイウォール半径(eyeSize)。

[S1 curl   ] velA            → curlT ★      ω̃ = (vR-vL-uT+uB)/2(h スケール済み)
[S2 force  ] velA,curlT      → velB ★       semi-Lagrangian 移流 → ランキン緩和(スパイラル角
                                             15°、目の内側はターゲット0+calm 緩和)→ vorticity
                                             confinement(ε·N×ω)→ 全域微小ドラッグ+外縁減衰
[S3 div    ] velB            → divT ★       D̃ = (uR-uL+vT-vB)/2
[S4 jacobi ] prsA/B ×20      → prs ★        P̃ ← (ΣP̃ − D̃)/4(前フレームの P̃ でウォームスタート)
[S5 project] velB,prs        → velA ★       vel −= (P̃R−P̃L, P̃T−P̃B)/2
[S6 density] denA,velA       → denB ★       移流 → sdf ゲート注入(アイウォール環ガウス+固定
                                             シード弧ソース+curl-noise mottle 変調、den>0.85 で
                                             テーパ)→ 距離依存散逸(目>外縁>帯)→ clamp[0,1]
[R  render ] denB,velA       → canvas       密度→oklab(海→灰→青白 L≤0.9)、勾配擬似法線+
             (DPR≤2)                         光方向2タップ自己遮蔽+共回転 fbm ディテール、
                                             海面グレイン(静的 hash+ゆっくり位相)、edge
                                             darkening ビネット、uDebug 0-4
```

- 更新頻度: 全パス毎フレーム 1 回(dt = clamp(rawDt)·pace)。freeze/リセット時は固定
  dt=1/60 の事前ロール 240 ステップをフレームあたり 12 ステップに分割して実行。
- 描画コール ≈ 26/frame(うち 20 が低解像度 Jacobi)。

### フィルレート概算(1920×1080・DPR2 の想定上限 3840×2160 ≒ 8.3MP)

- シミュ: 448×252 ≒ 0.113MP × 26 パス ≒ 2.9MP/frame(半精度・軽シェーダ)→ 無視できる
- レンダ: 8.3MP × 1 パス。fbm ~10 オクターブ相当+密度 6 タップ+影 3 タップ ≒ 中程度
  → デスクトップ 60fps 見込み。モバイルは DPR≤2 制限+シミュ低解像度で 30fps 見込み
  (実機 GPU は未検証と報告する)

### リスクと手当

1. 銀河化 → 海の青を黒に落とさない・雲は遮蔽で描く・スクショ第一印象テスト(D3)
2. whiteout/消失 → 距離依存散逸+テーパ+`--longrun`、目視 3/8/15s
3. 目が埋まる → 注入ゲート(r<0.8R でゼロ)+目内散逸最強、uDebug=3 で環と目を常時確認可能
4. RGBA8 フォールバックの精度(圧力・渦度) → スケール済み量(P̃,D̃,ω̃ ≈ 速度オーダー)で
   符号化し ±4 レンジに収める(劣化はするが機能する)
5. モバイル実性能 → 未検証項目として報告
