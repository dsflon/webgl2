## Phase 1 — 不変量表の復唱と実装上の懸念

### 復唱(発注書 §2 の表を、実装者の言葉で。再解析はしない)

1. **溶解帯の実在**(優先1位): シルエットの縁に「実体↔気体」の遷移帯があり、帯上が最も明るい。
   煙はこの帯**から**流体の密度場へ毎フレーム注入される。実装原理は指定どおり
   「背景の遅い EMA 推定との差分 → シルエット場 → 擬似 SDF(ぼかし値)の帯 → 密度注入」。
   オーバーレイ合成は不合格。
2. **煙は流体**(優先3位): 半解像度以下(長辺≤512)の Stable Fluids。
   semi-Lagrangian 移流+Jacobi 圧力 20〜30回+vorticity confinement。
   外力 = 運動場(フレーム差分 EMA)+curl noise+弱い浮力。密度注入は溶解帯のみ、実体内部には注入しない。
3. **煙は自発光**(優先2位): 密度→カラーランプ(深青 #0a2a66 → シアン #35c8ff → 白 #eaf6ff)。
   縦横分離ブラー2〜3段のブルーム+feedback ping-pong の減衰残光。
4. **夜のシネマティックグレード**(優先4位): 輝度ゾーン別 split toning(影 #12333a / 中間 #274a6e /
   ハイライト冷白)。左=赤 #ff2f4f / 右=青 #2f6dff の対向リム(Fresnel 近似)。
   背景は映像をほぼ落とした暗い書き割り+静的位置でゆっくり明滅するボケ光。
5. **溶解は動きに反応**(優先5位): 運動場が注入量と侵食深さを変調。速い=侵食が深まる/静止=縁からゆっくり再構成。
6. **静的グレイン**(優先6位): cell-hash 静的グレイン(時間シード禁止)+暗部限定ディザ。

被写体がシルエットと残存実体部で判読できることは受入基準(§3)。

### 実装上の懸念(Phase 1 での列挙のみ)

- **C1: 背景学習のチキンエッグ問題(実カメラ)** — 起動時から人物が写っていると、初期学習で人物ごと
  背景に取り込まれ、シルエットがゼロから始まる。対策: 数秒の LEARNING 表示付き高速学習フェーズの後は
  「シルエットが立っている画素では背景を学習しない」ゲート付き EMA に切替。人物は動いた瞬間から
  シルエット化され、以降ゲートで保持される(=動きが実体を顕在化させる。本作の主題と整合)。
  完全静止し続けた人物が数十秒かけて背景へ沈む挙動は原理上残る(未検証項目として報告)。
- **C2: ?freeze=1 の初期フレーム問題** — freeze を dt=0 と等価にすると、t=0 から freeze の場合
  EMA(α=1-exp(-dt/τ)=0)が一度も更新されず場が空のままになる。対策: リセット直後の1フレームだけ
  α=1 の「シード」を許す(papercraft の emaNeedsReset と同じ規約。時間発展ではなく初期化と整理)。
  以降は完全に静的。流体密度は注入∝dt=0 のため freeze 静止画に煙は出ない(§4 の定義どおり
  「最後の場の表示」= t=0 では空)。溶解帯・実体・書き割り・リムは初期フレームで確立され写る。
- **C3: fakesource の背景推定** — 合成シーンでも背景差分パイプラインを生かすため、fakesource 時は
  背景推定パスが「人物を除いた合成背景」を直接描く(合成シーンの GLSL 関数を scene パスと共有)。
  シルエット抽出・溶解・流体は実カメラと同一経路を通る。
- **C4: float レンダーターゲット非対応時** — EXT_color_buffer_float が無い環境では RGBA8 に落とす。
  速度・圧力・カール等は常に [0,1] オフセット符号化(enc/dec 関数)で読み書きし、シェーダは単一
  コード経路のまま精度だけが落ちる設計にする(8bit Jacobi は粗いが発散はしない)。
- **C5: 発散・NaN** — 速度は enc 時に必ずクランプ、密度は毎フレーム減衰+クランプ、
  normalize は max(len,1e-4) ガード、pow は max(x,0)。Jacobi は JS 側の固定回数ループ。
- **C6: フレーム差分流(擬似オプティカルフロー)の弱さ** — 1画素 Lucas-Kanade 近似は小さい/遅い動きを
  過小評価する。閾値を低めに置き EMA で安定化する。方向情報は注入された煙の初速と実体内部の
  「動く障害物」挙動にのみ使い、破綻しても様式が死なない位置に置く。
- **C7: フィルレート** — 最終コンポジットはフルキャンバス解像度で書き割り・リム・グレイン等を全部やる
  重いパス。ボケ光は8灯の解析形状に限定、流体/場は長辺512、発光・残光・ブルームは半解像度以下に制限。

## Phase 2 — 設計

### 候補アーキテクチャ比較(2案却下・1案採用)

**A案: パーティクル煙(transform feedback で帯から粒子放出+ソフトスプライト描画)** — 却下。
不変量2が明示的に「スプライト貼り付けではない/grid 流体」を要求し、発注書 §4 が
Stable Fluids を技法語彙として固定している。粒子は渦・非圧縮性・実体回避が出にくく、
失敗モード「ゲームのスプライト煙」に直行する。

**B案: 圧力解なし擬似流体(1枚の密度 feedback バッファに curl noise 移流のみ)** — 却下。
パス数は激減するが、非圧縮性がないため煙が「流されるだけ」で渦を巻いて滞留する実写VFXの
質感(不変量2)が出ない。発注書 §4 が「Jacobi 圧力反復 20〜30回」を明示指定しており逸脱になる。

**C案(採用): 場テクスチャ+半解像度 Stable Fluids+半解像度発光チェーン+フル解像度コンポジット**
- 「場」テクスチャ(RGBA, 長辺512)に R=シルエット EMA / G=侵食量 E / BA=運動場(enc)を集約。
  ぼかした (シルエット, E) から q = blur(sil) − blur(E) を作り、q=0.5 の等値線が溶解境界、
  |q−0.5| の窓が溶解帯(擬似 SDF)。E が増えると境界が内側へ後退=侵食、E の回復で再構成。
- 流体は同じ長辺512グリッド。移流→外力(運動場・curl noise・浮力・渦度強化)→発散→Jacobi 24回→射影。
  密度は帯からのみ注入(q の深い内側では注入ゼロ+強制減衰)。実体内部は速度を運動場へ緩和させ
  「動く障害物」として振る舞わせる。
- 発光: 密度→ランプ+帯の発光を半解像度で描き、feedback(max, 減衰)→分離ブラー2段ブルーム。
- コンポジット(フル解像度): 書き割り背景(グレード0で素の映像へ)、実体=グレード済み映像+
  SDF 法線からの赤青対向リム、帯コア発光、煙(feedback+ブルーム)加算、split toning、
  静的グレイン+暗部ディザ、ビネット、uDebug 0..7。

### パス構成図(入出力・解像度・フォーマット・更新頻度)

フォーマットは float 対応時 RGBA16F(★印)/ 非対応時 RGBA8(同一シェーダ、enc/dec 符号化)。
scene は常に RGBA8。全て毎フレーム更新、Jacobi のみ毎フレーム24回。

### リスク(対策は Phase 1 の懸念 C1〜C7 に対応)

1. 実カメラの背景学習品質(C1) — ゲート付き EMA でも照明変化・自動露出で誤シルエットが出る。
   中央重み事前分布と閾値の smoothstep で抑制。
2. freeze 決定性(C2) — リセット1フレームのみ α=1、以降 dt=0 で全 EMA・移流・注入・減衰・明滅・
   腕の動きが停止することをコードレビューで確認する。
3. 8bit フォールバック品質(C4) — 動作はするが圧力が粗い。float 有無を readout に出さない代わり
   ヘッダに明記。
4. 侵食の空間表現(新規) — E は「ぼかしシルエットへの閾値オフセット」なので、侵食可能深さは
   ぼかし半径で頭打ち。DISSOLVE スライダーでぼかし σ と E 上限を同時に広げて対処。
   細い部位(腕・手)は blur(sil) が低く、完全に溶け切る=参照どおり手から溶ける画になる。

### uDebug 割当(発注書 §4)+Phase 3 標本

0=FINAL / 1=シルエット場 / 2=流体密度 / 3=速度場 / 4=溶解帯(擬似SDF+侵食の可視化) /
5=グレードのみ(煙・帯なし) / 6=背景推定。
**7=LAMP SPECIMEN(発光ランプ標本)**: §5 Phase 3 が要求する「密度 0→1 の帯にカラーランプ+
ブルームを適用した帯」。emission パスが標本帯を出力し、実物の feedback・ブルーム・加算経路を
そのまま通す(標本のための別実装を作らない)。プリセット2種(Night Chase / Cold Morgue)の
ランプ・リム・トーン色はこの標本で審査可能。
溶解帯標本 = `?fakesource=1` + uDebug=4。

### スライダー→uniform 対応(発注書 §6 の8本、初期値も §6 どおり)

dissolve→帯ぼかしσ・E上限・侵食レート / emission→注入量 / swirl→渦度強化ε+curl noise 振幅 /
glow→ランプ輝度+帯発光+ブルーム加算重み / trail→feedback 減衰 τ / grade→split toning と
書き割りのブレンド(0で素の映像) / rimLight→対向リム強度+ボケ光強度 / grain→グレイン+暗部ディザ。

プリセットは色セット(ランプ3色・リム左右・トーン3色・ボケ光2色)+rimLight/grade の初期値のみを
切り替える(スライダー定義や他パラメタは共有)。

## Phase 3-4 記録(実装後の追記)

- 標本: 溶解帯標本 = `?fakesource=1` + DEBUG「DISSOLVE BAND (SDF)」/ 発光ランプ標本 =
  DEBUG「LAMP SPECIMEN」(emission パスが 0→1 の密度帯を出力し、実物の feedback+ブルーム
  経路をそのまま通す。標本用の別実装なし)。
- 自己批評(§10)を2周実施。1周目: 煙が帯に張り付いたまま放出されず不変量2が2点 →
  修正: 帯の外向き法線方向への放出速度を外力に追加(band × (0.30+1.5·mot01))、浮力
  0.25→0.85、密度減衰 0.42→0.30/s、curl noise の密度ゲート緩和、fakesource の腕の周期を
  わずかに短縮。2周目: 密度デバッグにキノコ渦・上昇プルームを確認、最終合成で煙が薄い →
  発光ランプの低密度側を持ち上げ(pow(d,0.85)→pow(d,0.6))。最終採点(自己):
  不変量1=5, 2=4, 3=4, 4=4, 5=4(侵食は合成腕の遅い動きでは控えめ。実カメラの速い動きで
  深まる設計), 6=4。
- 検証: verify_static エラー0(警告1件は createFramebuffer 文字列出現回数を数える lint の
  誤検知 — FBO生成はヘルパ関数経由で、EMA/feedback/流体は全て実バッファの ping-pong)。
  verify_runtime(`?fakesource=1&freeze=1`, フェイクカメラ)全10チェック合格
  (flicker mean|Δ|=0.000)。
- freeze=1 の意味論: dt=0(移流・注入・減衰・EMA・明滅・腕・残光すべて停止)。リセット直後の
  1フレームのみ EMA α=1 のシード(初期化)を許可 — t=0 から freeze でも溶解帯・実体・
  書き割りが確立した決定的静止フレームになる。t=0 freeze では密度注入が一度も起きないため
  煙は写らない(発注書 §4「最後の場をそのまま表示」の t=0 ケース)。
