## Phase 1 — 不変量表の復唱と実装上の懸念

### 復唱(§2 の表を実装者の言葉で。再解析はしない)

1. **紙積層(最優先)** — 画面全体が 4〜8 枚のフラットな紙。kuwahara 平滑輝度を
   quantile しきい値で量子化し(しきい値は CPU 統計の ema+hysteresis)、境界近傍の
   擬似 sdf 帯で「切り口の細いハイライト」と「下層への短い柔らかな落ち影」を付ける。
   面の内部はほぼ平坦。前身 kirie-portrait の肌積層エンジンの全画面化。
   外すと→ただのポスタライズフィルタ。
2. **ハサミの滑らかさ** — 輪郭に 1〜2px の鋸歯・ちぎれ粒を出さない。平滑半径で
   境界曲率を制御し、fwidth 比較の最小帯幅フロアで薄帯・小島を下の層へ吸収。
   乱数は cell-hash のみ。外すと→劣化画像。
3. **奥行きの秩序** — 量子化レベル⇔前後関係を固定対応(明=手前/暗=手前はプリセット)。
   落ち影は単一光源ベクトルで全画面一貫。edge darkening 控えめ。
   反転時は影方向・切り口の付く側も一貫して反転(§8-16)。外すと→ランダムな縁取り。
5. **時間安定** — 静止で完全静止・動けば遅れなく追従。しきい値は ema+hysteresis、
   平滑輝度は ping-pong の時間 ema、乱数に時間を混ぜない。外すと→沸き立ち。
4. **限定パレット** — 各層の色を oklab で紙セット代表色へスナップ。彩度と色数は
   紙セットが支配(シーン色相の反映は僅かでよい)。層ごとに位相の違う fbm 紙グレイン。
   外すと→実写色の段々。
6. **人物の判読性** — 検知なしで、暗部小紙片の保護(最暗トーンとして保持)+
   局所コントラストに応じた quantile 段の局所細分で目・眉・口を残す。
   外すと→鏡としての面白さが消える。

優先度: [1, 2, 3, 5, 4, 6]

### 実装上の懸念(Phase 1 で列挙のみ)

- **懸念A(失敗モード#1直結)**: 全画面 quantile は「かしこいポスタライズ」に堕ちやすい。
  切り口ハイライト+落ち影が「層の重なり」として読めるかは、量子化場の平滑度
  (=境界が大きな曲線であること)と relief の画素基準のオフセットに依存する。
  前身では「量子化場を強い等方ぼかしにした低周波場にする」ことで解決済み — これを踏襲。
- **懸念B**: 全画面共通しきい値だと、動く人物が明るい窓の前を横切る等でヒストグラムが
  動き、静止背景の境界まで動く(不変量5違反)。hysteresis 不感帯(0.006)+calm の
  時定数で吸収するが、目視で prewarm 3/8/15 比較の確認が要る。
- **懸念C**: 暗部保護を全画面に広げると、髪や影など大きな暗部まで「インク紙」化して
  第2の量子化層と競合する。→ 暗部フロアは低い分位(2〜6%)に置き「最暗の一枚」として
  読ませる。目・眉はこの層として生き残る。
- **懸念D**: 局所細分(不変量6)は細かい場を量子化するため、鋸歯(不変量2違反)や
  ゴミ紙片を作りやすい。→ 細分は中間平滑場(band より軽いぼかし)に対して行い、
  振幅を弱く・detail でゲートし、最小帯幅フロアを同様に適用する。
- **懸念E**: 「暗=手前」(夜プリセット)の反転で、rim の付く側・影の向き・ランプの
  前後をひとつでも反転し忘れると不変量3が壊れる。→ 量子化場自体を F = 1-L に
  反転して機構を共有する(rim/影のコードは F 空間で不変)。
- **懸念F**: swiftshader 検証環境では実時間 warm 不可。prewarm をチャンク分割+
  glSync(1×1 readPixels)で決定的に回す(CRAFT §C4、前身の実装を踏襲)。

## Phase 2 — 設計

### 候補アーキテクチャ比較

- **A案(採用): 発注書のパス構成(前身エンジンの全画面化)**
  kuwahara+時間ema → 強等方ぼかしの量子化場 → CPU quantile(~200ms readback)→
  comp で擬似 sdf 帯(rim/落ち影)。
  根拠: 前身 kirie-portrait で紙の質感が実証済み(ref_4)。MediaPipe・部位クラス・
  台紙・etf/LIC を捨てるだけで、残る機構がそのまま本作の核になる。
- **B案(却下): GPU ヒストグラム+GPU しきい値**
  却下理由: WebGL2 に atomic がなく、リダクションパスの追加(≥4パス)に見合う利得が
  ない。CPU readback は §8-13 で低頻度(~200ms)なら許可されており前身で実証済み。
  しきい値の hysteresis/ema は CPU の方が書きやすく検査もしやすい。
- **C案(却下): 層ごとに実バッファを持つマルチレイヤー合成**
  レイヤーマスクを 4〜8 枚の RT に展開し、各層をぼかして本物の落ち影を合成する案。
  却下理由: フィルレートが層数倍(+層ごとのぼかし)になりモバイル 30fps 制約に触れる。
  擬似 sdf 帯で同等の見た目が得られることは前身で実証済み。
- **D案(却下): jump flooding による正確な SDF**
  却下理由: JFA で +8 パス。切り口と影は境界近傍の細い帯にしか要らないため、
  (L - T)/fwidth(L) の擬似距離で十分(前身で実証)。

### パス構成図

```
入力: カメラ映像 or ?fakesource=1(GLSL 合成: 窓のある室内+動く人物+振り子ランプ+雲)
[P0 scene ] cover-fit + mirror / fakeScene            sceneT  RGBA8   長辺≤1024   毎フレーム
[P1 struct] kuwahara(sceneT)+細平滑輝度 → 時間ema     structA/B RGBA16F(*fallback RGBA8)
            (rgb=平坦色, a=fine輝度)                              長辺≤768 ping-pong 毎フレーム
[P1b band ] struct の分離ガウス 2段:
            σ_med → bandM(局所細分の場)               bandM   同fmt  長辺≤384    毎フレーム
            さらに σ_rest → bandT(量子化場)           bandT   同fmt  長辺≤384    毎フレーム
[P2 stats ] R=量子化場輝度 G=fine輝度                  statsT  RGBA8  128×128     毎フレーム描画
            → CPU readback ~200ms 毎 → 加重ヒストグラム(64bin, プリセットの向き F で)
            → quantile → hysteresis(不感帯0.006)+ema(τ=0.5+2.0*calm) → MIN_GAP
            → uniform uTh[7] / uN / uDark
[P3 comp  ] F=uInvert?1-L:L を 4〜8 層に量子化 + 擬似 sdf 帯で切り口 rim +
            単一光源(左上)オフセットの落ち影 + 暗部フロア(fine 場) +
            局所細分(bandM 場, detail ゲート) + oklab 紙パレットスナップ +
            fbm 紙グレイン(層ごとに位相) → canvas  DPR≤2                       毎フレーム
```

readPixels は stats の ~200ms 毎のみ。ping-pong は structA/B(ema)。
前身の P1 class / P2 soft / P2b shad / P4 etf / P4b flow は**全て削除**
(部位クラス・MediaPipe・台紙・髪 LIC の死んだコードを持ち込まない — §8-14)。

### 反転(明=手前/暗=手前)の一貫性(§8-16)

量子化場そのものを F = uInvert==1 ? 1-L : L とし、しきい値・rim・落ち影・レベル→
紙トーンの対応を全部 F 空間で書く。rim は「自層の下側しきい値の直上」、影は
「光源方向オフセット先が上位層(F が Tup 超)」— F 空間で不変なので、反転しても
光源方向(左上)と「手前の紙が奥の紙に影を落とす」秩序が自動的に保たれる。
CPU ヒストグラムも F で組む(プリセット切替時はしきい値を snap 再初期化)。

### フィルレート概算(1100×750・DPR1)

- P0: 0.71 MP × 1 fetch ≈ 0.7 Mfetch
- P1 kuwahara: 0.40 MP × (36+9) ≈ 18 Mfetch
- P1b blur ×2段×2方向: 0.10 MP × 17 tap × 4 ≈ 6.8 Mfetch
- P2 stats: 0.016 MP × 3 ≈ 0.05 Mfetch
- P3 comp: 0.83 MP × ~12 fetch ≈ 10 Mfetch
計 ≈ 36 Mfetch/frame。60fps で 2.2 Gfetch/s — デスクトップは余裕、
モバイル(DPR2, comp ~2MP)でも comp が ~24 Mfetch に増える程度で 30fps 圏内。
重い kuwahara は 768 上限、ぼかしは 384 上限に固定(CRAFT §C3 の解像度上限)。

### プリセット(色は uDebug=4 の標本で確認)

- 0 昼の風景箱: 明=手前。深いティール(奥)→セージ→砂→クリーム→暖白(手前)。
- 1 夜の風景箱: 暗=手前。灯りの金(奥)→琥珀→暮れの赤褐→藍→濃紺(手前)。
  切り口 rim を 1.3 倍(発注書「切り口が目立つ」)。
- 2 セピアの標本箱: 明=手前。焦茶(奥)→アンバー→タン→ラテ→生成り(手前)。

### uDebug 割当(発注書 §4 どおり)

0=最終 / 1=平滑輝度(量子化場 F のグレースケール) / 2=量子化レベルのみ(切り口・影なし) /
3=境界帯の可視化(rim=橙, 落ち影=青, 細分境界=緑, レベル=グレー) /
4=標本(3プリセットの紙トーン階段+切り口/落ち影の段階見本+グレイン見本)

### スライダー(§6 の 7 本をそのまま)

layers / relief / smooth / palette / calm / detail / grain — 単一 state、
[key,ラベル,ヒント,min,max,step] 配列から生成。プリセット select+デバッグ select。
ボタン: PNG保存 / リセット / UI非表示。readout: FPS / 解像度 / レイヤー数・更新周期。

### 検証フック

__artReady(glSync 後)/ ?freeze=1 / ?prewarm=<秒>(チャンク+glSync、決定的)/
?fakesource=1(合成シーン、カメラ・権限を触らない。動く要素=人物スウェイ+振り子
ランプ+雲 — --motion 対象)。?fakescale= は人物マスク駆動でないため該当なし(実装しない)。
fakesource 時は startCamera() を呼ばず overlay を即時隠す(headless スクショが
エラーオーバーレイで覆われないように。カメラ3経路は非 fakesource で検証可能)。

### リスク

1. ポスタライズ読み(最重要): 量子化場の低周波性+relief の画素基準幅+紙パレットで
   対処。毎変更スクショ目視(CRAFT §D1/D3)で「何に見えるか」を言語化して監視。
2. 全画面ヒストグラムの揺れ: hysteresis+calm。prewarm 3/8/15 比較でドリフト確認。
3. 局所細分のゴミ紙片: 弱く・中間平滑場・最小帯幅フロア。
4. 夜プリセットの反転バグ: uDebug=3 と標本で影方向を目視確認。
5. swiftshader: prewarm チャンク+glSync(前身の実装を踏襲)。
