## 0. ゴール定義(何を作るか)

画面全体を作品サムネイルの**規則格子(グリッド)**で埋め尽くし、ポインタ位置を中心とした**レンズ状の拡大エフェクト**(中心の数枚が大きく、外周に向かって滑らかに縮小する)を持つ、シングルページのポートフォリオサイト(本リポジトリの新トップページ `index.html`)を構築する。

参照挙動の要点(参照動画の分析結果に基づく):

1. タイルは**矩形のまま**大小が変化する。タイル自体を樽型に湾曲させる魚眼シェーダーは**実装しない**。「レンズ感」は格子座標の再マッピング(中心付近のセル間隔を広げ、周辺を圧縮する)によって表現する。外周の格子が同心円状に波打って見えるのは、矩形のまま半径方向へ押し出した結果として生じる見え方であり、これで参照と同等になる。
2. 平面は**ドラッグ(PC: マウスドラッグ / モバイル: スワイプ)でパン可能**な無限平面とする。端は存在せず、トーラス状にラップアラウンドする。
3. レンズ中心にあるタイルの作品メタデータ(タイトル・日付・タグ)を画面左上のHTMLオーバーレイに表示する。
4. タイルの**クリック(タップ)で該当作品ページを開く**。ドラッグとクリックは移動量閾値で判別する。
5. **レンズは生きて動く**: ドラッグ中はすぼまり、静止すると注視タイルの上で開き直す。レンズ移動時は遠方のセルほど遅れて追従し、波の航跡が走る(§4.5, §4.6)。

非ゴール(やらないこと):

- ページ内遷移アニメーション、詳細モーダル、ズームトランジション
- タイル個別の3D回転・湾曲・Z軸隆起、透視投影
- 音、スクロールジャック、WebGPU対応

## 2. データ契約(最重要・最初に実装)

作品データはリポジトリルートの **既存 `works.json`** から取得する。**このファイルが作品追加時の唯一の更新箇所**であり、コード変更なしで作品の増減に追従できること。スキーマは既存のものを正とする:

```jsonc
[
  {
    "slug": "fable5_mosaic",        // 一意ID(英数ハイフン・アンダースコア)
    "file": "fable5_mosaic.html",   // クリック遷移先(サイト内相対URL)
    "title": "黄金地モザイク",        // オーバーレイ表示用
    "date": "2026-07-17",           // オーバーレイ表示用(YYYY-MM-DD)
    "desc": "…",                    // 本ページでは未使用(フォールバック一覧では使用可)
    "model": "Fable 5",             // 未使用(null あり)
    "tags": ["WebGL2", "Voronoi"],  // オーバーレイのチップ表示用
    "series": "FABLE5",             // 未使用
    "thumb": "thumbs/fable5_mosaic.jpg" // 表示画像(800×500 JPEG)
  }
]
```

実装要件:

- 起動時に fetch し、手書きバリデータでスキーマ検証する(zod等の実行時依存は追加しない)。不正エントリは console.error のうえ該当項目のみスキップし、全体は起動継続する。
- `data/works.ts` に内部型 `Work {id, title, url, image, date, tags}` への**アダプタ**を置き、以降のモジュールは内部型のみに依存する(`slug→id`, `file→url`, `thumb→image`)。
- `works.length` が 1〜500 の範囲で正しく動作すること(現在33、将来増加)。
- 作品画像のアスペクト比は**統一を前提としない**。表示は §5 のUV cover切り抜きで吸収する。
- 既存 works.json のスキーマ自体は**変更しない**(他ツールが依存)。

## 3. レイアウトとグリッドモデル

### 3.1 論理グリッド

- 無限平面上の論理グリッドを定義する。セルは整数座標 `(col, row)` を持つ。
- セルの基準サイズ(変形前): 高さ `CELL_H = 画面高さの 1/18`(2026-08-07 発注者FBにより 1/14 から縮小)、幅 `CELL_W = CELL_H × 1.6`(8:5 横長。比率は `CELL_ASPECT` としてパラメータ化し、config で正方形・縦長にも切替可能)。
- **密度に関する規範**: 参照サイトより意図的に低密度とする(改訂履歴#4)。1080p で可視セルはおよそ 600〜700。`CELL_BASE` 系パラメータを GUI で調整する際も、1作品あたりの画面内反復が概ね20回を超えない範囲を推奨とする。
- 画面に描画するインスタンス数は「ビューポートを覆うのに必要なセル数 + 外周マージン4セル」を毎リサイズ時に再計算する。上限 `MAX_INSTANCES = 8000`。超える場合は `CELL_H` を自動で引き上げて上限内に収める。

### 3.2 作品割り当て(決定的・トーラス周期)

- 起動時に seed から **N×N のトーラス周期割当表**(既定 `PATTERN_SIZE = 48`)を生成し、実行時はセル座標の剰余で O(1) 参照する。`seed` はURLクエリ `?seed=` で上書き可能、未指定時は固定値 `42`。
  - 理由1: リロード・レビュー・不具合再現のため、毎回同じ配置になること。
  - 理由2: 逐次割当は評価順に依存して非決定になりがち。周期表の事前生成なら決定性・ラップ境界の整合・ユニットテストが容易。
- **近傍重複禁止**: あるセルと上下左右±1セル(計8近傍)に同一作品IDが来ないこと。**周期表の境界をまたぐ近傍(ラップ)も検査対象**。生成は seed 付き擬似乱数で候補を選び、衝突時は `works` 配列内の次候補へ線形にずらす。works数が9未満の場合はこの制約をベストエフォートに緩和する。
- 全作品が周期表に最低1回は登場すること(33作品 ⊂ 48×48=2304 スロットなので自明に可能。テストで保証)。

### 3.3 パン(平面移動)

- 状態変数 `pan: {x, y}`(ワールド座標オフセット)。ドラッグ量をそのまま加算し、指を離した後は速度ベースの**慣性**(減衰係数 `INERTIA_DAMPING = 0.94`/frame、dt正規化)で滑走して停止する。
- ラップアラウンド: セルのワールド座標は仮想周期で扱い、描画対象セル範囲を pan に応じてスライドさせる(インスタンスを動かすのではなく、可視セル窓を動かす)。
- 自動ドリフト(放置時にゆっくり流れる演出)は `AUTO_DRIFT = {x: 6, y: 2}` px/秒。ユーザー入力があれば即停止し、入力停止から3秒後に再開する。パラメータで0にできること。

## 4. レンズ変形(本実装の核心)

### 4.1 方式: 格子座標の1次元半径リマッピング(CPU計算)

タイルを曲げるのではなく、**各セルの中心座標とスケールをレンズ関数で再配置**する。計算はCPUで行い、インスタンス属性バッファ(位置・スケール等)に毎フレーム書き込んで `bufferSubData` で転送する。頂点シェーダーは属性を適用するだけで、変形ロジックを持たない。

- 理由1: 参照挙動はタイル矩形を保ったままの拡縮であり、頂点シェーダー変形は不要。
- 理由2: CPU側に真の座標があるため、ヒット判定(§7)が座標配列の直接検索で済む。
- 8000インスタンス × 属性更新は毎フレーム十分に間に合う(TypedArray を事前確保し、GCゼロで書き換える)。

### 4.2 レンズ関数

ポインタ位置 `P`(ワールド座標)、セル中心の変形前位置 `C`、距離 `d = |C - P|` として:

```
コア影響率 t = clamp(1 - d / LENS_RADIUS, 0, 1)
イージング e = smootherstep(t)            // 6t^5 - 15t^4 + 10t^3
スケール s = 1 + (MAX_SCALE - 1) * e * lensAmount   // lensAmount は §4.5
```

- 位置の再配置: レンズによりセルが重ならないよう、**半径方向の累積押し出し**を行う。`dir = normalize(C - P)` に対し `C' = P + dir * remap(d)`。`remap(d)` は「0からdまでの区間で各点のスケールを積分した距離」を近似する単調増加関数とし、閉形式近似を用いてよい:

```
remap(d) = d + (MAX_SCALE - 1) * LENS_RADIUS * K * g(d / LENS_RADIUS) * lensAmount
```

- **遠距離減衰(v1.1 追加)**: `g(x)` はコア(`x ≤ 1`)の外側で急にゼロにせず、**長い裾野**を持たせて `x ≈ TAIL_END`(既定 2.4)で滑らかに0へ漸近させる。参照動画では格子のうねりが画面全域に及んでおり、影響半径で変位を打ち切ると遠方の「布のたわみ」感が消える。裾野形状は `exp(-a·x²)` 系または有理関数系から GUI で選定し定数化する。
- `K` は隣接タイルの非重複を保証する係数。プロトタイプで GUI 調整のうえ定数化する。
- **受け入れ条件(数式より優先)**: いかなるポインタ位置・lensAmount でも、隣接タイル同士のすき間が `GAP_MIN = 2px` を下回らず、かつ重ならないこと。数式の厳密性よりこの視覚条件を満たすことを優先し、必要なら反復補正(1〜2回のリラクゼーション)を入れてよい。

### 4.3 パラメータ表(初期値。すべて lil-gui で可変にすること)

| パラメータ | 初期値 | 説明 |
|---|---|---|
| `LENS_RADIUS` | 画面短辺 × 0.30 | コア影響半径(2026-08-07 FB: 0.45→0.30。安静時を「小タイルの平面+ホバー位置の魚眼バンプ」とするため) |
| `TAIL_END` | 2.2 (× LENS_RADIUS) | 変位の裾野が消える距離 |
| `MAX_SCALE` | 3.0 | 中心セルの最大倍率(2026-08-07 FB: 5.0→3.0。参照ほど劇的にせず、丸みを帯びた隆起に留める) |
| `GAP_BASE` | セル寸法の 8% | 変形前のセル間ギャップ |
| `LERP_POINTER` | 0.12 (60fps基準) | ポインタ追従の補間係数 |
| `INERTIA_DAMPING` | 0.94 | パン慣性の減衰 |
| `AUTO_DRIFT` | (6, 2) px/s | 放置時ドリフト |
| `LENS_OPEN_LERP` | 0.10 | lensAmount の開き速度(§4.5) |
| `LENS_CLOSE_LERP` | 0.18 | lensAmount の閉じ速度(§4.5) |
| `LENS_MIN` | 0.05 | ドラッグ中のレンズ残存率(§4.5)。ほぼフラットまで閉じる |
| `WAVE_LAG` | 0.35 | セル毎時間平滑の距離勾配(§4.6) |

- **すべての時間依存処理は dt 正規化すること**。補間は `1 - pow(1 - k, dt * 60)` 形式を用い、60Hz/120Hz/144Hz環境で同一の体感速度になること。

### 4.4 ポインタとレンズ中心

- デスクトップ: レンズ中心は**マウス位置をLerp追従**。初期状態(マウス未移動)は画面中央。
- タッチデバイス: レンズ中心は**画面中央に固定**。スワイプはパンに割り当てる。タップは §7 のクリック処理。
- デバイス判別は `window.matchMedia('(pointer: fine)')` を用い、ハイブリッド機では入力イベント種別で動的に切り替える。

### 4.5 レンズの開閉状態(v1.1 追加)

参照動画で確認された挙動。レンズ強度のグローバル係数 `lensAmount ∈ [LENS_MIN, 1]` を導入し、スケールと押し出しの両方に乗算する。

- **閉じる**: ドラッグ中、またはパン速度が閾値(`CLOSE_SPEED = 600 px/s`、GUI調整)を超えている間、目標値を `LENS_MIN` とする。レンズがすぼまり、格子全体が見える。
- **開く**: 入力が止まりパン速度が閾値を下回ったら目標値を 1 とする。注視タイルの上でふわっと開き直す。
- 遷移は dt 正規化 Lerp(`LENS_CLOSE_LERP` / `LENS_OPEN_LERP`。閉じは速く、開きは柔らかく)。
- 初回ロード時は `lensAmount = 0` から 1 へ開く(§6 のフェードインと同時進行)。
- `prefers-reduced-motion: reduce` では開閉を無効化し常時 1(§7.3)。

### 4.6 波の航跡 — セル毎時間平滑(v1.1 追加)

参照動画では、レンズが速く動くと遠方のセルほど遅れて追従し、変形が波のように伝播して見える。これを**セルごとの表示位置・スケールを目標値へ dt 正規化 Lerp で追従させる**ことで再現する:

```
k_cell = LERP_CELL_BASE * (1 - WAVE_LAG * clamp(d / (LENS_RADIUS * TAIL_END), 0, 1))
display += (target - display) * (1 - pow(1 - k_cell, dt * 60))
```

- 近いセルは速く、遠いセルは遅く追従 → 追従差がそのまま「航跡」になる。追加コストは事前確保済み TypedArray の read-modify-write のみ。
- 受け入れ条件(§4.2 の非重複・GAP_MIN)は**平滑後の表示値**に対して満たすこと(リラクゼーションは表示値へ適用)。
- `prefers-reduced-motion: reduce` では `WAVE_LAG = 0`・`k_cell` を即時相当に強める。

## 5. 描画・テクスチャ設計

### 5.1 描画構成

- ジオメトリ: 単位クワッド1つを `drawArraysInstanced`(または `drawElementsInstanced`)で全セル分描画。VAO 1つ。
- インスタンス属性(`divisor=1`): 中心位置 vec2 / サイズ vec2 / UV矩形 vec4 / 演出係数(明度・彩度・ハイライト)vec2 程度に詰める。毎フレーム更新するものと静的なものでバッファを分ける。
- 射影: 頂点シェーダーの uniform で「1ワールド単位 = 1 CSSピクセル」の正射影を行う(行列は自前の4値 `scale/offset` で足りる)。リサイズ時に更新。
- `devicePixelRatio` は `min(devicePixelRatio, 2)` でキャンバス実ピクセルへ反映。
- 色: テクスチャは `RGBA8` で焼き込み、ライティング等の線形空間演算を行わないため色変換は不要(入力JPEG → Canvas → テクスチャ → そのまま出力)。**元画像とタイルの色が一致しない実装は受け入れ不可**。

### 5.2 テクスチャアトラス(必須)

- 全作品画像を**1枚(不足時は複数枚)のアトラス**に実行時パックする。33作品 × 512枠 → **4096×4096 1枚**を基本とし、`works.length ≤ 16` なら 2048×2048、64超は複数枚に分割(最大4枚)。
- 各作品はアトラス内で `ATLAS_TILE = 512×320`(8:5。セル比率変更時は追従)の枠に **cover** で切り抜いて焼き込む(Canvas 2Dで生成 → `texImage2D`)。元画像のアスペクト比差はここで吸収し、**元素材の統一書き出しは要求しない**。
- インスタンスごとのUV矩形はインスタンス属性で渡す。
- `generateMipmap` + `EXT_texture_filter_anisotropic`(取得できた最大値)を必ず有効化する。縮小時のモアレ・ちらつきが残る場合はアトラス生成時に軽いガウシアンを併用。
- アトラスが複数枚になる場合はアトラス毎にドローコールを分割(ドローコール = アトラス枚数)。

### 5.3 アセット仕様(素材準備側への要求)

- 既存の `thumbs/<slug>.jpg`(800×500 JPEG、1枚 約70KB)を**そのまま使う**。新規要求はしない。
- 将来の追加分も同形式(800×500 JPEG、300KB以下)でよい。WebP化は任意の後日最適化。

### 5.4 見た目の仕上げ(v1.1 追加 — 参照映像の印象の核)

いずれもフラグメントシェーダー+インスタンス属性で実装する。すべて GUI で調整可能にし、定数化する。

| 表現 | 実装 |
|---|---|
| **ヴィネット(必須)** | レンズ中心からの距離に応じてタイル明度を落とす。周縁はほぼ黒(既定: 中心1.0 → TAIL_END で 0.25)。CPU で per-instance 係数を計算して属性で渡す |
| **角丸(必須)** | フラグメントで矩形SDF。半径は CSS px 指定(既定 6px)をタイル表示サイズに応じて維持 |
| **周縁の彩度低下(必須)** | ヴィネットと同じ係数で灰色へ寄せる(既定: 周縁で彩度 60%) |
| **注視タイルのハイライト(任意・既定ON)** | 注視タイルのみ明度をわずかに上げ、白の細枠(角丸に沿う)を出す。切替はクロスフェード |
| 背景色 | `#0a0a0a`。タイル間ギャップは背景がそのまま見える |

## 6. ローディングと初期状態

1. 初回ペイント: 背景色 `#0a0a0a` の全面 + 中央に作品数/読込済数のミニマルなプログレス表示(HTML)。
2. `works.json` 取得 → 画像を並列ロード(同時6本まで)→ アトラス焼き込み → フェードイン(opacity 0→1, 600ms)+ レンズが開く(§4.5)ことでグリッド表示。
3. 個別画像のロード失敗はプレースホルダ(単色 + IDテキスト)で埋め、全体は起動する。
4. 目標: 33作品(画像計約2.4MB)・回線 10Mbps で **3秒以内に操作可能**。

## 7. インタラクション詳細

### 7.1 ヒット判定とメタデータ表示

- 毎フレーム、レンズ中心に最も近いセルを**CPU側の座標配列から直接検索**して「注視タイル」とする。クリック判定も同じ座標配列に対する点包含判定で行い、両者が同一結果になること。
- 注視タイルのメタデータを画面左上の固定HTMLオーバーレイに表示する。構成は上から: `title`(大)、`date`(小・年月表記)、`tags` のチップ(小)。切り替え時はテキストをクロスフェード(150ms)。
- オーバーレイのスタイル: 白文字、`font-weight: 600`、`text-shadow: 0 1px 8px rgba(0,0,0,.6)`、背景の動きに埋もれない視認性を確保。タイトルのフォントサイズは `clamp(16px, 2.2vw, 28px)`。
- レンズが閉じている間(§4.5 で lensAmount が低い間)はオーバーレイを減光(opacity 0.4 程度)し、開き切りで全表示に戻す。

### 7.2 クリック / タップ遷移

- `pointerdown` から `pointerup` までの移動量が **6px 未満** かつ経過 500ms 未満の場合のみクリックとみなす(それ以外はドラッグ=パン)。
- クリック位置のタイルを特定し、`window.open(url, '_blank', 'noopener,noreferrer')` を実行(遷移先はサイト内作品HTML。同タブへの切替を config フラグで用意する)。
- ホバー可能デバイスでは注視タイル上で `cursor: pointer`。

### 7.3 キーボード・アクセシビリティ

- Canvasとは別に、**全作品の実体リンクを `<nav>` 内の非表示リスト(sr-only、ただし `display:none` 禁止)としてDOMに出力**する。スクリーンリーダーとキーボードのTab移動でも全作品へ到達できること。
- `prefers-reduced-motion: reduce` の場合: 自動ドリフト無効、レンズ追従のLerpを強める(即時に近く)、慣性無効、レンズ開閉無効(常時開)、波の航跡無効(§4.6)。

## 9. フォールバック

- WebGL2コンテキスト取得失敗、または `works.json` 取得失敗時: **CSSグリッドの静的一覧**(レスポンシブ、各タイルが通常の `<a>` リンク)へ自動フォールバックする。エフェクトなしでも全作品の閲覧・遷移が成立すること。デザインは現行「黒の展示室」の簡約版とし、§7.3 の実体リンクリストと実装を共有してよい。
- `webglcontextlost` を捕捉し、`webglcontextrestored` で復帰。復帰失敗時は上記フォールバックへ。

## 11. コード構成・品質

ソースは `site/` に置き、`npm run build` が**リポジトリルート**へ `index.html` と `assets/top/*.js` を出力する。成果物はコミットする(GitHub Pages ルート直接配信・CIなしの既存運用を維持するため)。

```
site/
  src/
    main.ts              // 起動シーケンス
    config.ts            // §4.3 §5.4 の全パラメータを一元管理
    data/works.ts        // fetch + バリデーション + 既存スキーマ→内部型アダプタ
    gfx/atlas.ts         // アトラス生成(Canvas 2D、チャンク分割)
    gfx/grid.ts          // セル管理・可視窓・トーラス周期割当表(決定的)
    gfx/lens.ts          // レンズ関数・開閉状態・セル毎平滑・属性バッファ更新
    gfx/renderer.ts      // WebGL2セットアップ・VAO/シェーダー・リサイズ・context lost
    gfx/shaders/tile.vert.glsl / tile.frag.glsl
    input/pointer.ts     // マウス/タッチ統合、ドラッグ/クリック判別、慣性
    ui/overlay.ts        // タイトル表示・プログレス
    fallback/staticGrid.ts
  test/                  // Vitest
index.html               // ビルド成果物(コミット対象)
assets/top/              // ビルド成果物(コミット対象)
works.json               // 既存のまま(単一情報源)
thumbs/*.jpg             // 既存のまま(アトラス原料)
```

- ESLint + Prettier。`any` 禁止。マジックナンバーはすべて `config.ts` へ。
- **ユニットテスト**(Vitest)必須対象: レンズ関数(単調性・GAP_MIN)、トーラス周期割当表(決定性・8近傍・全作品出現・ラップ境界)、クリック判別、dt正規化Lerp。
- README に「作品の追加手順(works.jsonへの追記とサムネ生成のみ)」と `site/` のビルド手順を明記する。

## 13. 実装手順(この順で進めること)
