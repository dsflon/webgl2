## 0. ゴール定義（何を作るか）

画面全体を作品サムネイルの**規則格子（グリッド）**で埋め尽くし、ポインタ位置を中心とした**レンズ状の拡大エフェクト**（中心の数枚が大きく、外周に向かって滑らかに縮小する）を持つ、シングルページのポートフォリオサイトを構築する。

参照挙動の要点（参照動画の分析結果に基づく）:

1. タイルは**矩形のまま**大小が変化する。タイル自体を樽型に湾曲させる魚眼シェーダーは**実装しない**。「レンズ感」は格子座標の再マッピング（中心付近のセル間隔を広げ、周辺を圧縮する）によって表現する。
2. 平面は**ドラッグ（PC: マウスドラッグ / モバイル: スワイプ）でパン可能**な無限平面とする。端は存在せず、トーラス状にラップアラウンドする。
3. レンズ中心にあるタイルの作品タイトル等のメタデータを画面左上のHTMLオーバーレイに表示する。
4. タイルの**クリック（タップ）で該当作品の詳細URLを別タブで開く**。ドラッグとクリックは移動量閾値で判別する。

非ゴール（やらないこと）:

- ページ内遷移アニメーション、詳細モーダル、ズームトランジション
- タイル個別の3D回転・湾曲・Z軸隆起
- 音、スクロールジャック、WebGPU対応

## 2. データ契約（最重要・最初に実装）

作品データは `public/works.json` から取得する。**このスキーマが作品追加時の唯一の更新箇所**であり、コード変更なしで作品の増減に追従できること。

```jsonc
{
  "version": 1,
  "works": [
    {
      "id": "work-001",          // 一意。英数ハイフンのみ
      "title": "作品タイトル",     // オーバーレイ表示用
      "url": "https://example.com/works/001", // クリック遷移先
      "image": "/assets/works/work-001.webp", // 表示画像
      "tags": ["graphic", "2025"]  // 任意。現時点では表示に未使用
    }
  ]
}
```

実装要件:

- 起動時に fetch し、zodや手書きバリデータでスキーマ検証する。不正データはconsole.errorのうえ該当項目のみスキップし、全体は起動継続する。
- `works.length` が 1〜500 の範囲で正しく動作すること（現在約30、将来増加）。
- 作品画像のアスペクト比は**統一を前提としない**。表示は §5 のUV cover切り抜きで吸収する。

## 3. レイアウトとグリッドモデル

### 3.1 論理グリッド

- 無限平面上の論理グリッドを定義する。セルは整数座標 `(col, row)` を持つ。
- セルの基準サイズ（変形前）: `CELL_BASE = 画面高さの 1/14`（正方形セル。パラメータ化すること）。
- 画面に描画するインスタンス数は「ビューポートを覆うのに必要なセル数 + 外周マージン4セル」を毎リサイズ時に再計算する。上限 `MAX_INSTANCES = 8000`。超える場合は `CELL_BASE` を自動で引き上げて上限内に収める。

### 3.2 作品割り当て（決定的ランダム）

- 各セルへの作品割り当ては `hash(col, row, seed)` による**決定的な擬似乱数**で行う。`seed` はURLクエリ `?seed=` で上書き可能、未指定時は固定値 `42`。
  - 理由: リロード・レビュー・不具合再現のため、毎回同じ配置になること。
- **近傍重複禁止**: あるセルと上下左右±1セル（計8近傍）に同一作品IDが来ないこと。ハッシュ結果が衝突する場合は `works` 配列内の次候補へ線形にずらす。works数が9未満の場合はこの制約をベストエフォートに緩和する。

### 3.3 パン（平面移動）

- 状態変数 `pan: {x, y}`（ワールド座標オフセット）。ドラッグ量をそのまま加算し、指を離した後は速度ベースの**慣性**（減衰係数 `INERTIA_DAMPING = 0.94`/frame、dt正規化）で滑走して停止する。
- ラップアラウンド: セルのワールド座標は `((col * CELL_BASE) - pan.x)` を仮想周期で扱い、描画対象セル範囲を pan に応じてスライドさせる方式とする（インスタンスを動かすのではなく、可視セル窓を動かす）。
- 自動ドリフト（放置時にゆっくり流れる演出）は `AUTO_DRIFT = {x: 6, y: 2}` px/秒。ユーザー入力があれば即停止し、入力停止から3秒後に再開する。パラメータで0にできること。

## 4. レンズ変形（本実装の核心）

### 4.1 方式: 格子座標の1次元半径リマッピング（CPU計算）

タイルを曲げるのではなく、**各セルの中心座標とスケールをレンズ関数で再配置**する。計算はCPUで行い、`InstancedMesh.instanceMatrix` に毎フレーム書き込む。カスタムVertex Shaderによる変形は行わない。

- 理由1: 参照挙動はタイル矩形を保ったままの拡縮であり、頂点シェーダー変形は不要。
- 理由2: CPU側に真の座標があるため、Three.js標準のRaycasterがそのまま使え、GPUピッキングの追加実装が不要。
- 8000インスタンス × 行列更新は毎フレーム十分に間に合う（行列合成は自前の軽量計算で行い、`Object3D.updateMatrix()` の汎用パスは使わない）。

### 4.2 レンズ関数

ポインタ位置 `P`（ワールド座標）、セル中心の変形前位置 `C`、距離 `d = |C - P|` として:

```
影響率 t = clamp(1 - d / LENS_RADIUS, 0, 1)
イージング e = smootherstep(t)            // 6t^5 - 15t^4 + 10t^3
スケール s = 1 + (MAX_SCALE - 1) * e
```

- 位置の再配置: レンズによりセルが重ならないよう、**半径方向の累積押し出し**を行う。具体的には、P からの方向ベクトル `dir = normalize(C - P)` に対し、変形後位置 `C' = P + dir * remap(d)` とする。`remap(d)` は「0からdまでの区間で各点のスケールを積分した距離」を近似する単調増加関数とし、実装は以下の閉形式近似を用いてよい:

```
remap(d) = d + (MAX_SCALE - 1) * LENS_RADIUS * K * g(d / LENS_RADIUS)
// g は g(0)=一定の押し出し、g(1)以降=0 に漸近する滑らかな減衰関数
// K は隣接タイルの非重複を保証する係数。プロトタイプでGUI調整のうえ定数化する
```

- **受け入れ条件（数式より優先）**: いかなるポインタ位置でも、隣接タイム同士のすき間が `GAP_MIN = 2px` を下回らず、かつ重ならないこと。数式の厳密性よりこの視覚条件を満たすことを優先し、必要なら反復補正（1〜2回のリラクゼーション）を入れてよい。

### 4.3 パラメータ表（初期値。すべて lil-gui で可変にすること）

| パラメータ | 初期値 | 説明 |
|---|---|---|
| `LENS_RADIUS` | 画面短辺 × 0.45 | 影響半径 |
| `MAX_SCALE` | 5.0 | 中心セルの最大倍率 |
| `GAP_BASE` | セル寸法の 8% | 変形前のセル間ギャップ |
| `LERP_POINTER` | 0.12 (60fps基準) | ポインタ追従の補間係数 |
| `INERTIA_DAMPING` | 0.94 | パン慣性の減衰 |
| `AUTO_DRIFT` | (6, 2) px/s | 放置時ドリフト |

- **すべての時間依存処理は dt 正規化すること**。補間は `1 - pow(1 - k, dt * 60)` 形式を用い、60Hz/120Hz/144Hz環境で同一の体感速度になること。

### 4.4 ポインタとレンズ中心

- デスクトップ: レンズ中心は**マウス位置をLerp追従**。初期状態（マウス未移動）は画面中央。
- タッチデバイス: レンズ中心は**画面中央に固定**。スワイプはパンに割り当てる。タップは §7 のクリック処理。
- デバイス判別は `window.matchMedia('(pointer: fine)')` を用い、ハイブリッド機では入力イベント種別で動的に切り替える。

## 5. 描画・テクスチャ設計

### 5.1 描画構成

- ジオメトリ: `PlaneGeometry(1,1)` を1つ、`THREE.InstancedMesh` で全セルを1ドローコール描画。
- カメラ: `OrthographicCamera`。1ワールド単位 = 1 CSSピクセルに一致させ、リサイズ時に更新。
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`。
- 色空間: `renderer.outputColorSpace = SRGBColorSpace`、全テクスチャに `texture.colorSpace = SRGBColorSpace` を設定。**この設定漏れによる色転びは受け入れ不可**。

### 5.2 テクスチャアトラス（必須）

- 全作品画像を**1枚（不足時は複数枚）のアトラス**に実行時パックする(2048×2048を基本、works数に応じて4096まで拡張)。
- 各作品はアトラス内で `ATLAS_TILE = 512×512` の枠に **cover** で切り抜いて焼き込む（Canvas 2Dで生成 → `CanvasTexture`）。元画像のアスペクト比差はここで吸収し、**元素材の統一書き出しは要求しない**。
- インスタンスごとのUVオフセット/スケールは `InstancedBufferAttribute` で渡し、`onBeforeCompile` で標準マテリアルのUV計算に差し込む（フルカスタムシェーダーは書かない）。
- ミップマップ生成 + `anisotropy = renderer.capabilities.getMaxAnisotropy()` を必ず有効化する。縮小時のモアレ・ちらつきが残る場合はアトラス生成時に軽いガウシアンを併用。
- アトラスが複数枚になる場合はアトラス毎に InstancedMesh を分割（ドローコール = アトラス枚数）。

### 5.3 アセット仕様（素材準備側への要求）

- 入稿形式: WebP、長辺 1024px 以上、1枚あたり 300KB 以下を目安。
- 実行時に 512px 枠へ縮小されるため、それ以上の高解像度は不要。

## 6. ローディングと初期状態

1. 初回ペイント: 背景色 `#0a0a0a` の全面 + 中央に作品数/読込済数のミニマルなプログレス表示（HTML）。
2. `works.json` 取得 → 画像を並列ロード（同時6本まで）→ アトラス焼き込み → フェードイン（opacity 0→1, 600ms）でグリッド表示。
3. 個別画像のロード失敗はプレースホルダ（単色 + IDテキスト）で埋め、全体は起動する。
4. 目標: 30作品・回線 10Mbps で **3秒以内に操作可能**。

## 7. インタラクション詳細

### 7.1 ヒット判定とメタデータ表示

- 毎フレーム、レンズ中心に最も近いセルを**CPU側の座標配列から直接検索**して「注視タイル」とする（Raycaster不要な設計だが、クリック判定にはRaycasterを使ってもよい。どちらも同一結果になること)。
- 注視タイルの `title` を画面左上の固定HTMLオーバーレイに表示。切り替え時はテキストをクロスフェード（150ms）。
- オーバーレイのスタイル: 白文字、`font-weight: 600`、`text-shadow: 0 1px 8px rgba(0,0,0,.6)`、背景の動きに埋もれない視認性を確保。フォントサイズは `clamp(16px, 2.2vw, 28px)`。

### 7.2 クリック / タップ遷移

- `pointerdown` から `pointerup` までの移動量が **6px 未満** かつ経過 500ms 未満の場合のみクリックとみなす（それ以外はドラッグ＝パン）。
- クリック位置のタイルを特定し、`window.open(url, '_blank', 'noopener,noreferrer')` を実行。
- ホバー可能デバイスでは注視タイル上で `cursor: pointer`。

### 7.3 キーボード・アクセシビリティ

- Canvasとは別に、**全作品の実体リンクを `<nav>` 内の非表示リスト（sr-only、ただし `display:none` 禁止）としてDOMに出力**する。スクリーンリーダーとキーボードのTab移動でも全作品へ到達できること。
- `prefers-reduced-motion: reduce` の場合: 自動ドリフト無効、レンズ追従のLerpを強める（即時に近く）、慣性無効。

## 9. フォールバック

- WebGLコンテキスト取得失敗、または `works.json` 取得失敗時: **CSSグリッドの静的一覧**（レスポンシブ、各タイルが通常の `<a>` リンク）へ自動フォールバックする。エフェクトなしでも全作品の閲覧・遷移が成立すること。
- `webglcontextlost` を捕捉し、`webglcontextrestored` で復帰。復帰失敗時は上記フォールバックへ。

- レンズ関数・決定的ハッシュ・近傍重複回避・クリック判別には**ユニットテスト**（Vitest）を書くこと。
- README に「作品の追加手順（works.jsonへの追記と画像配置のみ）」を明記する。

## 13. 実装手順（この順で進めること）

1. **M1**: データ契約 + 静的CSSグリッドのフォールバック版（この時点で「動くサイト」が存在する状態にする）
